# M7.6 small-object and depth-content safeguards — 2026-09-11

## Result

Two additional frozen manifests now cover the remaining object-scale and explicit
depth-owner changes in the experimental fused Hi-Z route.

`m7_occlusion_subpixel_object_v1` scales the reference asset to 0.001 on every
axis. At 1280x720 all 101 opaque primitive bounds are below the conservative
one-pixel footprint threshold. On every eligible frame the device reports exactly
101 `SmallBounds` fail-visible results, performs zero depth tests, applies zero
rejections, and retains all 101 commands. Device and oracle command counts are
identical; all other fail-visible reasons, invalid results, unsafe mismatches, bin
mismatches, indirect overflow, and profiler drops are zero.

The GPU-scene qualification stream now publishes bounded per-reason fail-visible
counters for invalid extent, invalid bounds, invalid projection, invalid settings,
clip-plane intersection, outside-view, and small bounds. The feature-heavy frame
uses 263 counters. The profiler's fixed ceiling is now 272 so combined resize
qualification also retains bounded headroom without steady-frame allocation.

`m7_occluder_visibility_step_v1` disables the nearest instance in a four-object
depth stack at benchmark-state frame 12. Stable pre-change frames emit 331 of 404
commands after 73 rejections. The transition reduces the active set to 303,
rejects prior history as `DepthContentChanged`, applies no occlusion rejection, and
emits all 303 remaining commands. The next frame recovers history and emits exactly
251 commands after 52 rejections. Every eligible frame has exact device/oracle
parity and zero invalid, unsafe, bin, overflow, or telemetry-drop counts.

Query-only and fused-rejection final-SDR captures at the visibility transition and
first recovered frame are byte-identical, all with SHA-256
`4462861f9c52da6e421928190832d937cdb3721a50749d6e04577e3209096b26`.

## Decision and remaining work

The small-object and explicit depth-content invalidation correctness gaps are
closed for the experimental route. This does not admit production command
rejection. Scene-target resize evidence is now also complete; see
`docs/performance/M7.6-resize-recovery-2026-09-11.md`. Duplicate-history removal
is subsequently complete in `docs/performance/M7.6-in-place-view-history-2026-09-11.md`;
the controlled large-occluded-workload performance gate remains. Production
depth-pyramid allocation and rejection remain off by default.

No accepted ADR changed, and M7.6 remains active.
