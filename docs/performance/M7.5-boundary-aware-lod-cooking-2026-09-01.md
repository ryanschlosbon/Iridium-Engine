# M7.5 Boundary-Aware LOD Cooking — 2026-09-01

## Outcome

M7.5 now has an explicitly opt-in boundary-edge collapse mode for deterministic
generated LODs. It doubles the representative Alfa Romeo asset's generated-chain
count from 5 to 10 and improves native-4K main-view triangle reduction at the
existing 2/4/8-pixel error ceilings. Canonical LOD0, RT geometry, default importer
settings, legacy importer behavior, and historical CookKeys remain unchanged.

The gain is useful but not sufficient for production admission. Only 18,491 of
201,612 canonical triangles per car (9.17%) participate in generated chains, and
the lit fixture removes at most 2.45% of main-view triangles at 8 pixels. The mode
therefore remains experimental and disabled by default. M7.5 stays active; the next
cooker step must address primitive/material fragmentation or use a stronger
topology-aware simplifier without relaxing the runtime error ceiling.

## Contract and implementation

Importer version 8 accepts the optional setting:

```json
{
  "generate_lods": true,
  "lod_allow_boundary_collapse": true
}
```

The key is intentionally absent from default normalized settings. Omitting it
therefore preserves the version-1 locked-boundary bytes and existing CookKeys.
Specifying it produces distinct canonical settings bytes, a distinct settings hash,
and a distinct CookKey. Importer version 7 rejects the key, and the current importer
rejects it unless `generate_lods` is also true.

The generator ABI advances to 2. The opt-in algorithm may merge two source-boundary
groups only across an actual source-boundary edge. Boundary/interior merges remain
forbidden, and each boundary group may participate in at most one boundary collapse
per generated level. This deliberately conservative limit prevents a boundary chain
from being folded repeatedly in one pass.

All existing guards remain mandatory: deterministic length/index ordering, exact
source-attribute representatives, normal/UV/color compatibility, object-space
displacement budget, triangle-orientation checks, source-to-reduced correspondence,
retained disconnected islands, and equal component/topology signatures. The default
path still retains every source boundary vertex.

No ADR is superseded. The change is an additive asset-cooking policy within the
accepted M7 parent-contained LOD architecture. Experimental device LOD and boundary
collapse remain disabled by default; physical missing-fine residency stays M7.9,
and independent shadow/probe LOD stays M7.7.

## Follow-up

The historical measurements above remain valid for the boundary-only artifact. A
later same-day opt-in boundary-fan repair plus transactional merge policy increases
the representative artifact to 57 chains and improves native-4K main-view triangle
reduction to 6.9988/13.4023/20.1350% at 2/4/8 pixels. See
`docs/performance/M7.5-transactional-lod-cooking-2026-09-01.md`. The stronger result
supersedes this report's next-step diagnosis, but it does not change the boundary-only
CookKey, artifact, or measurements.
