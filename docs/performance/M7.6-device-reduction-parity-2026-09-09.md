# M7.6 device depth reduction parity — 2026-09-09

## Scope and result

The new `assets/shaders/depth_pyramid.comp` executes the reference farthest-device-
depth reduction on Vulkan. This is not the transparency pyramid: forward depth
uses maximum, reverse depth uses minimum, and invalid samples become far depth.
Integer proportional intervals preserve every odd-edge sample at every mip.
Each dispatch uses one sampled source-mip view and one R32 storage output-mip view;
equal extents initialize mip zero from D32 or R32 source depth. Workgroups are 8x8,
with an extent guard; the only push value is a 32-bit reverse-depth flag.

The standalone `VulkanDepthPyramidTests` hardware executable builds real Vulkan
images, per-mip views/descriptors, transfer uploads, compute dispatches, barriers,
and host readback. It compares every output texel of every mip with the independent
`DepthPyramidReference`. It uses its own headless test device and is intentionally
not part of the portable CTest suite. No window or scene asset is needed.

## Evidence

- Reference hardware: NVIDIA GeForce RTX 4090.
- Debug and Release full builds pass.
- Both hardware configurations pass 28 cases: seven extents times two depth
  conventions times D32/R32 source formats. Extents are 1x1, 15x1, 15x3, 7x5,
  1x15, 127x73 and 3840x2160. Every mip value matches exactly, including all twelve
  levels at 4K.
- D32 cases contain finite device depth; R32 cases also inject NaN, infinity,
  negative and greater-than-one samples. The 15x1 finite case carries the original
  far-depth hole at x=4. Cases sequentially release/recreate resources.
- Khronos validation and synchronization validation are explicitly enabled;
  final runs report zero errors, including resource destruction.
- The first run produced exact values but failed the error gate due to broken
  installed Overwolf/ReShade implicit-layer loading. Final runs set process-local
  `VK_LOADER_LAYERS_DISABLE=~implicit~`; the explicit validation layer remains active.
  No installed layer or user configuration was modified.
- Full portable Release suite remains 77/77 passing.

Reproduce after building with the Vulkan SDK and validation layer installed:

```powershell
$env:VK_LOADER_LAYERS_DISABLE = '~implicit~'
& out/build/x64-release/bin/VulkanDepthPyramidTests.exe
```

## Integration contract and remaining work

This adds a shader and hardware qualification target in CMake, not a production
render-graph pass. The headless harness deliberately waits for completion before
readback/destruction; those waits are not an engine scheduling design. Production
must bind nonoverlapping one-mip views, use nearest unfiltered depth fetches,
synchronize depth writes to sampling and each reduction write to the next read,
and enforce supported image dimensions (integer products assume <=65535 per axis).

Next: persistent per-view history resources, fence-safe resize/retirement, explicit
view/scene/revision ownership, and GPU query/compaction integration with parity and
fail-visible counters. D32 was uploaded here, not sampled from a live scene depth
attachment; graph ordering and temporal disocclusion are not qualified by this test.

No screenshot, complete-frame timing, or production VRAM delta is claimed: runtime
rendering is unchanged and does not allocate these images. No ADR or milestone
acceptance status changes; M7.6 remains active and production occlusion stays off.
