# M7.8 camera-driven directional clip construction

Date: 2026-09-30
Status: qualified projection prerequisite; live frame publication remains next

## Contract and implementation

`DirectionalVirtualShadowClipConfig` and `buildDirectionalVirtualShadowClips`
now construct directional clip levels from stable light identity, projection and
caster revisions, camera/focus position, light direction and explicit projection
policy. The fixed-capacity result holds up to 16 clips plus per-level world units
per texel/page, without heap allocations. The default four 16,384-texel levels
with 128-texel pages consume exactly the existing 65,536-cell accumulation bound.
The finest XY world span doubles at each successive level, providing increasing
detail near the focus without coupling the projection to camera FOV or far plane.
These defaults are qualification policy, not a new production or editor setting.

Construction uses a normalized deterministic light basis and double-precision
intermediate math, then emits the existing float matrix/ABI-v2 clip record.
Camera focus projects onto the light's XY plane. Window origins are floored to
whole world pages (including negative coordinates), and the window covers an even
page axis centered about that snapped location. Local page coordinates plus the
signed window origin recover the same world-page identity after scrolling.
Sub-page focus movement leaves a level's matrix and origin unchanged.

Depth is a fixed light-space zero-to-one interval, not a camera-following fit.
Movement along the light direction therefore does not silently change cached page
depth. The caller must change `projectionRevision` when light direction/basis,
world span, resolution/page policy or depth bounds change. That revision is explicit
input; this pure builder does not infer scene revisions or publish cache state.
Receivers outside the interval/clip stack are unmapped and require the existing
fail-visible/conventional-fallback policy. Future live publication must derive
conservative depth bounds from scene/light policy and never clip relevant casters
without invalidation and fallback. The basis's near-vertical up-hint switch also
counts as a projection change.

Validation rejects invalid identity/revision, nonfinite focus/direction/policy,
zero direction, invalid depth span, unsupported level count, fractional/odd page
axes, signed GPU coordinate overflow and unrepresentable GPU projection rows.
Large-world float cancellation near extreme signed page origins is not qualified
as precise shadow rasterization; rebasing/precision policy remains an integration
concern, not a fidelity guarantee from int32 bounds alone.

## Verification

RTX 4090 / i9-14900K, Debug and Release:

- The CPU suite passes 16/16 cases. New cases cover page/texel density doubling,
  default four-level workspace fit, sub-page matrix stability, positive and
  negative page scroll, overlapping receiver identity, stable depth under axial
  focus movement, caster revision propagation, vertical light direction and invalid
  policy/representation rejection.
- Vulkan raw marking exactly matches the CPU receiver oracle with generated clips
  across focus X = 0, 0.001, 0.02 and -0.02 world units, including fine-to-coarse
  guard fallback and out-of-stack receivers. The odd 67x65 full-depth fixture now
  uses generated two-level clips rather than hand-built identity projections;
  request/overflow parity remains exact through forward/reverse, invalid depth,
  perspective and singular reconstruction. Synchronization validation is clean.
- The existing native-4K single-grid full-depth fixture still passes, measuring
  0.569792 ms Debug / 0.574112 ms Release over five warm samples. It has not
  changed projection distribution; this is continuity evidence, not a speedup.
- Five runs of 100,000 changing-focus four-level constructions measure median
  1.46701 us/plan Debug / 0.186163 us/plan Release. A consumed page-origin checksum
  prevents dead-code removal. This is standalone host construction, not integrated
  CPU frame timing or proof of zero allocations elsewhere in the frame path.
- Full Debug and Release builds succeed; all 78 repository tests pass in each
  configuration, including the updated current-contract hash gate. The separate
  Vulkan hardware executable passes in both configurations with zero validation
  errors. No new engine GUI launch was needed for this pure projection prerequisite;
  it does not change the runtime frame path.

No new GPU resources, shader ABI changes or lighting samples are introduced.
Tracked experimental storage remains 88.753 MiB. Normal scene output and
conventional shadows are unchanged; no visual improvement is claimed.

## Next integration gate

Publish the generated clips from actual scene/light/camera state with explicit
projection revision ownership, conservative caster depth bounds and per-slot packed
uploads. Schedule full-view page accumulation and compaction in the render graph,
then qualify moving cameras/lights, resize and overlapping frame slots with native
4K whole-frame evidence. Page residency, raster and virtual lighting sampling remain
later M7.8 work; forward/transparency coverage still needs its own producer or
conventional fallback. M7.8 remains active and no accepted ADR is superseded.
