# M7.6 odd-extent query correction — 2026-09-04

Source review found a false-occlusion defect in the initial CPU oracle before its
integration into the renderer. Reduction partitions were rounded at every mip, but
queries used a direct normalized base-to-mip ratio. Those boundaries do not compose.

A 15x1 forward-depth image with depth 0.2 everywhere except a far-plane hole at x=4
incorrectly rejected the rectangle [0,5) at depth 0.7. The 15->7->3 chain places that
hole in a different coarse texel than the original query sampled. The focused
regression and an exhaustive rectangle test both failed before the correction.

Queries now invert the reduction partition at each successive mip. Source pixel p
belongs to `ceil((p+1)*outputExtent/sourceExtent)-1`. Inclusive endpoints propagate
through the chain until the rectangle spans at most 2x2 texels. The reduction data
and four-sample bound are preserved. Vulkan must implement this same mapping.

Additional hardening maps nonfinite and out-of-range depth samples to the far plane
instead of clamping invalid negative forward depth into an occluder. Mip extent
queries stop at 1x1, including UINT32_MAX requests.

Verification: Debug and Release engine targets build successfully. DepthPyramidTests
passes in both configurations. For each depth convention, the coverage test places
a hole at every pixel of 15x3, 7x5, and 1x15 images and checks every nonempty rectangle:
queries containing the hole never reject and queries touch at most four samples.
Tests also cover invalid depth and an oversized mip request.

Affected interfaces: DepthPyramidReference::test/build and depthPyramidMipExtent;
no signature or ABI change. There is no runtime visual, GPU-time, or VRAM comparison
because the oracle is not yet consumed by the renderer. No Vulkan resources or
runtime culling were changed. M7.6 remains active; device reduction/readback parity,
history ownership, temporal safety, and compaction integration remain outstanding.
No ADR is changed. This record corrects the initial oracle acceptance claim in the
2026-09-02 contract report.
