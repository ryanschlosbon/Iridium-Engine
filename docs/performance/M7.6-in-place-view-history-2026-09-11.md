# M7.6 in-place per-view Hi-Z history — 2026-09-11

## Result

The experimental Hi-Z route no longer builds a frame-local R32 pyramid and then
copies every mip into a second persistent image. Each retained render view now
owns one persistent full-mip image which is both the current build destination
and the next eligible submission's history. The ordered graphics queue samples
the preceding contents during fused opaque compaction, then transitions and
overwrites that same view image after opaque and depth-writing forward work.

Scene and asset-preview histories remain independent. Publication metadata is
still tracked per view and frame fence, resize/rebuild still changes the image
generation and invalidates all history, and an older completion still cannot
replace a newer queued publication. The implementation keeps the persistent
images behind the Vulkan depth-pyramid object rather than pretending that the
render graph's per-frame physical slots provide stable per-view ownership.

The production graph no longer allocates `depth.occlusion-pyramid` once per frame
context and no longer contains separate ready/publish passes. It retains an
ordered build pass and the optional validation-readback hook. The direct image
barriers cover compute history reads, storage writes, inter-mip dependencies,
transfer readback, and the following submission's compute sampling. The shared
`ShaderResource` Vulkan state now correctly includes compute consumers.

## Memory and timing evidence

At 1280x720, the otherwise matching pre-change temporal run reports 162,056,480
render-graph requested bytes, 23 passes, 27 logical resources, and 20 physical
slots. The in-place run reports 152,226,376 bytes, 21 passes, 26 logical resources,
and 19 physical slots. The exact 9,830,104-byte (9.374718 MiB) reduction is the two
removed per-frame full-mip R32 chains. Their committed allocation delta is
10,711,040 bytes (10.214844 MiB) at this extent.

At native 3840x2160, the same two removed logical chains contain 88,472,440 bytes
(84.373894 MiB) of requested texels. The earlier allocation evidence measured
87.3515625 MiB committed for this duplicate half of the topology; that overhead
is now absent. The two required per-view histories remain.

The focused `gpu.depth.occlusion-pyramid` median falls from 0.054272 ms in the
previous 32-frame synchronization-validation temporal run to 0.032768 ms in the
new equivalent run. This is supporting evidence that the full-chain copy is gone,
not the separate large-occluded-workload admission gate.

- Live D32 capture validation checks 921,600 source texels and 1,228,763 direct
  history texels across 11 mips with zero invalid values, zero mismatches, and
  zero maximum error.
- The 32-frame temporal rejection run preserves exact device/oracle command
  counts. Stable pre-cut frames emit 331/404 commands after 73 safe rejections;
  the cut frame retains all 404; stable post-cut frames emit 362/404 after 42.
  All frames have zero bin mismatch, overflow, invalid result, unsafe mismatch,
  and profiler drop counts.
- Query-only and rejection scene captures at measured frame 10 are byte-identical
  with SHA-256
  `c1e1f44a83071f6e8a613a453c013c3309535c5de3a81cbb5320283645fba54f`.
- The three-step 960x540, 1600x900, and restored 1280x720 validation still reports

  stable frame recovers the previously accepted 340, 346, and 331 exact command
  counts.
- Debug and Release builds succeed. Focused depth-pyramid, resource-state, and
  production-graph tests pass. Full portable suites are run as the final slice
  gate.

## Decision and remaining work

The duplicate-storage and full-mip-copy pre-admission item is closed. The feature
remains default-off: M7.6 still needs a controlled large, genuinely occluded
workload showing an end-to-end scalable win before production rejection can be
admitted. No accepted ADR changed.
