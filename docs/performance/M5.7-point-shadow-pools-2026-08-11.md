# M5.7 Tiered Point-Shadow Pools Checkpoint — 2026-08-11

Status: point-shadow GPU vertical slice implemented and validated. Final M5.7
acceptance still requires the dedicated complex-forward visual comparison and a
matched multi-process timing baseline.

## Behavior and architecture

- Backend-neutral point packets carry one light owner, six frozen face transforms,
  stable tier/cube allocation, and all-or-nothing cache state. The application owns
  allocation and scheduling; the Vulkan backend owns D32 images, views, pipelines,
  frame buffers, and commands.
- Three persistent cube arrays provide 256, 512, and 1024 tiers. Default capacities
  are 32, 16, and 8 cubes: 56 stable slots and exactly 336 MiB requested/committed.
  Together with the default 4096 spot atlas, `image.shadow.local` is exactly 400 MiB
  across four allocations.
- A point update is one atomic six-face unit. The default project budget is 12
  MiTexels/frame and the compatible-stale window is two frames; incompatible or
  incomplete history is never sampled. Per-light quality selects the tier while
  project settings own capacity and scheduling policy.
- Each sampleable point light publishes a constant-time shadow-data slot into its
  packed GPU light record. Deferred and complex-forward consumers call the same
  manual depth-comparison and 5x5 tangent-space cube filter.
- Face order matches Vulkan cube-array layers (+X, -X, +Y, -Y, +Z, -Z). The cube
  projection intentionally omits the ordinary 2D Vulkan Y inversion so rendered
  coordinates match cube sampling. A small receiver normal/depth bias replaces the
  unsuitable directional-map slope bias near 90-degree face edges.
- Alpha-mask and double-sided pipeline variants reuse canonical material bindings.
  Conservative transformed-sphere tests reject only casters proven outside each
  face and expose exact tested/culled counters.

## Verification and evidence

- Debug and Release build successfully and pass all 67 tests. Focused contracts
  cover allocation capacity/omission, cache behavior, graph resources/pass order,
  shader inclusion/bindings, and both lighting consumers.
- Final Debug Vulkan-validation runs completed without messages. On a cold frame,
  two 512 cubes requested and allocated 2 owners, updated all 12 faces, rendered
  3,145,728 texels, tested 36 caster-face pairs, culled 15, and recorded 21 draws
  including 3 alpha-mask draws. `gpu.shadow.point` measured 0.031744 ms. The next
  three frames reported 2 cache hits, no updates, and no point-shadow pass.
- The deterministic final-SDR contact capture visibly shows independent orange and
  blue point-light projections and overlapping cast regions. SHA-256:
  `813d2d46fdd194915e7b7a2941dd2e9e2be02d7758e04ffecde8c6528a27c7cc`.
- A single-process 3840x2160 Release diagnostic over 64 measured static frames
  reported 2.933792 ms median / 2.941408 ms p95 GPU frame time, 0.583680 ms median /
  0.586752 ms p95 deferred lighting, and 3.140000 ms median / 3.198600 ms p95 CPU
  frame time. Every measured frame reused both cached cubes. This is an absolute
  diagnostic, not the final matched baseline.

## Remaining risk and deferred work

- Default local-shadow storage is deliberately high for the reference RTX 4090,
  but fixed startup allocation means low-capacity project presets need matched
  memory/performance evidence before M5.7 acceptance.
- The current bias values are renderer policy, not yet a named user quality preset.
  Exposing them later must extend backend-neutral project/per-light settings rather
  than editor or Vulkan state.
- The fixture proves deferred composition. A complex-forward parity capture and
  repeated matched on/off sampling are still required for final M5.7 acceptance.
