# M7.6 fused Hi-Z query and compaction — 2026-09-11

## Result

The default-off `--experimental-depth-occlusion-rejection` route now projects,
queries, records its ABI-2 qualification result, and conditionally emits the opaque
indirect command in one compute invocation. The previous rejection experiment ran a
device-owned query dispatch, inserted a compute-to-compute barrier, and then read
the result from compaction. Those extra dispatch and barrier steps are gone.

`depth_pyramid_gpu_scene_query.glsl` is now the single conservative GPU-scene
projection/query implementation shared by the standalone qualification shader and
the fused compaction variant. The CPU-projected/device-tested stream remains an
independent safety oracle, and the fused shader still writes the complete result
record for fence-delayed identity, shape, rejection, and command-bin validation.

The experimental configuration creates two compatible compaction pipelines. Frames
with unpublished, stale, rebuilt, or camera-cut history use the base frustum/LOD
pipeline, which does not statically access a depth image. Only eligible frames bind
the correct per-view persistent history and use the fused shader. This is required
by Vulkan image-layout validity; a uniform-false branch in a shader that statically
uses a sampler is not a substitute for valid history.

Frustum-rejected candidates now write an explicit `OutsideView` fail-visible result
before returning. Frustum culling still omits their command independently, but the
result stream remains fully initialized and auditable for every candidate.

## Correctness and lifecycle evidence

Release validation and synchronization-validation runs on the RTX 4090 prove:

- 32-frame overlap/camera-cut: 404 commands on unavailable/cut frames, exactly
  331 commands after 73 pre-cut occlusion rejections, and exactly 362 after 42
  post-cut rejections;
- off-frustum: 303 candidates, 192 explicit fail-visible results, and exactly 98
  commands after frustum culling plus 16 occlusion rejections;
- scRGB -> HDR10 -> SDR rebuild: base-pipeline fallback while history is invalid,
  then exactly 275 commands after 28 rejections, with 15 fail-visible projections;
- every eligible frame has zero invalid results, unsafe mismatches, bin mismatches,
  and indirect overflow;
- the standalone shared projection retains its exact 73/42 temporal verdicts with
  zero invalid or unsafe results;
- no `gpu.depth.occlusion-gpu-scene-query` range is recorded by the fused route.

The lifecycle runs caught and repaired two real integration errors before evidence
was accepted: the first fused pipeline statically referenced an uninitialized
history descriptor on unavailable frames, and the first off-frustum implementation
left diagnostic records unwritten on its early return. The dual-pipeline fallback
and explicit `OutsideView` record are the final validated behavior.

A fresh same-build measured-frame-10 final-SDR pair is byte-identical. Both files
have SHA-256
`5c7cd37994e737d39ac5ff9a47665e5e181f41451fd51f59fc6e942cb3ce40ba`.

Debug and Release builds succeed, including both shader variants. Both portable

forward/reverse, D32/R32, odd/1D/native-4K reduction/query cases exactly with Vulkan

## Performance decision

One fresh 1280x720 process pair used 40 warmup and 200 measured frames. It is smoke
evidence, not a repeated admission set.

| Metric | Query-only control | Fused rejection | Delta |
|---|---:|---:|---:|
| Wall average | 10.057424 ms | 5.596378 ms | -4.461046 ms |
| CPU-frame median | 10.692600 ms | 6.811600 ms | -3.881000 ms |
| GPU-frame median | 0.378048 ms | 0.376416 ms | -0.001632 ms |
| Compact median | 0.008672 ms | 0.013408 ms | +0.004736 ms |
| Separate device-owned query | 0.001024 ms | none | -0.001024 ms |
| GBuffer median | 0.067584 ms | 0.066560 ms | -0.001024 ms |

Wall/CPU movement is dominated by fence-wait state and is not credited. The
complete GPU median slightly favors fusion, but the isolated work shows that fused
projection adds about 0.004736 ms to compaction while eliminating a 0.001024 ms
dispatch and approximately 0.001024 ms of raster in this small fixture. That does
not demonstrate scalable benefit.

Two reverse-ordered native-4K pairs used 100 warmup and 500 measured frames. They
remain non-admissible because unrelated forward/UI work and GPU-frame distributions
change drastically between processes. Pair A reports 9.331872/8.033440 ms query-
only/rejection GPU medians while wall time moves in the opposite direction. Pair B
reports 3.910624/3.845184 ms, but its GPU p95 and unrelated passes occupy different
states. The stable local ranges put fused compaction at 0.013984–0.014848 ms versus
0.011136–0.011488 ms for base compaction plus the separate query. No production
speedup is claimed.

## Decision and remaining work

Keep fused rejection as the safer, lower-dispatch experimental implementation, but
do not enable it by default. The next performance work should use a larger occluded-
geometry workload, avoid qualification-only CPU/readback overhead when measuring a
deployable route, and reduce duplicated world-AABB/frustum/projection math inside
the fused invocation. Selected moving-occluder, moving-occludee, and disocclusion
fixtures are now complete; see
`docs/performance/M7.6-moving-occluder-disocclusion-2026-09-11.md`. Small-object,
and explicit depth-content invalidation fixtures are now also complete; see
`docs/performance/M7.6-small-object-depth-content-2026-09-11.md`. Resize is now
complete in `docs/performance/M7.6-resize-recovery-2026-09-11.md`. The duplicate
frame-build/history copy is subsequently removed in
`docs/performance/M7.6-in-place-view-history-2026-09-11.md`; the controlled
large-workload performance gate remains.

M7.6 stays active and no accepted ADR changed.
