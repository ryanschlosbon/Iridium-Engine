# M7.8 GPU residency reference qualification — 2026-10-01

M7.8 remains **active**, not complete. This checkpoint implements and exercises
GPU allocation semantics but does not change image-producing engine work.

## Behavior and interfaces

`VirtualShadowMap.h/.cpp` now provide checked 80-byte residency-request and
96-byte page-mapping records alongside the existing full-identity resident ABI.
48-byte telemetry reports requests, hits, allocations, evictions, raster demand,
missing pages, update overflow, pool overflow and invalid input. Explicit size and
offset assertions freeze the C++/std430 boundary. Missing mappings are never
sampleable; pending mappings require separate successful raster completion.

`virtual_shadow_residency_reference.comp` is a **serial qualification oracle**,
not the live allocator. It consumes unique requests ordered by priority,
receiver coverage and full address, checks that ordering on-device, and preserves
full UUIDs, signed 64-bit pages, 64-bit revisions and frame ages. UUID comparisons
are byte-lexicographic, signed coordinates use signed high words, and the remaining
address fields follow the RHI comparator exactly. The compact marking output's
ordering cannot be used directly as this input ordering.

The shader maintains one full-key resident record per physical slot. It performs
independent static/dynamic invalidation, clears stale validity even when redraw
budget is exhausted, protects all requested pages from eviction, and reproduces
priority/age/physical-slot eviction and both safe fallback policies. It rejects
bad identities, duplicate requests/residents, wrong physical indices, invalid
flags/validity and unsorted inputs before modifying any resident record.
An invalid-input result leaves mapping contents unspecified: callers must check
telemetry before consuming them. ABI-zero resident slots are unused storage.

The serial reference is bounded to 256 requests and 256 physical slots. It must
not be used as the 16K-page production allocator. This bound is tested separately
from actual descriptor capacity using 257-element test buffers.

`VulkanVirtualShadowMarkingTests.cpp` owns private host-visible coherent buffers,
descriptors, pipeline, command buffer and timestamp queries. These allocations
are destroyed at test completion; they do not reinterpret the live flat page
table or add engine memory. `--residency-only` permits focused Vulkan validation;
the full hardware suite also runs the new tests. CMake compiles the new shader
and tracks it as a hardware-test dependency.

## Qualification and performance decision

- Debug and Release full engine builds succeed. Release configuration reused
  the existing Debug GLFW source checkout with FetchContent disconnected after
  an unavailable network prevented downloading another copy; no dependency
  version changed.
- All 78 CTest tests pass in each configuration. The RHI suite now contains
  24 passing cases, including checked request/mapping conversion and malformed
  state/layer/slot/ABI rejection. Only the latest M5 superseding fingerprint gate
  is refreshed; historical evidence hashes remain immutable.
- Focused hardware qualification passes on RTX 4090 in both configurations:
  14 oracle dispatches and five atomic rejection cases, with zero Vulkan errors.
  Every mapping field, resident record and telemetry count matches the CPU
  reference. Fixtures cover empty allocation/reuse, hits, separate invalidation,
  exhausted budgets, static-cache disable, pool overflow, protected eviction,
  wide ages, mixed light owners/projection identities and the 256-element bound.
  Known raster-complete fixtures are constructed with the CPU commit helper;
  this does **not** claim GPU raster or GPU completion publication.
- Full Debug and Release Vulkan suites also complete successfully, covering
  page crops, depth reconstruction, native-4K demand and persistent two-slot
  marking/compaction in addition to residency. Their repeated residency medians
  are 10.7245/10.504 ms, consistent with the focused rejection measurement.
  Artifacts: `out/m7_8_gpu_residency_reference_20261001.{debug,release}.log`.
- Five repeated 256-request/256-slot/64-update dispatches measure **10.5083 ms
  Debug / 10.8429 ms Release** median using GPU timestamps around the dispatch.
  Host upload, pipeline creation, submission and readback are excluded. Test
  buffers are host-visible, not a production device-local benchmark. Even under
  that qualification setup, this is clearly too expensive: the serial reference
  is **rejected for live production integration**. A scalable lookup/validation/
  allocation implementation is required and must retain this exact oracle.
- A hidden native-4K Debug launch completes eight moving-camera frames with
  Vulkan validation and the explicit full-depth oracle. Final observed demand
  is 120 requests with exact full-identity/coverage agreement, zero overflow,
  four clip levels and projection revision 1. Shutdown collects pending slots;
  the validation error log is empty. Artifacts:
  `out/m7_8_gpu_residency_reference_20261001.live.{log,err.log,jsonl}`.

## Visual and memory impact

There is no new image-producing shader path, page drawing or sample consumer.
Conventional shadows remain active and selectable. No new matched screenshot
comparison is claimed; the preceding byte-identical demand-only capture evidence
and its whole-frame overhead/p99 measurements remain authoritative.

Live experimental persistent virtual-shadow allocations remain 93,064,256 bytes
(88.753 MiB), with zero added engine VRAM from this checkpoint. Request readbacks
and the expensive full-depth CPU oracle remain qualification-only. The hardware
test's four buffers request 69,952 bytes (257 x 80-byte requests, 257 x 96-byte
residents, 257 x 96-byte mappings, plus 48-byte telemetry), excluding Vulkan
allocation alignment and implementation-owned pipeline/descriptor/query memory.

## Remaining M7.8 gates

1. Produce full-key sorted unique requests entirely on GPU from immutable live
   light metadata and receiver demand; implement scalable residency lookup and
   bounded deterministic arbitration without CPU readback driving the frame.
2. Bind persistent device-local records through the render graph, handle frame
   ownership and generation-safe raster completion, and retire/invalidate old
   light/projection content safely.
3. Render selected pages with GPU caster culling/indirect draws, rasterized
   borders, alpha/two-sided semantics and independent static/dynamic depth layers.
4. Share virtual sampling across deferred and complex-forward consumers, add
   local-light pages and safe observable missing-page fallback.
5. Expose page/cache/caster/memory diagnostics and perform matched native-4K
   whole-frame visual, GPU/CPU percentile and VRAM comparisons before classifying
   the complete path as production, experimental or rejected.

No accepted ADR is superseded. ADR-0010, the roadmap, context and frame budget
record this checkpoint and its explicit production rejection. M7.9–M7.12 remain
unchanged and M7 as a whole is not complete.
