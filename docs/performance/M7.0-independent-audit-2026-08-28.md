## Verified rendering facts

- `DrawPacket` is 240 bytes/aligned 16 and mixes a model matrix and hot draw fields
  with scene UUID, source/exact primitive GUIDs, material GUID, selection,
  transparency, bounds, and diagnostics.
- `Application` rebuilds a packet for every enabled model submesh each frame,
  linearly searches material overrides per primitive, computes camera distance for
  ordinary opaque work, sorts opaque/forward queues, and copies full packets into
  selection and shadow work.
- The main GBuffer, directional shadows, local shadows, probes, selection, and
  forward paths submit individual `vkCmdDrawIndexed` calls. There is no indexed
  draw-indirect path or capability contract.
- Main opaque rendering has no general frustum, LOD, or Hi-Z rejection. Spot and
  point shadows and probe faces already have independent CPU sphere rejection;
  directional cascades iterate all eligible casters.
- Main, shadow, probe, and selection consumers currently share source packets but
  not an incorrect main-camera visibility decision. That separation is a required
  M7 invariant.
- One global caster revision invalidates all affected shadow/probe consumers even
  when a changed caster is irrelevant to a particular light or probe.
- The clustered-light product remains one shared count/scan/fill/sort/finalize
  representation for deferred and forward consumers. Its historical dressed cost
  is about 1.93 ms, while the earlier 512-light microbenchmark was about 0.241 ms;
  M7.10 must reprofile the current complete workload before changing it.

## Verified asset and geometry facts

- Cooked schema 5 is one required seven-section parent product. Model conversion,
  serialization, runtime decode, and GPU publication remain whole-model operations.
- The standard vertex is 72 bytes of float32 attributes. Import/runtime publication
  always uses UInt32 indices even though the RHI and Vulkan backend can bind UInt16.
- `lodSection` and `meshletSection` are unpopulated. Current validation also fails
  to reject arbitrary non-sentinel values in those fields.
- Runtime models own one geometry handle and model publication creates one vertex/
  index buffer pair. There is no stable arena or child geometry residency.
- Both `sourcePrimitiveGuid` and exact `primitiveGuid` survive metadata, cooking,
  runtime decode, `SubMesh`, and `DrawPacket`. Connected transparent pieces may
  share the source GUID but have deterministic distinct exact GUIDs.
- Whole-asset newest-only scheduling, atomic replacement, and last-known-good
  behavior are present. Only embedded texture views currently have child CookKeys
  and DDC reuse; primitive geometry and LODs do not.
- Publisher eviction does not physically release cached model GPU resources on the
  current application publication callback, so accounting alone is not a residency
  guarantee.

## Source-driven execution corrections

1. Keep the validated whole-model product through M7.2 while GPU-scene identity,
   generations, mobility, sparse updates, and direct-render parity are proven.
2. Add high-precision geometry arenas and explicit mixed-index/base-vertex semantics
   in M7.3 before compact-attribute experiments.
3. Add parent-contained deterministic LOD definitions in M7.5 before M7.9
   externalizes them into child products and progressive physical residency.
4. Add explicit indirect feature/limit discovery and a direct tiny/unsupported/
   debug/overflow fallback before any indirect-count production use.
5. Preserve independent visibility for main, directional, spot, point, probe, and
   selection consumers. Existing local/probe CPU tests are fallback oracles.
6. Reuse transparency-pyramid lifetime mechanics, not its nearest-depth reduction
   or frame-local semantics, for the conservative previous-frame occlusion pyramid.
