# M7.6 device occlusion-query parity — 2026-09-10

## Result

The first device-query slice is accepted as qualification infrastructure, not as
production occlusion admission. A new Vulkan compute shader consumes the complete
R32 farthest-depth pyramid and a versioned, backend-neutral 32-byte query ABI. It
selects a mip whose mapped query covers at most four texels, combines the farthest
occluder depth, applies the configured forward/reverse-Z comparison and writes a
32-byte result record. Invalid rectangles, depths and biases fail visible.

The shader deliberately mirrors the corrected recursive integer mapping used by
`DepthPyramidReference`. It does not use direct normalized base-to-mip scaling,
which was proven unsafe at odd extents. Explicit padding avoids host/std430 array
stride ambiguity and the ABI reports the selected mip, sample count, tested flag,
farthest depth and occlusion verdict for exact oracle comparison.

## Device evidence

`VulkanDepthPyramidTests` now runs reduction and query in one synchronized headless
submission. For each of 28 pyramid configurations (seven extents, forward and
reverse depth, R32 and D32 source), 130 deterministic rectangles are tested. The
set includes 1x1, 15x1, 1x15, 15x3, 7x5, 127x73 and native 3840x2160 extents.
All 3,640 device query records match the CPU oracle exactly in Debug and Release,
including selected mip, sampled texel count, farthest depth and final verdict.
The RTX 4090 run is clean under Vulkan synchronization validation.

The history owner was also hardened while auditing integration. Its retained ABI-v2
`projectionRevision` field now fingerprints the complete view and projection
matrices. Previously it fingerprinted projection alone, which could permit a camera
translation or rotation to reuse depth rasterized from a different pose. The field
name remains stable, but its documented meaning is now the complete world-to-clip
camera transform.

The publication tracker now exposes separate queue-ordered and fence-published
metadata. `queued()` identifies the latest scheduled image for a later submission
on the same ordered graphics queue; it may be considered only when the consumer
serial is exactly adjacent. `published()` remains the fence-completed contract for
CPU readback. Scheduling a newer same-view image immediately replaces only the
queued metadata, while completion of an older frame still cannot publish stale
ownership. Reset/rebuild clears both domains.

## Integration constraint and remaining work

No live indirect command is rejected by this slice. The integration audit found
that requiring history to be both CPU-fence-completed and exactly one global
submission old is not normally satisfiable with two frames in flight. The new
queue-ordered metadata domain resolves that ownership ambiguity without weakening
serial adjacency: the prior copy completes before the next query reaches the same
queue, and the next overwrite is recorded after that query. Alternating retained
scene/asset views still fail stale because their view history is two submissions old.

The immediate live-integration prerequisites are now complete. The renderer computes
the complete deferred-opaque plus depth-writing-forward owner before opaque
compaction and, under `--experimental-depth-occlusion-query`, binds the proven shader
for eligible GPU-scene candidates. Requested/projected/tested/would-reject/invalid/
fail-visible counters are fence-delayed and frame-attributed. See
`docs/performance/M7.6-live-query-qualification-2026-09-10.md`.

The temporal large-occluder/cut/disocclusion fixtures and device-owned query
construction/compaction remain. The duplicate four-chain build/publication topology
also remains a pre-admission memory task. Default allocation and all occlusion
rejection remain off. No ADR changed.

## Verification

- Debug and Release full engine builds succeed.
- Portable Debug and Release CTest pass 77/77.
- Debug and Release `VulkanDepthPyramidTests` pass all 28 reduction configurations
  and all 3,640 query records exactly with synchronization validation enabled.
- Live binding is now separately qualified and measured under an additional
  default-off flag; this document's standalone parity result remains unchanged.
