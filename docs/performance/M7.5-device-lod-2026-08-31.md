## Changed behavior and interfaces

`GpuScene.h`, `GpuScene.cpp`, `scene/GpuScenePublisher.*`, and `Application.cpp`
publish shared LOD children without creating extra instantiated primitives or
material bindings. Maximum chain size is 16 including LOD0. Canonical primitive
bindings remain attached to their base geometry and exact source/cooked GUIDs.
Children retain parent material identity. Invalid children or exhausted capacity
fall back atomically through the existing direct-owner path.

The 96-byte geometry ABI remains size/version 1; formerly reserved fields now mean:

| Field | Meaning |
|---|---|
| `localBoundsMin.w` | Object-space geometric error, zero for LOD0 |
| `localBoundsMax.w` | Finest-to-coarsest ordinal, 0..15 |
| `state.z` | Next coarser dense geometry index, or `InvalidGpuSceneIndex` |

Dense-link changes participate in exact packed-byte revision comparison and
fence-owned upload planning. Material edits do not dirty geometry. Child removal,
reintroduction, relocation, and capacity fallback have regression coverage.

`GpuSceneIndirect.*` and `VulkanVertexBackend.*` now bind the shared vertex arena
at byte zero and emit the geometry's signed base-vertex offset in each command.
Bins separate physical buffers, index type, material and pipeline, not individual
vertex offsets. The backend checks packet/packed-record references and actual
geometry addressing before admitting indirect work. The indirect ABI is v2: a
32-byte candidate includes a host-validated maximum compatible LOD; the indexed
command remains 20 bytes. Direct rendering keeps its existing per-primitive bind.

`GpuSceneLod.*` and `gpu_scene_frustum_compact.comp` implement a matching stateless
CPU/device selector. It bounds pixel displacement of an object-space error ball
around every point of the base AABB using clip-coordinate row norms, the minimum
homogeneous W and maximum absolute XY. This includes nonuniform/negative scale,
shear, off-axis perspective and orthographic projection. Eye-crossing, invalid or
nonfinite cases retain LOD0. A subsequent hardening also retains LOD0 when the error
ball can cross either depth clip plane, including reverse-Z projection: a grazing
surface may otherwise clip away despite a small XY displacement bound.
Monotonic error/count/ordinal checks reject malformed
chains; traversal is bounded. The 1.0001 rounding guard is mirrored on both paths.

The host limits device traversal to the resident prefix that shares the bin's
vertex/index buffers and index type. A UInt16 child cannot silently enter a UInt32
bin. This is conservative prefix admission, **not** the planned missing-fine
streaming fallback. Main GBuffer selection does not mutate shadow, probe,
selection, complex-forward, transparent, or RT geometry decisions.

Opt-in CLI:

```text
--experimental-gpu-lod-error-pixels 2
--gpu-lod-max-level 0
```

The first option enables the experiment (0.01..64 pixels); the second optionally
pins LOD0. The default is disabled. `--reference-direct-gbuffer` still forces the
unculled direct LOD0 reference. The cap is global diagnostic policy, not completed
per-entity hero authoring. Capture/profile metadata records the requested settings.

Experimental runs independently build expected commands and compare GPU-written
commands after the owning fence. Comparison includes index count, first index,
base vertex, instance count and canonical primitive identity, plus duplicate and
missing command checks. A mismatch fails the run. Added counters expose base,
oracle and device triangles, reduced commands, and command mismatches. Readback
and oracle CPU cost remain in experimental performance measurements. They are not
silently excluded as though this were a shipping path.

## CPU upload-memory read regression and repair

The first five-process oblique comparison (`timing-oblique`) exposed a substantial
regression: approximately 1.55 ms/frame for disabled LOD and 3.37 ms/frame for the
experiment. GBuffer CPU recording was about 0.27 ms versus 1.89 ms. CPU packet
checks and the oracle repeatedly read mapped upload buffers; host-visible coherent
memory is not necessarily CPU cached. That implementation is rejected.

`VulkanVertexBackend` now owns hot-only CPU mirrors per frame context. The exact
upload ranges copy the same source records into both the GPU table and its CPU
mirror; there is no borrowed publisher lifetime or per-frame whole-scene copy.
Prepared capacity bounds the mirrors. The CPU view is retained at `updateCamera`,
and command readback is copied contiguously before field/duplicate checks.
`gpu_scene.cpu_mirror.capacity_bytes` reports the extra host payload capacity;
GPU allocations and shader data layouts do not change. The mirror is not a second
scene database: it has no identities, ownership decisions or independent revisions.

Cached Release binary `699056ef0d4f53157a364bb118d92e0196a1843672e81bbfd841172505609eb7`
and Debug `501c6c47a493e49ce78da7e009097c831130df5f4a2b949bccdb115e927e7a77`

## Remaining work

Remaining M7.5 work: generation/revision-safe per-view device hysteresis; motion
and camera-cut evidence; missing-fine resident fallback beyond a compatible prefix;
per-content hero controls; independent shadow/probe LOD quality decisions; richer
lighting/material and silhouette evidence; and worthwhile complete-path reduction.
The small conservative cooker yield remains a limitation, not permission to
loosen error/material/topology constraints. The prior cross-configuration texture
codec CookKey issue remains tracked for M7.9.

No accepted ADR is superseded. M7.6 and later slices are not started.

Next bounded implementation should make history explicitly per consumer/view and
generation/revision-safe. Do not use the rotating frame-context index as temporal
view identity, dense geometry indices as durable history keys, or a global selected
LOD stored on canonical primitives. GPU history needs the immediately preceding
ordered submission, not whichever older frame happens to own the current fence
slot. Tests must cover retirement/reuse, dense relocation, product changes, camera
cuts, resolution changes, and directional threshold oscillation. The hysteresis
band must state its maximum error explicitly; a nominal 2-pixel setting must not
silently conceal a larger allowed error.
