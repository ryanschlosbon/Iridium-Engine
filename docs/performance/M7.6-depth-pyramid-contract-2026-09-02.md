# M7.6 Conservative Depth-Pyramid Contract — 2026-09-02

## Decision

Correction on 2026-09-04: initial query mapping could falsely occlude at odd extents
after multiple reductions. Recursive inverse partition mapping and exhaustive
rectangle tests repair this; see `M7.6-odd-extent-query-correction-2026-09-04.md`.

Accept the first M7.6 contract/oracle slice and keep M7.6 active. The RHI now defines
the extent, mip, device-depth convention, farthest-depth reduction, bounded query,
and previous-frame eligibility semantics that Vulkan Hi-Z must match. The contract
does not enable occlusion culling yet; all existing rendering remains unchanged.

This separation is intentional. A Vulkan image or shader may not reject geometry
until it agrees with the backend-neutral oracle and reports every fail-visible path.
The existing transparency pyramid is not promoted: it stores nearest metric depth,
has frame-local lifetime, and does not satisfy conservative previous-frame history.

No ADR changes. This implements the M7 execution plan under the existing ADR-0010
occlusion direction without changing its scope.

## Contract and oracle

- `DepthPyramidExtent`, `depthPyramidMipCount`, and `depthPyramidMipExtent` define a
  complete Vulkan-style mip chain for arbitrary nonzero extents.
- `DeviceDepthConvention` makes forward and reverse zero-to-one depth explicit.
- Each reduced texel stores the farthest source depth: maximum for forward Z and
  minimum for reverse Z. Whole-bounds rejection is therefore conservative.
- Odd dimensions use proportional source intervals. Every source edge texel reaches
  every coarser level instead of being silently dropped by a naive 2x2 reduction.
- `DepthPyramidReference` sanitizes nonfinite source depth to the far plane, builds
  deterministic reference mips, selects the first level covering the projected
  rectangle with at most 2x2 texels, and samples at most four texels.
- Occlusion is strict and bias-aware. Equal depth remains visible to prevent static
  geometry from self-occluding against its own previous-frame sample.
- Invalid bounds, out-of-range depth, malformed bias, or unavailable storage never
  produce an occluded result.
- `evaluateDepthPyramidHistory` emits stable fail-visible reasons for disabled or
  missing history, zero/changed extent, stale history, invalid projection, camera
  cuts, rapid motion, near-plane intersection, new residency, and large transform
  changes. Only an exact one-frame-old eligible history can be tested.

The reference owns no Vulkan types, ECS records, render-graph resources, or editor
state. It is suitable for device readback parity and later shared consumers without
leaking backend implementation into the RHI contract.

## Visual and performance disposition

There is intentionally no image or GPU-time delta: the contract is linked but no
runtime image, dispatch, descriptor, or culling decision consumes it yet. The visible
validation launch confirms unchanged executable behavior, not Hi-Z admission.

## Remaining M7.6 work

- Add persistent previous-frame D32-derived farthest-depth pyramid resources with
  extent-safe creation, resize/zero-extent handling, per-mip views, retirement, and
  explicit history ownership.
- Implement the proportional odd-edge reduction in Vulkan and prove mip readback
  against `DepthPyramidReference` for forward depth.
- Add previous-view projection and conservative screen-rectangle/depth bounds, then
  feed eligible queries into GPU-scene compaction.
- Publish requested/tested/rejected counts and every fail-visible reason.
- Freeze and run large-occluder, cut, rapid-motion, disocclusion, near-plane,
  new-residency, small-object, and resize fixtures before enabling production policy.
