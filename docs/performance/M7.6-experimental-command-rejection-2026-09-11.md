# M7.6 experimental command rejection — 2026-09-11

## Result

M7.6 now has a separately explicit `--experimental-depth-occlusion-rejection`
route. The option implies the live depth pyramid and both qualification query
streams, but does not change the production default. When exactly-adjacent,
same-view history is eligible, the device-owned projection/query dispatch runs
before opaque GPU-scene compaction. A shader variant then consumes only valid ABI-2
`tested` results for the matching primitive and omits confirmed occluded candidates
from the existing per-bin indirect command stream. Every malformed, stale,
unavailable, untested, or projection-rejected result fails visible.

The fence-delayed qualification path retains the independent CPU-projected/device-
tested oracle. It validates result shape and identity, proves every consumed
device-owned rejection is also rejected by the CPU safety oracle, adjusts the
expected per-bin command counts, and fails the run on an unsafe verdict, invalid
record, bin mismatch, command mismatch, or overflow. The new delayed counter
`depth.occlusion.gpu_scene.applied_rejects` distinguishes actual command removal
from diagnostic `would_reject` results. Capture/profile provenance records the
rejection option independently from pyramid and query enablement.

This record describes the first qualification architecture. The follow-up now
fuses projection/query with compaction while retaining host-visible results and the
independent safety oracle; see
`docs/performance/M7.6-fused-query-compaction-2026-09-11.md`.

## Correctness and lifecycle evidence

All runs used the Release build on the RTX 4090 with Khronos validation,
synchronization validation, and process-local suppression of unrelated implicit
overlay layers.

The frozen 32-frame `m7_occlusion_depth_stack_v1` temporal run proves command
rejection through the deterministic camera cut:

- frame 1 has no eligible history and retains all 404 commands;
- frames 2-12 retain exactly 331 of 404 commands, applying 73 conservative
  rejections per frame;
- frame 13 classifies history as `CameraCut` and retains all 404 commands;
- frames 14-32 retain exactly 362 of 404 commands, applying 42 rejections per
  frame.

Every eligible frame has exact device/oracle per-bin command parity, zero invalid
records, and zero unsafe mismatches. Current-build baseline and rejection captures
are byte-identical at the pre-cut frame 10, cut frame 12, and post-cut frame 20. The
respective SHA-256 values are `5c7cd37994e737d39ac5ff9a47665e5e181f41451fd51f59fc6e942cb3ce40ba`,
`9e696292f8969a8197fe475713688cebcac2a0bc3125cded4102dc41435dbc65`, and
`9e696292f8969a8197fe475713688cebcac2a0bc3125cded4102dc41435dbc65`.
These comparisons intentionally use a fresh baseline from the same build; an older
historical cut capture has a different whole-image hash and is not treated as the
comparison oracle.

The 16-frame `m7_three_dense_one_visible_v1` off-frustum run retains 114 commands on
the unavailable first frame and exactly 98 thereafter. Each eligible frame applies
16 occlusion rejections only after frustum visibility, with zero mismatched bins,
invalid results, or unsafe results.

The 30-frame scRGB -> HDR10 -> SDR transport-rebuild run has four history-
unavailable frames and 26 eligible frames. Each eligible frame applies 28
rejections from 303 candidates after 288 tests and 15 explicit fail-visible
projections. Descriptor/history regeneration recovers with zero command mismatch,
invalid result, or unsafe mismatch.

After promoting bin mismatch and overflow from telemetry to hard rejection-path
failures, Debug and Release rebuild successfully and both portable suites pass

rejection launch both exit cleanly. The latter again reports exact 404/404 on
unavailable/cut frames, 331/331 with 73 applied rejections before the cut, and
362/362 with 42 applied rejections after it; mismatch, overflow, invalid, and unsafe
counters remain zero.

## Performance decision

The experimental route is not admitted as a production default. A 1280x720
query-only/rejection pair removed 73 of 404 opaque commands, but the complete GPU
median increased from 0.370496 ms to 0.379104 ms (+0.008608 ms). The device-owned
query increased from 0.001024 ms when scheduled after compaction to 0.011712 ms when
scheduled before it, while compaction fell from 0.008256 ms to 0.003072 ms. Requested
memory was unchanged at 1343.572525 MiB. Wall time moved from 9.190076 ms to
8.383990 ms, but fence-wait noise makes that value non-admissible.

The first native-4K pair was invalidated because unrelated forward/UI GPU work
changed dramatically between routes. A longer 300-warmup/1000-measured-frame pair
also remained uncontrolled: query-only/rejection GPU medians were 8.798752/10.582464
ms and forward medians were 0.405504/0.631808 ms, so the whole-frame difference
cannot be attributed to command rejection. The unfavorable result is retained,
not normalized into a performance claim.

## Remaining M7.6 work

- The second dispatch is removed by the fused experimental route. Reduce duplicated
  frustum/projection math and remove qualification readbacks from a deployable
  performance route.
- Remove the temporary frame build plus persistent-history copy and duplicate
  history/query storage.
- Deterministic selected moving-occluder, moving-occludee, and disocclusion fixtures
  are complete. Explicit depth-content invalidation and small-object fixtures are
  also complete. Scene-target resize/recovery is now complete.
- Repeat controlled alternating native-4K processes with stable unrelated GPU
  passes and report savings only for workloads where avoided raster work exceeds
  query cost.

M7.6 remains active, all occlusion features remain default-off, and no accepted ADR
changed.
