# M4.6 Editor Transaction Performance - 2026-08-02

## Result

The transaction service is comfortably below interactive editor budgets at the
required 1, 100, and 10,000-target scales. The 10,000-target atomic apply is 0.112 ms
median / 0.128 ms p95 / 0.163 ms p99. Undo and redo are allocation-free at every
scale and remain below 0.068 ms p99 for 10,000 targets.

An initial implementation copied all applied operations into a second temporary
vector. The measured 10,000-target apply was 0.473 ms median and allocated 1.68 MB.
In-place stable compaction removed that copy. The accepted measurement is 4.2x faster
at the median and applies with one 120-byte history-entry allocation independent of
target count.

## Method

- Configuration: MSVC Release on the M4 reference workstation.
- Samples: 30 independent histories per target count.
- Workload: one atomic integer property assignment per target, followed by exact undo
  and redo.
- Timing scope: transaction service apply, undo, or redo only. Command construction is
  outside the scope because editor widgets construct commands before commit.
- Allocation scope: C++ global `new`/`new[]` requested bytes.
- Raw data: `docs/performance/data/M4.6-editor-transactions-2026-08-02.json`.

## Whole-editor and gizmo evidence

A like-for-like normal-editor Release run collected 300 measured 1280x720 frames
with validation enabled. Against the accepted M4.5 compact-editor profile, M4.6
changed editor-build median from 0.1021 ms to 0.1032 ms (+0.0011 ms), while p95
improved from 0.1367 ms to 0.1193 ms. Median GPU UI remained 0.0174 ms. Whole-editor
C++ allocations were unchanged at 126 calls and 14,890 requested bytes per frame at
the median. Both runs retained all 300 frames with zero profiler overflow. Raw
profiles: `out/m4.5-release-editor-normal-compact-validation.jsonl` and
`out/m4.6-release-editor-visible-1280-validation.jsonl`.

| 1280x720 normal editor | M4.5 median / p95 / p99 | M4.6 median / p95 / p99 |
|---|---:|---:|
| Editor build | 0.1021 / 0.1367 / 0.1523 ms | 0.1032 / 0.1193 / 0.1779 ms |
| CPU frame | 0.5647 / 0.7527 / 0.8291 ms | 0.5727 / 0.7648 / 0.9652 ms |
| GPU UI | 0.0174 / 0.0184 / 0.0205 ms | 0.0174 / 0.0184 / 0.0195 ms |
| GPU frame | 0.0528 / 0.0623 / 0.0823 ms | 0.0529 / 0.0717 / 0.0849 ms |

The viewport gizmo now has a dedicated nested CPU range. A 300-frame hidden 4K
Release validation run measured its selected-entity steady path at 4.1 / 5.9 /
6.8 microseconds median/p95/p99, with a 9.2 microsecond maximum. The containing
editor build was 0.1673 / 0.2263 / 0.2519 ms. The run retained all frames, reported
zero overflow, and emitted no validation warning/error line. Raw profile:
`out/m4.6-release-editor-gizmo-instrumented-4k.jsonl`.

Interactive validation exercised hierarchy Ctrl-click multi-selection, atomic
two-target Transform editing, menu label/enablement, Ctrl+Z, Ctrl+Y, and
Ctrl+Shift+Z. Both targets restored and reapplied the exact value. Deleting a target
outside history intentionally forced undo failure: the earlier target was rolled
back atomically and a modal presented `Undo failed: entity/transform is no longer
available`. Three long-running validation profiles completed with zero dropped
frames and zero profiler overflow. Representative captures are under `out/` with
the `m4.6-` prefix.

Asset pending/failure/publication/eviction transitions remain covered by the focused
headless transaction tests. They prove those runtime-only changes do not alter
history or dirty state and that pending assignments serialize before publication.
