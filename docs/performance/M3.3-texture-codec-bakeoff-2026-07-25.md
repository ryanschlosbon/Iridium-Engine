# M3.3 Texture Codec Bake-off - 2026-07-25

## Decision

Iridium texture product schema 1 uses Microsoft DirectXTex May 2026
(`4feb3e11a020f35b796fc769a74216a555d4f5ef`) as the pinned Windows reference
codec. Reference cooks force the CPU path with `--single-proc -nogpu`; the tool
identity, implementation version, quality tier, semantic, color-space policy, and
mip/alpha/normal settings are cook-key inputs.

The selected GPU-native products are:

- BC7 sRGB or linear for color/data, using BC7 quick/mode-6 as the default
  iteration quality;
- BC5 linear for tangent-space normal XY, with Z reconstruction;
- BC4 linear for scalar products;
- BC6H unsigned-float for scene-linear HDR color;
- uncompressed reference products for fidelity tests and unsupported-platform
  diagnostics, not as the normal shipping representation.

The cooker artifact remains Iridium's versioned sectioned container. DDS is an
evaluation interchange/output of the reference codec, not persistent asset identity
or the renderer asset database.

## Method

`tools/TextureCodecBakeoff.py` generates deterministic 256x256 color, tangent-normal,
scalar, and HDR fixtures. It runs the pinned CPU codec, decodes the products, reports
error and encoded size, and hashes three independent BC7 outputs per quality mode.
Color input and output are explicitly tagged sRGB so the comparison measures block
compression rather than an accidental transfer-function conversion.

The source tree was built with Visual Studio 2026 18.8.1. DirectXTex OpenMP was
disabled and GPU compression was forbidden. Timings include process startup and file
I/O and are selection evidence, not a cooker throughput baseline.

All three independent runs of each BC7 mode were byte-identical. Default and maximum
produced identical bytes on this fixture. Quick traded 0.639 dB for approximately
26x lower elapsed time than default, so it is the default iteration policy.
Production quality remains an explicit setting and distinct cook key; it is not
silently substituted based on machine or thread count.

BC4 maximum error was 0.09412. BC5 maximum angular error was 8.483 degrees on the
deliberately adversarial high-gradient fixture. BC6H maximum relative error was
0.8045 at near-black samples; its mean relative error is the useful aggregate here.
Tracked representative material and HDR captures remain mandatory before M3.3
acceptance.

## Reproduction

Build the pinned DirectXTex `may2026` `texconv` target with `BC_USE_OPENMP=OFF`, then:

```powershell
python tools/TextureCodecBakeoff.py `
  --texconv <path-to-texconv.exe> `
  --work-dir out/benchmarks/m3.3-texture-codec
```

The work directory is disposable derived data. No source asset, sidecar, catalog row,
or runtime GUID depends on that path.
