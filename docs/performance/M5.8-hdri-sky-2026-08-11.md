# M5.8 HDRI Sky Checkpoint — 2026-08-11

## Status and scope

The HDRI portion of M5.8 is implemented and validation-clean. This checkpoint does
not accept all of M5.8: local reflection probes, cubemap capture, Skybox rendering,
and the M10 physically simulated atmosphere remain planned.

## Changed behavior and architecture

- Added stable `iridium.component.sky` / `SKY1` source and cooked component contracts.
  `Skybox`, `Hdri`, and `Simulated` have separate runtime data structures and editor
  sections so future implementations do not reinterpret HDRI fields.
- HDRI exposes environment asset, lighting intensity, background intensity, Y
  rotation, camera visibility, lighting participation, enabled state, and priority.
  Selection is priority then stable scene UUID.
- `.hdr` now belongs to the first-class `iridium.environment.hdri` importer rather
  than the generic texture importer. It produces the existing AP1 radiance,
  irradiance, GGX-prefilter, and BRDF-LUT product through DDC.
- Asset Browser environment filtering, cooked equirectangular thumbnails, typed
  drag/drop, clear, asynchronous preparation, and non-destructive diagnostics are
  connected to the Inspector.
- The active Sky drives one backend-neutral `EnvironmentLightingSettings` contract.
  Vulkan packs the settings in the shared clustered scene parameters; deferred and
  complex-forward consumers use the same rotated cube sampling and independent
  background/IBL scale.
- The normal editor scene owns a default Belfast sunset Sky instead of displaying a
  black background when no command-line environment is supplied.

## Performance and memory interpretation

This was a functional checkpoint, not a new 4K frame-time baseline. The runtime
reuses M5.5's accepted 20.297 MiB High environment product and adds one `vec4` to the
existing clustered parameter record rather than allocating a new full-screen target
or pass. The editor-quality reference convolution is intentionally asynchronous but
its 22.3-second cold cook is a workflow cost to optimize or move to a production GPU/
offline cooker after output-equivalence tests. Cache-hit startup avoids repeating it.

## Remaining risks and deferred work

- Skybox rendering and physically based Simulated atmosphere/clouds are not
  implemented; the UI states this rather than silently falling back.
- Local reflection-probe selection/capture remains the rest of M5.8.
- HDR Radiance input is implemented. OpenEXR, KTX2/cubemap source ingestion,
  compression-tier bakeoffs, and importance-sampled GPU/offline convolution remain
  candidates, not claimed behavior.
- The functional capture is 1280x720. M5.8 acceptance still requires prescribed 4K
  probe scenes, capture costs, steady runtime timings, memory, and multi-process
  evidence.

## Roadmap and ADR changes

ROADMAP M5 and M6-M11 now include the high-fidelity shadow, virtual-page, temporal,
colored-transmission, GTAO/CACAO, RTAO, atmosphere, and scalability handoffs.
Accepted ADR-0010 records the lasting direction. No earlier accepted material,
cluster, or shadow-cache contract was weakened.
