# M4.2 Source Scene Scale - 2026-07-31

Status: Accepted M4.2 characterization; these measurements are not shipping gates.

Machine-readable evidence:
`docs/performance/data/M4.2-source-scene-scale-2026-07-31.json`

## Protocol

- Release, MSVC 19.51.36252.0, 32 logical processors.
- One warmup and five measured samples per workload and scale.
- Fixed generated schema-1 and logical-v0 documents at 1k, 10k, and 100k entities.
- Schema-1 entities contain Name and Relationship; all are roots with unique sibling
  order. The serializer output is canonical two-space JSON.
- Each case reports duration, global C++ `new`/`new[]` calls and requested bytes,
  and process working/private memory sampled while the result is still alive.
- Allocation requested bytes are aggregate allocator traffic, not retained memory.
  Live process deltas include allocator behavior and are not a C++ object-size claim.

## M4.0 comparison and decision

M4.0 measured 100k v0 save at 1,809.439 ms p95 and v0 load at 1,450.162 ms
p95. M4.2 canonical serialization is 3.75x faster than that save result despite
performing deterministic ordering and unknown-store reconstruction. Strict schema-1
parse/validation is 5.94x slower than the transitional load and v0 migration is
6.01x slower. The comparison includes a different, modular schema and considerably
more validation, but the 100k result is still a real editor-scale risk.

The dominant evidence is allocation pressure from the source DOM and semantic
reconstruction: strict parsing makes 11.90 million allocation calls at 100k;
serialization makes 6.50 million; migration makes 9.90 million. M4.2 does not hide
this with an ECS redesign or weaken validation. M4.3 will measure staged document
open/commit and may reduce transient copies/reserve known containers. The cooked
binary runtime path remains the production scaling solution. A streaming/SAX source
reader is a later option only if representative authored scenes justify its
complexity.

No renderer behavior, GPU time, VRAM, or visual baseline changed in this slice.
