# M5.7 Complex-Forward Parity and Final Timing — 2026-08-13

Status: accepted. Complex-forward visual parity and the prescribed five-process
native-4K local-shadow timing gate are complete.

## Behavior and architecture

- Added dedicated deferred/complex-forward twins for the two-owner spot and point
  contact fixtures. The twin receiver is opaque clearcoat, so it selects the real
  complex-forward queue while retaining identical geometry, base-layer inputs, and
  shadow-caster participation.
- Both fixture IDs use the same generated light placement and independent stable
  spot-atlas/point-cube ownership as their deferred twins.
- The shadow-visibility diagnostic now accumulates the minimum filtered visibility
  across every contributing directional, spot, and point light. Complex-forward
  debug routing now permits cascade and visibility views instead of returning depth.
- `--benchmark-disable-local-shadows` disables `castsShadows` only on generated
  local-shadow benchmark lights, providing a matched fresh-process on/off baseline
  without changing production component semantics.

## Remaining risk

- Point cube filtering is materially more expensive than spot filtering at 4K.
  M5.9 must compare retained point sample tiers and temporal/contact-hardening paths
  with image-error evidence rather than simply increasing the fixed 5x5 kernel.
- Point-cube fixed filtering remains about 0.325 ms more expensive than spot-atlas
  filtering in the matched two-owner fixtures. M5.9's bounded PCSS tiers and later
  temporal/virtual/RT techniques must continue to be selected by measured quality,
  not assumed to be free on high-end hardware.
