# M7.7 GPU-scene reflection-capture graphics checkpoint

Date: 2026-09-14  
Status: accepted implementation checkpoint; device command construction is
superseded by the subsequent probe-command checkpoint

## Outcome

Compact reflection-probe casters now render through a capture pipeline that reads
the instance transform and material index from the persistent GPU scene. The
primitive index is carried by `firstInstance`, matching the directional, spot, and
point shadow graphics ABI that the upcoming cube-face compaction path will use.

The direct packet pipeline remains available for primitives that cannot enter the
persistent publication. Both pipeline layouts share capture-face, material,
sampler, and lighting descriptor sets; the GPU-scene variant appends its table at
set 4, so compact and fallback draws can safely interleave within one cube face.

`--reference-direct-probe-capture` isolates the direct probe submission without
changing main-view or conventional-shadow submission. The broader
`--reference-direct-gbuffer` reference continues to select all three direct paths.

## Qualification

The 1280x720 Debug validation fixture uses the self-contained M7.7 contact artifact,
the `point_shadow_contact_v1` scene, and a six-face renderable-owner capture.

The scene-linear images are numerically equivalent but not byte-identical. Across
2,764,800 RGB values, 257,472 differ; the maximum absolute difference is
`0.0009765625` (one R16 quantization step) and the mean absolute difference is
`0.0000194135`. There are no missing pixels, invalid references, overflows, or
Vulkan validation errors. This explicitly supersedes byte identity as the gate for
the GPU-scene capture-vertex transition only; later device-command qualification
must not enlarge this envelope.

device face tests with exact owner exclusion; indirect-count rendering through the
pipeline established here; delayed overflow/count validation; and warmed
heterogeneous capacity/timing admission. Probe-specific LOD remains subsequent.
