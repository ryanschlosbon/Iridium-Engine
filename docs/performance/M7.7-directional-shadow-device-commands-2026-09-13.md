# M7.7 directional-shadow device commands — 2026-09-13

## Result

Directional cascades now build their persistent GPU-scene caster commands on the
device. The application submits compact primitive indices, Vulkan bins those
indices only by physical geometry buffers, index type, alpha-mask mode, and
two-sided raster state, and one compute dispatch per refreshed cascade performs
light-view visibility and emits `VkDrawIndexedIndirectCommand`-compatible records.
Direct packets remain a mixed-submission fallback and small or unsupported GPU-
scene workloads remain on the direct path.

This is not M7.7 completion. Spot and point device commands followed in the local-
shadow checkpoint; shadow-specific LOD, position/opacity-only streams, independent
reflection-capture visibility, and the full quality matrix remain open. See
`docs/performance/M7.7-local-shadow-device-commands-2026-09-13.md`.

## Changed behavior and architecture

- `GpuSceneShadowIndirectCandidate` is a backend-neutral 16-byte ABI containing a
  dense primitive index and its host-validated bin/output range. One candidate
  table is reused by every refreshed cascade; only commands and counts have per-
  cascade regions.
- The compute shader reads the directional shadow matrices and persistent GPU-
  scene tables, mirrors the accepted world-space sphere/clip-volume test, and
  writes the existing 20-byte indexed-indirect command ABI. `firstInstance` is the
  primitive index.
- GPU-scene shadow vertex and masked-fragment variants fetch transform and material
  identity from the persistent tables. The direct shaders and push-constant path
  are retained without repacking fallback work.
- The directional graphics pipeline layout now includes the shared GPU-scene set.
  Direct pipelines do not consume it; indirect pipelines do.
- The path requires multi-draw indirect, indirect first-instance, and indirect-
  count support, uses a minimum eight-candidate workload, and fails the whole GPU-
  scene portion to direct submission on stale handles, incompatible physical
  buffers, or capacity exhaustion.
- Fence-delayed count validation compares every device bin against the independent
  CPU visibility oracle and rejects overflow. Exact counters expose device/oracle
  commands, mismatched bins, overflow, bins, direct fallback, and fallback reason.
- `--reference-direct-gbuffer` is the qualification reference switch for both the
  main GBuffer and directional GPU-scene submission, allowing matched final-image
  comparisons without a separate shadow-only command ABI.
- The directional shadow render uniform declaration was corrected to include the
  depth-span and filter arrays already present in the 720-byte C++ layout. The
  transform-only direct vertex stage did not read the displaced tail previously,
  but the fix prevents future consumers from inheriting a stale offset contract.

The implementation advances ADR-0010 and reuses ADR-0006/ADR-0010's persistent
GPU-scene and independent light-view direction. It does not change the accepted
conventional-versus-virtual shadow decision.

## Qualification evidence

Two validation-enabled Release processes used
`m7_directional_shadow_caster_culling_v1`, the source-free schema-7 contact
artifact, 35 m directional coverage, 8 warmup frames, 16 measured frames, and
1280x720. The automatic process used device commands; the reference process used
direct GBuffer and directional-shadow submission. Every automatic frame reported:

|---|---:|

| Indirect bin submissions | 6 |
| Mismatched bins / overflow | 0 / 0 |
| Direct fallback casters | 0 |
| Compact compute median / p95 | 0.007456 / 0.010752 ms |
| Directional graphics median / p95 | 0.014432 / 0.017632 ms |

At this deliberately small surviving workload, device generation trades about
0.0067 ms of GPU time for a 0.1478 ms (49.2%) reduction in median CPU command
recording. This is a focused architecture checkpoint, not a broad scale admission;
larger and more heterogeneous shadow scenes remain part of M7.7 qualification.

The automatic and direct-reference final-SDR captures are byte-identical with
SHA-256 `fcb0152562a944a04a64a1d7b2dafc2d0ea62bd19196dca81b5e3ffa00a5bd07`.
Vulkan validation emitted no engine errors. The loader skipped an unrelated
Overwolf implicit layer that does not export the loader entry point.

## Verification

- `GpuSceneIndirectTests` freezes the 16-byte shadow candidate word order and ABI
  version alongside the existing 20-byte indexed-command ABI.
- Fence-delayed validation checks real device counts for every cascade/bin range;
  four Debug smoke frames and all 16 Release qualification frames matched exactly.
- The paired Release captures exercise the GPU-scene transform/material shadow
  shaders as well as device compaction and are byte-identical to direct submission.
- Debug and Release builds and full CTest results are recorded after final
  provenance hashes are updated.
