# M7.8 depth receiver producer

Date: 2026-09-30
Status: accepted per-pixel region reconstruction and chained hardware checkpoint;
M7.8 remains active

## Contract and implementation

The RHI defines an explicit depth-source extent, rectangular pixel region, and
forward/reverse zero-to-one depth convention. The CPU reference reconstructs one
packed world-space receiver per region pixel using inverse view-projection and
pixel-center coordinates. Clear, nonfinite, out-of-range depth and unsafe
homogeneous division produce zero sample weight. The region is validated against
the source dimensions and receiver capacity before recording. A full 3840x2160
region is rejected by the current 65,536-receiver workspace; no implicit decimation
or assumption that one center sample covers a whole tile is allowed.

`virtual_shadow_depth_receivers.comp` implements that contract using `texelFetch`
on sampled depth and the existing 32-byte packed receiver records. Its push
constants are 96 bytes (inverse matrix, region, source metadata). The downstream
mark/request ABI stays at v2. `VulkanVirtualShadowDepthReceiverPass` owns its
pipeline, bounded descriptor pool and per-slot sets. The persistent virtual-shadow
owner initializes it against the existing receiver ranges and destroys it before
the buffers. There is no additional tracked buffer/image allocation.

The caller supplies the actual depth image view, nearest sampler, source extent,
and shader-readable image layout at a completed-slot retirement boundary. The
caller also supplies the depth image's producer-to-compute dependency and layout
transition. This pass validates source extent and finite inverse matrix, writes
every region receiver, and publishes its writes to compute consumers. The shared
mark/compact operation consumes those writes in the same command buffer.

## Verification

RTX 4090, Vulkan synchronization validation, Debug and Release:

- A real uploaded D32 image of 67x65 pixels feeds a 65x63 region at origin (1,1).
  Its 4,095 GPU reconstructed receivers match the CPU reference within 1e-6 world
  units and with exact sample weights. The chained output requests and unique,
  output, overflow and dropped-coverage telemetry match exactly.
- Forward and reverse clear-depth handling, NaN, negative and greater-than-one
  depth, translated inverse matrices, perspective homogeneous division, and a
  singular camera are checked. Singular reconstruction after populated work emits
  zero requests, with no stale count.
- Five post-warm-up timestamps for reconstruction plus marking and compaction
  measure 0.067904 ms Debug and 0.067872 ms Release median. Upload/readback and
  initialization are excluded. The fixture's page distribution differs from the
  prior 4,096-input fixture, so these timings do not establish a relative speedup.
- The CPU contract suite passes 14/14 cases, including odd region mapping,
  forward/reverse depth endpoints, singular division, capacity and extent rejection,
  and explicit rejection of full 4K at the current capacity.
- Existing raw mark/compaction correctness and two-slot reuse tests still pass;
  the hardware validation callback reports zero errors.
- Full Debug and Release builds succeed and all 78 repository tests pass in each
  configuration, including the updated M5 current-contract hash gate.

An eight-frame Debug launch with validation and the resource switch exits with
code zero; its error log is empty. Pipeline initialization and cleanup complete,
and tracked virtual-shadow memory remains 93,064,256 bytes (88.753 MiB). The short
1280x720 run averages 5.189012 ms and is lifecycle evidence, not a matched frame
performance comparison. Local evidence is in
`out/m7_8_depth_receiver_profile_20260930.jsonl` and the corresponding launch logs.

## Next integration gate

Continuation: the exact full-view dense page-cell producer has now passed native-4K
hardware parity; see
`docs/performance/M7.8-full-view-page-marking-2026-09-30.md`.
The region-capacity limits below remain valid for this producer; the full-view
pass uses a different representation. Live clip/render-graph publication remains next.

The engine initializes the producer under the existing default-off resource switch.
Normal scene frames do not dispatch it yet. Full-view coverage requires an explicit
strategy for accumulating page demand across bounded pixel regions (or a measured
direct page-marking representation). Simply sampling fewer pixels would miss thin
or small geometry and is not admitted by this checkpoint. Next implement that
coverage/accumulation contract and stable live directional clip publication, then
schedule the depth producer and shared chain in the render graph. Camera changes,
resize, overlapping slots, native-4K frame percentiles and memory must be qualified
before runtime promotion. Deferred opaque depth alone also cannot claim coverage
for forward/transparency receivers; those consumers need an explicit producer or
conventional fallback when virtual sampling is introduced.

Page rasterization, residency mapping/cache updates and virtual lighting samples
remain later M7.8 work. Conventional shadows remain active. The roadmap, context,
M7 plan, frame budget, ADR-0010 and M5 contract hashes record this checkpoint;
no accepted ADR is superseded.
