# M5.4 clustered direct lighting and deferred/forward parity

Accepted 2026-08-09 on the reference RTX 4090/Core i9-14900K system.

## Changed behavior and architecture

Authored directional, point, and spot records are now the only production direct-
light source. The fixed demonstration lights were removed from both canonical
deferred and complex-forward shaders. Both consumers read the exact M5.3 global,
cluster-local, or whole-product fallback list through
`clustered_light_access.glsl`, then call the descriptor-free
`direct_lighting.glsl` evaluator for photometric calibration, source-radius-
bounded inverse-square attenuation, smooth range cutoff, and spot cones.

The shared convention is world-space surface-to-camera `V`, surface-to-light `L`,
and the accepted M2 oriented shading normal. AO affects indirect environment light
only. Emissive is added once, and unlit closures remain independent of scene
lights. Complex forward applies every selected light to its standard base plus
clearcoat, sheen, anisotropy, iridescence, and diffuse-transmission direct terms.
Texture-driven lobe parameters are resolved once per fragment, not once per light.

`direct-lighting` is a scene-linear contribution-isolation view available through
the CLI and both editor view selectors. Cluster telemetry now reports active,
directional, and local light counts in addition to assignment statistics.

## Verification

- Debug and Release builds complete; both configurations pass 65/65 CTests.
- Analytic CPU vectors cover physical scale, directional lux, point candela,
  inverse-square/range/source-radius boundaries, smooth and hard spot cones,
  invalid inputs, and finite BRDF edges. Contract tests prove both consumers use
  the shared access/evaluation includes and contain no fixed production light.
- `glslc` compiles canonical reference/packed and complex opaque/transparent
  variants. Frozen M5.0/M5.2/M5.3 hashes remain historical; the manifest adds a
  named M5.4 supersession for current GLSL and SPIR-V products.
- Vulkan validation is clean for the 512-light complex-forward path and the
  4,096-light overflow/fallback deferred path at 1280x720.
- The mixed directional/point/spot diagnostic produces a non-black direct-only
  capture. The normal 512-light and overflow fallback runs produce deterministic
  direct-only hashes across validation and non-validation executions.
- 4K scRGB final-output smoke is finite in linear Rec.709, uses
  `VK_FORMAT_R16G16B16A16_SFLOAT`, and ranges from 0 to 4.92578125 relative paper
  white.

## Deferred/forward parity

The equivalent standard deferred and alpha-forced-forward fixtures use the same
camera, closure values, light records, and cluster product. At 3840x2160 their
direct-only final-SDR images differ by at most one code value: 0.02894% of pixels
change, and mean linear-luma SSIM is 0.99999648. Scene-linear FP16 comparison is
finite; p99 relative error is 0.1601% and the maximum relative error above a 0.01
signal is 0.2924%. The remaining difference is consistent with FP16 render-target
rounding and the forward blend path, not a different light/BSDF equation.

The stress distribution exposes four global directionals to the visible standard
surface; its locals remain spatially bounded, so the consumer times correctly stay
nearly constant while cluster construction scales. The complex 64-light lab costs
0.002 ms opaque-forward plus 0.005 ms in each occupied transparency bucket. These
are fixture costs, not full-screen overdraw extrapolations. Raw profiles and exact
capture/parity data are indexed by
`docs/performance/data/M5.4-direct-lighting-2026-08-09.json`.

## Remaining risks and deferrals

- M5.5 still owns cooked irradiance, prefiltered GGX radiance, and the BRDF LUT;
  current environment sampling remains the explicitly named approximation.
- M5.6/M5.7 own shadow visibility. M5.4 preserves the light-record shadow slot but
  deliberately evaluates visibility as unshadowed.
- Dense overlapping local-light shading and transparent overdraw need dedicated
  workload fixtures before final M5 capacity claims; M5.4 proves correctness,
  bounded list consumption, fallback safety, and the accepted standard parity gate.
- The M5.0 retained allocation-counter discrepancy remains a milestone-level
  investigation. M5.4 does not claim to resolve it.

No ADR changed. ADR-0007 already owns the shared clustered/photometric direction;
M5.5 is next.
