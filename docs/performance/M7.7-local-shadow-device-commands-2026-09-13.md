# M7.7 local-shadow device commands — 2026-09-13

## Result

Spot-atlas tiles and point-cube faces now build persistent GPU-scene caster
commands on the device. This extends the accepted directional implementation to
all conventional shadow-map consumers: the application submits compact primitive
indices, Vulkan bins compatible geometry once, and each refreshed local-light view
receives a bounded indirect-command/count region. Direct packets remain available
for mixed submissions and explicit fallback.

This is a correctness and architecture checkpoint, not M7.7 completion or broad
performance admission. The follow-up gates CPU oracles out of production local-
light views; reflection-capture visibility, shadow-specific LOD/thresholds,
position/opacity-only streams, and the full heterogeneous quality matrix remain
open. See `docs/performance/M7.7-shadow-command-oracle-gating-2026-09-13.md`.

## Changed behavior and architecture

- Spot and point compaction reuse the backend-neutral 16-byte
  `GpuSceneShadowIndirectCandidate` and the existing 20-byte indexed-command ABI.
  The dense primitive index is carried as indirect `firstInstance`.
- Candidates are binned by physical vertex/index buffers, index type, alpha-mask
  mode, and two-sided state. GPU-scene vertex variants resolve transform and the
  masked material index without copied persistent draw packets.
- One dispatch is recorded for each refreshed spot tile or point face. The compute
  shaders apply the corresponding light-view clip-volume sphere test and emit only
  surviving commands.
- Direct capability, fewer-than-eight-candidate, capacity, invalid-data,
  mixed-packet, and `--reference-direct-gbuffer` paths are explicit and profiled.
- Fence-delayed validation compares every device count against the independent CPU
  oracle and rejects count overflow. Spot and point expose exact commands, bins,
  device/oracle counts, mismatches, overflow, direct fallbacks, and fallback reason.
- The spot and point render-set layouts are now visible to compute and their
  pipeline layouts include the shared GPU-scene descriptor set. Direct pipelines
  preserve the prior push-constant route; indirect variants use the GPU-scene
  vertex stage.
- The spot and point shader uniform declarations were brought back into exact
  agreement with their existing C++ layouts (144 and 464 bytes respectively).
  This removes stale tail offsets before those records gain further consumers.

Initial capacity reserves about 6.03 MiB across the two frames in flight for spot
and point candidate, command, and count storage. Growth is bounded by the shared
1,048,576-command/count work cap; the theoretical combined local-shadow ceiling is
about 100 MiB. Capacity overflow falls back to direct submission rather than
silently allocating beyond that ceiling. Device-local output storage and shared
staging remain future residency work.

The implementation advances ADR-0010's independent light-view visibility and
reuses ADR-0006's persistent GPU-scene direction. It does not change the accepted
conventional-versus-virtual shadow decision.

## Verification and remaining gate

- Runtime smokes exercised real device compaction, indirect graphics, masked
  material lookup, and fence-delayed count validation for both local-light types.
- The paired Release captures exercised the explicit direct reference and matched
  device submission byte-for-byte.
- `M5FixtureContractTests` freezes the local-light implementation, shader/SPIR-V,
  and fixture hashes through an explicit M7.7 supersession record.
- Debug and Release builds succeeded and their full suites pass 77/77. The
  provenance contract test passes in both configurations after freezing the final
  implementation and shader hashes.

The CPU oracle is qualification-only in the follow-up. The warmed multi-frame
heterogeneous directional/spot/point gate is now accepted at native 4K in
`docs/performance/M7.7-heterogeneous-shadow-admission-2026-09-19.md`. Larger
light/primitive storage-residency and capacity sweeps remain open.
