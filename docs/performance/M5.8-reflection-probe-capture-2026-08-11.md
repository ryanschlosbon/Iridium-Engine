# M5.8 Reflection-Probe Capture and Qualification — 2026-08-11

## Status and scope

M5.8 is complete. Iridium now has a stable HDRI Sky, cooked local reflection
probes, deterministic spatial selection, clustered deferred/complex-forward
sampling, six-face scene capture, GPU GGX filtering, complete-only publication,
and an explicit persistent baked-environment workflow. Skybox rendering and the
physically simulated atmosphere remain in their named later slices; M5.8 was only
required to implement the HDRI Sky mode.

## Changed behavior and architecture

- `iridium.component.sky` keeps distinct Skybox, HDRI, and Simulated setting
  groups. HDRI assignment, thumbnail drag/drop, background and lighting intensity,
  rotation, visibility, priority, source cooking, and runtime publication are live.
- `iridium.component.reflection_probe` persists sphere/box influence, blend,
  priority, parallax, capture tier, clip range, sky inclusion, update mode, and an
  optional environment GUID. Runtime residency and diagnostics do not dirty the
  scene document.
- One backend-neutral probe record and one four-probe-per-cluster assignment feed
  both deferred and complex-forward specular IBL. Shading blends the best two local
  probes, supports box projection, and falls back smoothly to the global HDRI.
- Vulkan captures AP1 scene radiance into six private faces, excludes the probe's
  own entity, includes authored direct lights and raster shadows, avoids recursive
  local-probe feedback, and optionally includes the global sky. A 256-sample
  Hammersley GGX compute filter builds the complete roughness mip chain before a
  fence-safe promotion replaces the last-known-good cube.
- Partial and invalidated captures are never sampleable. Scheduling is bounded by
  rendered texels, faces per probe, captures in flight, and realtime cadence.
  Project Settings exposes those budgets plus GGX sample count; component settings
  expose capture resolution and update policy.
- Baked mode performs a layer-major GPU readback, derives exact cube-texel SH9
  diffuse irradiance, reuses the shared split-sum BRDF LUT, and writes a complete
  versioned `iridium.environment` source container under
  `assets/generated/reflection-probes/<scene-guid>/`. Publication is atomic,
  source-controlled UUIDv7 metadata is retained across rebakes, scene/shader
  dependencies and hashes enter the CookKey, and the Asset Browser refreshes after
  success. Baking requires a saved, clean scene so provenance cannot claim a
  different scene than the captured one.
- `.irprobe` is owned by `iridium.environment.probe_capture`. Reimport validates
  the complete artifact and recooks the ordinary source-free environment product;
  assigning the generated asset uses the existing typed environment workflow.

## Performance and memory

The true Release native-4K 1,000-frame steady-state pair records:

| Scope | Global only | One captured local probe | Delta |
|---|---:|---:|---:|
| GPU frame median | 0.525216 ms | 0.533664 ms | +0.008448 ms |
| Probe cluster median | 0.005120 ms | 0.009216 ms | +0.004096 ms |
| Deferred median | 0.111616 ms | 0.111616 ms | 0 |
| Forward opaque median | 0.002048 ms | 0.002048 ms | 0 |
| CPU probe extraction median | 0.0007 ms | 0.0016 ms | +0.0009 ms |

The published 512 cubemap adds 15.999985 MiB requested and 16.03125 MiB committed
live VRAM. A complete 512 capture uses 34.000 MiB of private logical target storage.
Baked capture additionally uses 28.000 MiB of transient mapped readback; neither
readback nor raw/depth staging survives publication.

One full six-face 512 capture plus 256-sample GGX filtering costs **1.234144 ms GPU**
in the retained 4K capture profile, within the 1.5 ms non-RT GI/probe update budget.
The allocation/record frame costs 8.800 ms CPU and the fence-safe publication frame
costs 2.611 ms CPU in this first foundation. Both are explicit update spikes, not
steady cost.

## Remaining risks and deliberate deferrals

- Publication currently waits for all frame fences before descriptor-visible
  promotion. It is correct and measured, but per-frame descriptor retirement should
  replace the 2.611 ms publication spike when capture churn becomes representative.
- Capture rasterization currently iterates the CPU opaque and opaque-complex queues.
  M7's persistent GPU scene should cull and submit capture work without changing the
  capture/product contract.
- General transparent/refractive surfaces are not captured in M5.8 and do not cast
  colored probe radiance. M6 owns transparent material transport; M10/M11 own the
  raster/ray visibility extensions.
- Local probes affect specular IBL. Spatial diffuse GI remains M10's irradiance-
  volume/probe responsibility.
- A captured opaque-complex surface uses the canonical base closure in this slice;
  uncommon layered-lobe capture parity remains a measured follow-up rather than a
  hidden guarantee.

## Roadmap and ADR impact

M5.8 changes to **Complete**. M5 remains In Progress because M5.7 final repeated
timing and M5.9-M5.11 are still open. No ADR was superseded; the implementation
conforms to ADR-0006's shared lighting consumers and ADR-0010's stable Sky/probe,
quality-policy, and high-fidelity evolution contracts.
