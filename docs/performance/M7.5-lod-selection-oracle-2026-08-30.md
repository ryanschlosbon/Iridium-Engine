# M7.5 LOD Products, Selection Oracle, and Qualification Repair

## Status and disposition

M7.5 remains the sole active slice. The CPU selection oracle, typed model LOD
transport, conservative opt-in generator, runtime arena ownership, and cooker
compatibility are implemented. **Live GPU LOD selection is not implemented and
no production triangle reduction or transition-quality acceptance is claimed.**

Generated LODs are **experimental, off by default**. LOD0 remains the runtime
reference. M7.0-M7.4 lit qualification was reopened after discovering that the old
matching captures were entirely black. This supersedes the oracle-only report,
not the accepted architecture records.

## Critical qualification correction

The old PFM SHA-256
`2073f5d985ce3632a1e0fb438fa441e06617ce76623534705f170c5bf423a297`
contains 2,764,800 RGB float samples, all zero. Equal all-visible/one-visible hashes
therefore did not prove fidelity. The fixture parser read `constant_linear_rgb`,
but benchmark startup never applied it without an external environment artifact.
Geometry was rendering into an unlit scene. Normal-debug captures independently
show all three cars.

The correction in `Application.cpp` creates the declared constant environment
through `makeConstantEnvironmentProduct` in `EnvironmentConvolution`, using the
existing typed product, Rec.709-to-AP1 conversion, shared BRDF LUT integration, and
asset-owned upload. Constant radiance, analytic diffuse irradiance
(`pi * radiance`), and prefiltered radiance use 1x1 cube faces; the BRDF LUT is
256x256. This is benchmark fixture construction, not a second light system or
runtime source-HDRI import route. External environment artifacts still take
precedence. Frozen fixture/source sidecars were not rewritten.

Capture/profile metadata now identifies `benchmark-procedural-constant`.
Metadata is emitted after cleanup, so the mode uses retained publication identity,
not already-retired GPU handles. Earlier exploratory lit captures incorrectly
say `neutral-black-fallback` for that reason; `lit-qualified-r2` fixes the label.

`CaptureArtifact` records finite/nonzero RGB pixel counts, per-channel extrema,
and spatial range. Alpha and row padding are excluded. The explicit
`--require-capture-signal` gate rejects constant or nonfinite RGB captures and
leaves no committed artifact on failure. Intentional black diagnostic captures
remain allowed without that option. This is a sanity gate, **not** proof of
correct content, sufficient contrast, lighting response, or image quality.

`--reference-direct-gbuffer` selects direct, unculled GBuffer submission through
the backend-neutral indirect policy. Main GBuffer candidates bypass indirect
compaction and CPU-frustum rejection; complex-forward, transparency, shadow, and
probe consumers retain their existing paths. Automatic remains the default.
The route is recorded in capture/profile quality metadata.

Historical unlit timings apply only to that historical workload. Their percentage
improvements are not qualified lit gains. The new direct reference is the
**current** implementation, not a reconstructed M7.0 executable.

## LOD policy and contracts

- Finest-to-coarsest levels carry monotonic object-space geometric error.
- Projected error is `error * viewportHeight / (2 * tan(fovY / 2) * distanceToBounds)`.
- Select the coarsest level within the pixel-error target, with directional
  hysteresis and a maximum-LOD hero override; zero pins LOD0.
- Missing desired residency searches coarser resident levels, then finer levels.
  No resident level returns a nondrawable result for a caller-owned fail-visible
  proxy/reference path. Invalid projection/error inputs choose the finest
  permitted resident level with `InvalidInputFailVisible`.

`GpuSceneLodTests` covers near/mid/far, both hysteresis directions, hero pinning,
coarser/finer residency fallback, malformed inputs, and no resident level.
Instance-scale-aware device inputs and valid per-view history remain pending.

Model schema 7 adds a typed MDL1 LOD-chain section; readers retain schemas 5/6.
Children are complete primitive records with stable child GUIDs, exact parent
source association, material/transport semantics, bounds, error, and triangle
counts. They are not canonical scene submeshes or new ECS identities. Validation
checks references, unique ownership, monotonic error, reduction, bounds, and
source node/mesh/primitive association. Child RT geometry is absent; accepted LOD0
RT geometry is unchanged.

`ModelRuntimeProduct` and `AssetManager` upload children into asset-owned geometry
arenas. `ModelAsset::subMeshes` remains canonical LOD0; `lodChains` separately
exposes LOD0 and children. Thumbnail and CPU-residency accounting understand that
distinction. Conversion rejects invalid LOD indices even when redundant full
product validation is disabled.

`ModelLodGenerator` ABI 1 is a deterministic endpoint-collapse prototype. It keeps
boundary vertices, source-connected components, manifold/link/Euler/boundary-loop
constraints, winding, and exact surviving attributes. Full source-root displacement
is rounded upward; normal, UV, and color guards limit attribute drift. Unsafe or
nonmanifold candidates retain LOD0. This does not establish screen-space silhouette
or temporal quality by itself.

The 9x9 grid test produces 128 -> 80 -> 48 -> 36 triangles under explicit test
budgets, with errors 1, 2.82843, and 5.65685. A disconnected small island is
preserved. Tests also cover determinism, malformed transport, schema migration,
material association, and cancellation.

## Dense publication revision repair

Adding/removing another primitive could relocate instance primitive ranges or
geometry indices without changing source revisions. A per-frame upload planner
could then skip changed hot bytes.

`GpuScenePublisher` now retains previous hot packed records/revisions in reusable
scratch on changed publication, compares exact packed bytes at each dense index,
and assigns a new packed revision when bytes change. Cold identity tables are not
duplicated. The unchanged-observation fast path remains. This adds bounded CPU
scratch, not persistent VRAM or a shader ABI change.

A regression test reproduced the old failure and now proves relocation updates
across insertion/removal, unchanged transforms remain untouched, and current frame
contexts request no redundant upload. Source-change statistics remain logical
counts; upload counters describe actual bytes.
