# M7.8 frame-slot clip uploads and external-buffer graph tracking

Date: 2026-09-30
Status: upload/lifetime checkpoint; live depth accumulation remains next

## Behavior and interfaces

The experimental live CPU packet is now copied into a frame-slot-owned snapshot
before upload. `shadow.virtual.clip-upload` is the first production graph pass
only when the existing default-off virtual-shadow resource switch is enabled.
It writes the existing slot's persistent working buffer with `vkCmdUpdateBuffer`:
16 packed clip records, 1,536 command-embedded bytes per frame. Active records use
the new checked RHI packing function; inactive records reset to deterministic
defaults with zero resolution/layers. Missing packets reset the block too, while
the slot snapshot records no active levels. CPU contents cannot be overwritten by
a later view/frame before the command consumes them. No staging buffer is needed.

`VulkanRenderGraphExecutor::bindExternalBuffer` adds an opt-in, non-owning contract
for imported buffer resources. Bindings are named, sized, frame-slot-specific,
and reject missing handles, incompatible descriptors, image-only initial access,
undersized buffers, aliasing between resources/slots and rebinding before slot
retirement. Tracking persists access state across slot reuse, and same-access
shader/transfer writes still produce ordering barriers. A tracked resource missing
a binding in the executing slot prevents frame execution. Existing unbound legacy
imports retain their caller-managed synchronization; this is not an implicit
takeover of every external resource. Images are not newly supported here.

The caller still owns the actual Vulkan fence, buffer lifetime, queue ownership
and initial access truth. `onFrameFenceCompleted` permits rebinding; topology
rebuild clears registrations and requires explicit rebinding. The backend binds
both already allocated working sets during graph setup/rebuild. Graph ownership
does not allocate or destroy those buffers. Whole-buffer hazard tracking is
conservative; subrange aliases and buffers shared between concurrently in-flight
slots are not admitted. This upload only defines the clip range, not every byte
of the scratch/request workspace; downstream compute must initialize its outputs
before reading them.

Files/interfaces: RHI `VirtualShadowMap.h/.cpp` checked packing; Vulkan
`VulkanRenderGraphExecutor.h/.cpp` borrowed bindings/access tracking;
`VulkanProductionRenderGraph.h/.cpp` optional imported working-set/upload pass;
`VulkanVertexBackend.h/.cpp` per-slot snapshots, binding and upload; CPU executor,
RHI packing and Vulkan marking tests; latest M5 fingerprint gate.

## Verification

RTX 4090 / i9-14900K, Windows MSVC Debug and Release:

- Full builds succeed; all 78 repository tests pass in each configuration.
- RHI CPU suite: 18/18, including packed matrix, signed origins, level/mip,
  priority/layers/reserved fields and out-of-range address rejection.
- Executor suite: 16/16. The optional graph adds one logical resource/pass and
  no physical allocation slots. Binding tests check missing slots, aliases,
  undersized/missing handles, retirement-scoped rebinding and borrowed cleanup.
- The Vulkan marker qualification now uses the same checked clip packer and
  command-embedded `vkCmdUpdateBuffer` upload. Existing odd two-clip and native-4K
  request/overflow parity remains exact through forward/reverse, invalid depth,
  perspective/singular reconstruction and populated/empty reuse. Hardware checks
  pass with synchronization validation in Debug and Release.
- A twelve-frame 1280x720 Debug engine launch exits zero with an empty validation
  error log. Every actual scene frame reports available=1, four clips, revision=1,
  one caster bound and 1,536 uploaded bytes, across both frame slots and cached
  conventional-shadow frames. The publication scope now includes packing and
  upload/barrier recording: 38.6 us median / 70 us maximum in this tiny fixture.
  Short-run CPU average is 4.467125 ms. These are lifecycle measurements, not a
  matched overhead/performance gate or proof of live GPU request output.
- Tracked storage remains pool 75,759,616 bytes + table 262,144 bytes + working
  sets 17,042,496 bytes = 93,064,256 bytes (88.753 MiB). No GPU buffer/image growth;
  additional CPU slot snapshots are fixed-capacity. Local artifacts:
  `out/m7_8_clip_upload_profile_20260930.jsonl` and matching startup `.log/.err`.

## Remaining gate

No live full-view compute is recorded yet and no virtual shadow is sampled.
Next schedule sampled scene-depth accumulation and compaction with explicit graph
depth dependencies and working-buffer transfer-to-compute access. Add delayed
per-slot request/readback comparison against the exact published CPU packet; the
standalone hardware oracle is not a substitute for that integrated check. Qualify
camera/light changes, disabled/missing packets, resize and overlapping slots at
native 4K. Whole-frame time, large-scene CPU publication cost and forward/transparent
receiver coverage remain open. Page residency/raster/sampling remain later gates.
Only the first selected directional light is currently published. Conventional
shadows and normal/default-off scene output remain unchanged; no visual improvement
is claimed. M7.8 remains active and no accepted ADR is superseded.
