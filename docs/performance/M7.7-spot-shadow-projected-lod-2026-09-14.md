# M7.7 projected spotlight-shadow LOD checkpoint

Date: 2026-09-14  
Status: accepted architecture/correctness checkpoint; default remains LOD0 and
warmed visual/performance admission remains open

## Outcome

Spot-atlas device command construction now selects geometry independently from the
main camera, directional cascades, and point cubes. The selector evaluates each
cooked LOD's conservative object-space error bound through the authored spotlight
projection and the light's atlas-tile resolution. It handles perspective depth,
off-axis bounds, nonuniform scale, shear, and reflection using the same projection-
bound contract as main-view LOD, without borrowing main-camera distance.

The host exposes only the resident finest-to-coarsest prefix compatible with the
already-bound vertex buffer, index buffer, index type, and vertex layout. Invalid
or eye-crossing projections, malformed chains, and missing compatible children
retain LOD0. Spot shadows share `--experimental-shadow-lod-error-texels` and
`--shadow-lod-max-level` with directional and point shadows. Zero threshold or zero
maximum level pins LOD0, which remains the global default.

Validation compares complete per-tile/bin command multisets after the frame fence,
including primitive identity, index count/range, vertex offset, and instance count.
It also reports device/oracle triangle and reduced-command totals. Production does
not repeat GPU-owned spotlight visibility or LOD selection on the CPU.

## Remaining gate

LOD0 remains the global spotlight-shadow default. Admission needs native-4K
threshold sweeps with thin and alpha-clipped silhouettes, narrow and wide cones,
multiple atlas tile sizes, grazing casters, moving lights/casters, atlas-cache
refreshes, and warmed heterogeneous local-light workloads. Virtual shadow maps
remain a separate later architecture.
