# M4.7 Structural Editing and Viewport Evidence - 2026-08-02

## Result

M4.7 meets its structural and viewport gates. Structural mutations are exact,
UUID-backed transactions; hierarchy derivation is iterative and atomic; and the
editor panel now owns a DPI-aware offscreen scene extent independently of the
presentation swapchain. The prior scene target remains aspect-fitted during the
100 ms debounce and on a failed replacement.

The first scale run found quadratic bulk-name generation in subtree duplication:
10,000 identical source names took 10.524 s median and requested 1.56 GiB of
temporary C++ allocations. A per-base next-suffix cursor preserves the same names
while reducing the accepted result to 71.116 ms median and 37.84 MiB: about 148x
faster with 41x less allocation demand.

## Structural benchmark method

- Configuration: MSVC Release on the M4 reference workstation.
- Samples: 30 independent samples per topology/scale.
- Hierarchy: one root with breadth children for rebuild, and a depth chain for
  rebuild-plus-preorder subtree collection.
- Commands: full stable UUID/component capture, execute, exact undo, and exact redo
  for subtree delete and duplicate.
- Allocation scope: C++ global `new`/`new[]` requested bytes.
- Raw data: `data/M4.7-editor-structural-2026-08-02.json`.

## Viewport architecture and live validation

The RHI exposes scene/offscreen extent replacement separately from swapchain
recreation. Vulkan compiles the candidate graph first, waits only the in-flight
frame fences at cutover, rebuilds scene targets/descriptors, and restores the prior
extent if target construction fails. Scene attachments use panel extent; SDR/HDR10
presentation and HDR10 UI composition remain swapchain-sized. Projection uses the
committed scene aspect, while picking and gizmos use the exact aspect-fitted image
rectangle. Minimized and steady matched extents perform no clock query, allocation,
descriptor change, or graph rebuild.

A visible Release session with the Khronos validation layer and the self-contained
cooked reference car repeatedly changed the real window 1600x900 -> 4K -> 1600x900
-> 4K -> 1600x900, then closed normally. It completed 825 measured frames with
zero drops. The final panel target was 1259x648; the graph recorded ten rebuilds
across both swapchain and scene replacements. The two resize events retained by the
bounded 512-frame profile cost 30.911 and 20.805 ms CPU. Graph transient memory was
103.69 MiB committed at the final extent and 758.62 MiB peak during the 4K phase.
The retained mixed session measured 2.349 ms median CPU frame and 0.341 ms median
GPU frame. Raw profile: `out/m4.7-repeated-resize-validation.jsonl`.

The graph unit contract separately proves every GBuffer/depth/scene/output resource
uses scene extent, while swapchain and HDR10 UI composition use presentation extent.
Viewport tests cover wide/tall aspect fit, DPI scaling, minimize, rapid changes,
debounce, retry, clamping, committed projection aspect, picking, and the no-stretch
pending/committed rectangles.

A final post-optimization visible validation run committed exactly one scene-target
replacement (graph rebuild count 1 -> 2), ended at the 483x261 compact panel extent,
and completed 400/400 frames with zero drops or profiler overflow. Raw profile:
`out/m4.7-final-viewport-validation.jsonl`.
