## Behavior and architecture

`GpuSceneLodHistory` in `src/renderer/rhi/GpuSceneLod.{h,cpp}` owns a bounded
stable-primitive-handle-to-history-slot map and independent CPU oracle history.
Sparse logical slots do not force a million-entry GPU allocation. Each lifetime
gets a monotonically increasing 64-bit token, carried as two uint32 fields;
exhaustion throws instead of aliasing old history. The GPU writes only an ordinal,
token and view-frame serial to its own 16-byte history record. No CPU-selected LOD
is uploaded, and canonical primitive geometry/material/owner bindings are unchanged.

`VulkanVertexBackend` owns **one main-opaque history buffer**, shared across
consecutive graphics-queue submissions, not one per rotating frame context. An
explicit compute-write to compute-read/write dependency makes the immediately
preceding frame visible. Buffer growth waits for frame fences and collects pending
command validation before replacing storage/descriptors. Queue fallback or missing
visibility leaves no current-frame record; reappearance starts without stale history.
Duplicate candidate writers are rejected to the existing direct path.

`ViewHistoryContext` is a CPU-side RHI contract passed with `updateCamera`; the
320-byte shader view UBO is unchanged. Main and asset-preview identities differ.
Explicit cuts, scene epochs, primitive generation/rebinding, layout/product edits,
projection/extent/world-unit changes and suspended/recreated views invalidate
history. Primitive dense relocation preserves history. Any packed geometry-table
revision change (including child-only edits or geometry relocation) conservatively
resets the whole main-view table. Material-only edits and ordinary camera motion
do not reset it. Finer-grained geometry invalidation is deferred.

The indirect candidate ABI is **3**, still 32 bytes: its former reserved fields
carry history slot/token. The compaction pass gains storage binding 3 and a
36-byte push-constant block. Device selection and the packed CPU oracle both use
the existing conservative projected-error bound. With 15% hysteresis, coarsening
requires error <= `target * 0.85`; retention/refinement always uses `target`.
Thus a 2-pixel setting never silently becomes 2.3 pixels. Invalid/cold history uses
stateless selection. The earlier scalar FOV/distance prototype is not the runtime
packed-projection selector.

`--gpu-lod-hysteresis-fraction 0..0.5` defaults to 0.15, but only applies when
`--experimental-gpu-lod-error-pixels` enables LOD. Zero supplies a no-margin control
while retaining the same history/readback machinery. Default launches retain
LOD0 and an unused 16-byte descriptor buffer. `--gpu-lod-max-level 0` still pins
LOD0. Shadow, probe, complex-forward, transparency, selection and RT choices remain
independent; this slice adds no LOD selection to those consumers.

The benchmark camera supports deterministic sinusoidal translation, additive to
linear motion, with phase restarted on a cut. The new fixture oscillates Z by six
world units every 24 application frames and cuts at frame 120. Original fixtures
are unchanged. Application metadata records the margin; `ReportM7RunEvidence.ps1`
includes history capacity/valid/reset/change counters.

## Synchronization defect found and repaired

Explicit synchronization validation exposed a **pre-existing** depth-image
WRITE_AFTER_WRITE hazard after `gpu.transparency.sorted.forward`, reproduced with
LOD disabled (`pre-repair-default-sync.log`) as well as enabled
(`final-moving-sync.log`). The forward render pass used depth `STORE` even for a
read-only subpass. That introduces a pass-end depth write behind the render graph's
`DepthRead` contract; ordinary validation alone had not reported it.

`VkForwardRenderPass.{h,cpp}` now uses core Vulkan 1.3 `STORE_OP_NONE` for read-only
depth, preserving the untouched attachment without a store access. Depth-writing
forward remains `STORE`; `DONT_CARE` is not used to discard required depth.
A regression assertion in `Stage3ArchitectureTests` checks both cases. The SDK's
local `vk.xml` identifies `STORE_OP_NONE` as core 1.3; no new device feature or
extension is required. No broader access masks or render-graph ownership changes
were introduced to hide the hazard.

Final runs request `VK_LAYER_VALIDATE_SYNC=1` with validation enabled. Earlier
`VK_LAYER_ENABLES` repro logs also contain a deprecation warning; final runs use
the current setting and have no validation messages. All nine final correctness
runs, including populated transparency and resize, pass this stricter check.

## Remaining gates

GPU history storage is 8,192 bytes for the three-car fixture and 524,288 bytes for
the tested stress fixture; the hard 65,536-command cap bounds it to 1,048,576 bytes
per active owner. A scene larger than the prepared history table gets no history
slots: an eligible smaller opaque subset may select statelessly; oversized indirect
plans retain direct fallback. CPU identity/oracle metadata is likewise bounded,
but its allocator-dependent hash-table overhead is not presented as measured VRAM.

Missing-fine streaming fallback, per-content hero controls, independent shadow/probe
LOD decisions, richer lit material/silhouette and temporal quality admission, and
worthwhile complete-path performance remain open. GPU hot-reload/retirement stress
needs broader runtime coverage beyond the pure lifecycle tests. OS minimize/restore
is reset in code and covered by reset unit tests, not yet an interactive lifecycle
qualification. Projection changes reset conservatively; future jittered views need
an explicit unjittered history/projection contract. The small conservative cooker
yield and legacy cross-configuration texture CookKey issue remain unchanged.

No accepted ADR or frame-budget target is changed; M7.6 and later are not started.
