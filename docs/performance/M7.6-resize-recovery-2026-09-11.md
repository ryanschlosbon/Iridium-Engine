# M7.6 depth-pyramid resize recovery — 2026-09-11

## Result

The new `--validate-depth-pyramid-resize` harness performs three real scene-target
extent reallocations through the RHI between measured frames: 1280x720 -> 960x540,
then 1600x900, then back to 1280x720. It spaces requests three frames apart so each
replacement proves both fail-visible invalidation and stable-history recovery.
This exercises resource retirement, render-graph rebuild, descriptor rebinding,
history generation reset, and fused-pipeline fallback; it is not an output-
transport-only topology switch.

The Release synchronization-validation run reports three requests, three
successes, zero failures, three render-graph rebuilds, and restoration of the
original extent. Each resize frame rejects history as `HistoryUnavailable` and
retains all 404 opaque commands. The next frame is eligible and has exact device/
oracle command counts:

- 960x540: 340 commands after 64 rejections;
- 1600x900: 346 commands after 58 rejections;
- restored 1280x720: 331 commands after 73 rejections.

All eligible frames report zero invalid results, unsafe mismatches, bin mismatches,
indirect overflow, and dropped profiler counters. The profiler remains bounded;
its fixed capacity is now 272 counters to accommodate per-reason occlusion and
resize qualification telemetry in the same feature-heavy frame.

Evidence:

- `out/benchmarks/m7.6/occlusion-rejection-fused-resize-validation.jsonl`

## Decision and remaining work

The scene-target resize correctness gap is closed for the experimental route.
Moving geometry, disocclusion, subpixel safeguards, explicit depth-content changes,
camera cuts, off-frustum work, and transport rebuilds now all have live exact
evidence. Duplicate history/build storage is subsequently removed in
`docs/performance/M7.6-in-place-view-history-2026-09-11.md`. Production rejection
remains off until a controlled large-occluded-workload performance gate
demonstrates a scalable win.

Debug and Release builds pass, and both portable suites pass 77/77. No accepted ADR
changed. M7.6 remains active.
