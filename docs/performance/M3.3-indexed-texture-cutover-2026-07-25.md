# M3.3 Indexed Texture Cutover Evidence - 2026-07-25

## Decision

The Vulkan production path uses separate, variable-count, update-after-bind sets for
sampled image views and samplers plus a per-frame material storage buffer. The former
per-material combined-image-sampler path remains available only through
`--material-descriptors compatibility` for bounded A/B work.

The cutover and refreshed fence-scoped growth implementation pass the approved
matched performance gate. Production DirectXTex cooking, physical table growth,
tracked captures, and live retirement/reuse validation are complete; M3.3 was
accepted on 2026-07-26.

## Correctness and compatibility

The four M2 GPU material fixtures were captured at 3840x2160 in both indexed and
compatibility modes. The scene-linear PFM outputs are byte-identical:

| Fixture | SHA-256 |
| --- | --- |
| `material_gpu_lab_v1` | `9e461df4d273c5d0fb7c8874f2e5380ce8642d85600c8682d524a2678a96e3d1` |
| `standard_shading_opaque_v1` | `53dd12b0bdefe8cd246d8864a099a5360d45bd9a061765273bf13a01e7deabf6` |
| `standard_shading_forward_v1` | `db551276c6cfbe86faa18daf390191922eae8c8522b1c8ae16fdbd59085539b7` |
| `complex_closure_lab_v1` | `164c60e7f8e00f7f94ac071d5e500540481b20a3296d94085d816cae94464462` |

The comparison exposed and corrected a defect in the retained deferred
compatibility shader. Its legacy binding names treated canonical semantic slot 1
as normal and slot 2 as metallic/roughness, while the CPU descriptor writer and
packed material contract use slot 1 for metallic/roughness and slot 2 for normal.
Occlusion, emissive, diffuse/specular-glossiness, and transmission had the same
legacy-order problem. The compatibility shader now consumes the canonical
21-semantic ordering used by the indexed and complex-forward paths.

Release Vulkan validation was clean at 3840x2160 for:

- `material_lab_v1`, `transparency_v1`, and `opaque_emissive_v1`;
- `material_gpu_lab_v1`, `standard_shading_opaque_v1`,
  `standard_shading_forward_v1`, and `complex_closure_lab_v1`;
- the SDR, scRGB, and HDR10 output paths;
- indexed and compatibility descriptor modes.

Debug and Release both pass all 23 CTests.

The pinned DirectXTex importer now performs production source decode in `parse`,
semantic mip processing and BC7/BC5/BC4/BC6H compression in `cook`, and emits
texture container schema 1. Importer version `20260508` and pinned commit
`4feb3e11a020f35b796fc769a74216a555d4f5ef` participate in tool dependency and cook
identity. Repeated source-to-artifact cooks are byte-identical; a complete
source/sidecar/cooker/DDC test verifies the next request is a validated cache hit.

The tracked embedded-image texture grid and optional local sample car were captured
at 3840x2160 in Final, Depth, Base Color, Normal, Material ID, Closure Class, and
wireframe. Indexed and compatibility sample-car captures are byte-identical in all
seven views. The corrected normal semantic and forward contribution intentionally
supersede the affected pre-M3 normal/wireframe images; both descriptor modes agree
on the corrected output. The accepted material-84 scene-linear gates remain exact:

- Depth: `686e0408ab608446cf5a740c1fb05268fdfa9eb7255465a9d4d5c8ae146f16db`;
- Material ID: `496d487c83664d3f8b9dd3a20f8f5c210237155726e3e34f72432402880df996`.

The sample car has 81 resident textures. It forces each physical table from 64 to
128 entries while the immutable layouts retain a 65,535-entry capability/packing
bound. Replacement is per frame slot after its fence, so pipelines remain layout
compatible and no device wait enters a normal frame. A separate 4K Vulkan-validation
churn retires index 81 to fallback, proves it is not reused immediately, and proves
it is reclaimed after its owning frame fence. That diagnostic declares a 1 MiB
per-frame M3.3 upload budget and records `cpu.texture.upload_schedule` at
0.1902 ms median / 0.2041 ms p99, passing the 0.25 ms scheduling gate. Larger
streaming budgets and background publication remain owned by M3.5.

## Matched Release performance gate

Hardware and run contract:

- RTX 4090 / Core i9-14900K reference system;
- visible borderless 3840x2160, validation off, canonical reference GBuffer;
- `material_lab_v1`, warm steady state;
- 500 warm-up frames and 10,000 measured frames;
- five independent indexed and five independent compatibility runs;
- delayed Vulkan timestamps, Release build.

Each row reports the per-run median GPU time. The gate applies to GBuffer plus
deferred lighting and permits at most the larger of 0.02 ms or 10% regression.

0.8629 ms indexed and 0.9522 ms compatibility.
