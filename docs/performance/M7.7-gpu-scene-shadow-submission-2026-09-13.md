# M7.7 GPU-scene shadow submission — 2026-09-13

## Result

Conventional directional, spot, and point shadow passes now consume the persistent
GPU-scene publication through compact primitive references. The application no
longer copies each persistent opaque primitive into a 240-byte `DrawPacket` shadow
queue. Producers that cannot enter the GPU scene retain a separate direct-packet
fallback.

This is not M7.7 completion. A same-day follow-up now builds directional-cascade
commands on the device; spot and point passes still resolve the compact references
from the frame-context CPU mirror and record direct indexed draws. Shadow-specific
LOD/geometry streams, independent reflection-capture visibility, and the complete
quality matrix remain open. See
`docs/performance/M7.7-directional-shadow-device-commands-2026-09-13.md`.

## Changed behavior and architecture

- `ShadowCasterSubmission` is backend-neutral and separates frame-local dense
  GPU-scene primitive indices from compatibility packets. No Vulkan handle crosses
  the RHI boundary.
- Primitive and instance consumer masks must both advertise
  `GpuSceneConsumerShadow`; disabled instances and invalid primitive bindings are
  excluded. The consumer-list builder does not accept main-camera visibility, so
  off-camera casters remain eligible.
- GPU-scene publication now places shadow and probe consumer bits on each opaque or
  masked primitive as well as its owning instance. Previously those bits existed
  only on the instance record, which was insufficient for per-primitive consumer
  extraction.
- Directional, spot, and point rendering resolve the compact list once per active
  pass into retained backend scratch. Per-cascade/tile/face visibility then operates
  on that resolved set. This avoids repeated reference decoding without restoring
  an application-owned packet copy.
- Directional and local cache identities hash the resolved GPU-scene transform,
  geometry, material, pipeline, draw range, and backend material revision. The
  affected-bounds directional invalidation contract is preserved.
- Exact counters expose `shadow.casters.gpu_scene`,
  `shadow.casters.direct_fallback`, and `shadow.casters.submission_bytes`.

The implementation advances ADR-0010's independent light-view visibility path and
uses the existing M7 GPU-scene identity/publication system. It does not alter the
accepted conventional-versus-virtual shadow decision.

## Qualification evidence

The validation-enabled Release `m7_directional_shadow_caster_culling_v1` run used
the source-free schema-7 contact artifact, 8 warmup frames, 16 measured frames,
1280x720, and 35 m directional coverage. Every measured frame reported:

| Metric | Value |
|---|---:|
| GPU-scene caster references | 48 |
| Direct fallback packets | 0 |
| Application submission payload | 192 bytes |
| Equivalent copied `DrawPacket` payload | 11,520 bytes |
| Submission-payload reduction | 98.333% |
| Refreshed caster-cascade tests | 96 |
| Conservatively culled pairs | 66 |
| Directional draws recorded | 30 |
| Directional-shadow GPU median | 0.015200 ms |
| Directional-shadow CPU record median | 0.318700 ms |
| Dropped profile frames | 0 |

Only two affected cascades refresh per moving frame after the earlier per-cascade
cache-revision work, hence 96 rather than 192 tests. The retained 30 draws are not
compared as a timing admission against the older four-cascade run.

The grazing correctness control produced final-SDR SHA-256
`fb4d56d6e58ab6907369fb90f55031582d20367fe9fb57bd89437f187ba70f4f`,
byte-identical to the accepted receiver-bias and caster-visibility captures.

A validation-enabled first-frame local-light smoke run used the lit oblique fixture
with the same source-free contact artifact. It submitted 9 GPU-scene caster
references and zero fallback packets, refreshed one spot tile, tested all 9
casters, and recorded 9 spot-shadow draws. The point path shares the same resolved
submission loop but that fixture intentionally disables point-light shadowing.

Vulkan validation emitted no engine errors. The loader skipped an unrelated
Overwolf implicit layer that does not export the Vulkan loader entry point.

## Verification

- `GpuSceneTests` covers consumer filtering, disabled instances, invalid bindings,
  and camera-independent shadow collection.
- The source-free moving-grid and grazing-contact fixtures exercise the real Vulkan
  path with zero direct fallback packets.
- Debug and Release builds and full CTest results are recorded after final
  provenance hashes are updated.
