# M7.6 live scene-depth build — 2026-09-09

## Scope

Completed the opt-in **build-only** integration of the qualified farthest-depth
shader. `--experimental-depth-pyramid` defaults off and does not enable any
occlusion rejection. M7.6 remains active; no accepted ADR is changed.

`VulkanDepthPyramid` owns the compute pipeline, nearest sampler, single-mip views
and descriptor sets. The production render graph owns a non-transient R32Float
full mip chain per frame context. The pass runs after GBuffer and opaque-forward
depth writes, before sorted transparency. It uses the engine's current forward
depth convention (maximum reduction), not the nearest-depth refraction pyramid.
The existing qualified shader still supports reverse depth in the hardware test.

The build pass declares storage read/write; the following ready pass transitions
the chain to sampled-read state without a dispatch. This declares sampled image
usage for the build's inter-mip sampled descriptors as well. An initial live run
caught missing sampled usage (VUID 00337); this is fixed and covered by graph tests.
Single-mip write-to-read barriers order each reduction. Supported dimensions are
bounded to 65535 per axis to keep integer reduction products representable.

Descriptors/views are cleared before graph replacement, then rebuilt against the
new frame targets at existing all-frame retirement boundaries. Cleanup owns no
graph image destruction. There is a separate `gpu.depth.occlusion-pyramid` timing
range and dispatches contribute to the existing frame counter.

Interfaces/files: ApplicationConfig/parser/help, Application backend configuration,
RHI RenderBackendConfig, VulkanProductionRenderGraph overloads, VulkanVertexBackend
lifecycle/recording, new VulkanDepthPyramid files, CMake, graph and CLI tests.

measured frames per process, native 4K, same frozen three-instance artifact:

| --- | ---: | ---: |

| GPU frame p95 | 1.198624 ms | 1.693024 ms |
| Pyramid GPU median / p95 | absent | 0.111616 / 0.111616 ms |
| Requested live bytes | 2,345,833,398 | 2,434,305,838 |
| Committed live bytes | 2,428,111,008 | 2,519,705,760 |
| Live allocation count | 178 | 180 |

The two chains request 88,472,440 bytes and commit 91,594,752 bytes (87.3515625 MiB).
This is an overhead sanity check, not an acceptance benchmark or a speedup claim;
there is no rejected geometry yet. Validation, short samples and process-order
noise disqualify these timings from production performance admission.

The first measurement exposed missing R32Float handling in the allocator's
requested-byte estimator. Committed memory was accurate but requested memory
omitted both the new chain and existing R32 refraction chains. Added the four-byte
format case with compile-time single/odd-mip checks, then repeated both profiles.
This fixes telemetry only; no allocation or rendering behavior changed. Other
unsupported-format accounting is outside this slice.
