# M5.7 Multi-Directional Shadows and Resize Regression — 2026-08-11

Status: implementation/verification checkpoint, not M5.7 acceptance. Spot and point
Vulkan rendering, sampling, captures, and final multi-process measurements remain.

## Behavior and architecture

- Swapchain recreation now retires clustered-lighting descriptor sets before their
  render-graph buffers are destroyed and rebinds them after graph reconstruction.
  This matches the existing scene-render-extent lifecycle.
- Two directional lights can own independent four-cascade maps in one persistent
  eight-layer D32 array. Lighting resolves the matching owner from each light slot,
  samples that projection, applies visibility only to that light's radiance, and
  then accumulates. Deferred and complex-forward use the same GLSL function.
- Selection remains deterministic: priority descending, stable UUID ascending.
  Lower-ranked valid shadow lights remain lit and publish an omission count.
- Backend-neutral `ProjectShadowSettings` owns resolution, owner count, update
  budget, split lambda, guard band, and depth padding. Live policy is exposed in
  Project Settings; resolution is an explicit 512/1024/2048/4096 startup allocation.
  Per-light enable, quality, and priority remain persisted Light component fields.
- ADR-0009 supersedes only ADR-0008's one-owner capacity. ADR-0008 cache validity,
  no-incompatible-stale-map, and visibility-one fallback remain authoritative.

## Bloom audit

Bloom is not implemented. The production graph declares `bloom-hook`, but the Vulkan
backend deliberately skips it; there is no bloom image, dispatch, sampling, or user
setting. Apparent glow/brightness in the current output comes from scene intensity,
exposure/output mapping, and the display. Bloom remains downstream work. When it is
implemented, its settings must live in a backend-neutral post-process policy/volume
record and feed the scene-linear pre-output pass rather than reside in Vulkan or the
Project Settings widget.

## Remaining risk and deferred work

- The default two-owner allocation doubles directional VRAM from the accepted M5.6
  64 MiB to 128 MiB. Resolution is configurable, but runtime reallocation still
  requires renderer restart.
- Capture metadata currently publishes the selected owner count plus primary owner;
  a full owner/allocation list belongs with the unified M5.7 local-shadow schema.
- Spot/point GPU resources, caster culling, seam-safe sampling, and visual/performance
  acceptance remain M5.7 work.
