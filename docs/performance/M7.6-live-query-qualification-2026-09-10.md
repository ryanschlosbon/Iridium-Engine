# M7.6 live occlusion-query qualification — 2026-09-10

## Result

The proven depth-pyramid query shader is now connected to the live GPU-scene
indirect path behind `--experimental-depth-occlusion-query`. The option implies
`--experimental-depth-pyramid`, allocates two host-visible 32-byte record streams
per frame context, and records a queue-ordered query dispatch before opaque draw
consumption. It remains qualification-only: every compacted frustum-visible command
is submitted regardless of the query verdict.

The renderer now computes the complete depth-content owner before opaque
compaction. Both deferred opaque and depth-writing forward queues contribute to the
revision, so a glass/depth-writing-forward change cannot leave an apparently valid
opaque-only history. The consumer uses the latest scheduled same-view history only
when its global submission serial is exactly adjacent. Fence-published metadata
remains the separate CPU-readback contract.

For each CPU-frustum-visible deferred candidate, the qualification path transforms
all eight local-bound corners, constructs a conservative history-view rectangle,
and sends only eligible projections to the device. Near-plane, outside-view,
small-bound, invalid-bound, and other projection failures remain visible. Results
are read only after the frame-slot fence and checked for the ABI version, tested
state, bounded one-to-four texel footprint, finite normalized farthest depth, and
boolean verdict. Any malformed device result fails the validation run.

New delayed counters are:

- `depth.occlusion.query.requested`
- `depth.occlusion.query.projected`
- `depth.occlusion.query.tested`
- `depth.occlusion.query.would_reject`
- `depth.occlusion.query.invalid_results`
- `depth.occlusion.query.projection_fail_visible`

The existing `depth.occlusion.history_eligible` and
`depth.occlusion.history_rejection` counters expose history admission. The GPU work
is timed as `gpu.depth.occlusion-query`. Capture and CPU-profile quality provenance
now records both depth-pyramid and occlusion-query enablement explicitly.

## Live evidence

A Release 1280x720 frozen `m7_three_dense_all_visible_v1` run completed 4 warmup
and 12 measured frames with Vulkan synchronization validation. Every measured frame
reported:

- history eligible, rejection reason `None`;
- 303 requested deferred-opaque candidates;
- 288 projected and tested queries;
- 15 projection failures retained as visible;
- 34 device `would_reject` verdicts;
- zero invalid device results.

The full frame still draws all 303 commands. The results are stable evidence that
the previous-frame history, projection, descriptor, dispatch, fence, and readback
chain is live; they are not production-culling evidence by themselves.

## Frozen temporal fixture

`assets/m7-occlusion-temporal-manifest.v1.json` freezes revision 1 of
`m7_occlusion_depth_stack_v1` (manifest SHA-256
`ae9d6793a596a75c9e63df4abe113156248c545262fe7ddd5b9d46e50fede50f`). Four dense
assets overlap along the view axis for frames 0-11. Application frame 12 cuts to
an oblique camera that exposes previously hidden surfaces. The historical M7
baseline manifest is unchanged, so its recorded hashes remain reproducible.

A 32-frame Release synchronization-validation run proves the intended temporal
gating:

- frame 1 rejects history as unavailable and submits everything;
- frames 2-12 each test 379 of 404 requested candidates, retain 25 projection

- frame 13 (application cut frame 12) rejects history as `CameraCut` and submits
  everything;
- frames 14-32 each test 395 of 404 requested candidates, retain 9 projection
  failures, and report 48 `would_reject`;
- every dispatched result is valid and no Vulkan validation error occurs.

Pyramid-only and query-qualification final-SDR captures of measured cut frame 12
are byte-identical, both SHA-256
`b41f30a594e06299225f227cc4d9acd05e126f45fdc7541ad5605d8402e087ea`.
That identity is expected because qualification does not yet alter commands.

A separate 30-frame synchronized run switches scRGB to HDR10 to SDR while the query
path is active. All three graph/output rebuilds complete. History is unavailable for
the first two measured frames after the rebuild sequence, then 28 consecutive frames
return to the same 288 tested / 34 `would_reject` / zero-invalid result. This covers
descriptor reallocation, history-generation reset, and cleanup without weakening the
fail-visible rule.

## Remaining M7.6 work

No default allocation or production draw rejection changed. Before admission, the
query construction and verdict must move into the existing device compaction flow,
the temporary frame build plus persistent-history copy topology must be collapsed,
and the now-runnable temporal fixture must be rerun with command rejection to prove
actual savings, disocclusion, camera-cut/reset, resize, and small-object behavior
without missing geometry or flicker. Repeated native-4K performance and image
evidence then decides whether the route is production, workload-selectable,
experimental, or rejected.

No ADR changed.
