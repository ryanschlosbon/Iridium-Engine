# M7.5 Per-Content Hero LOD Policy — 2026-08-31

## Outcome

M7.5 now has a persistent per-mesh maximum LOD ordinal. `0` pins hero content to
full-detail LOD0; the default `15` permits every level supported by the current
GPU-scene ABI. The device selector uses the minimum of this content ceiling, the
project/device `--gpu-lod-max-level` policy, and the host-validated compatible
resident prefix. Experimental device LOD remains opt-in and default launches still
render LOD0.

This closes the M7.5 **authoring/control** gap. It does not claim production LOD
admission, physical missing-fine streaming, or independent shadow/probe LOD.

## Architecture and behavior

- `MeshComponent` source and cooked schemas advance to version 2 with
  `maximumLodLevel` / `maximum_lod_level`, constrained to `[0, 15]`.
- Source version 1 migrates deterministically to `15`. Cooked version 1 is rejected
  by the existing exact-version runtime contract and must be recooked.
- The Mesh Inspector exposes **Maximum LOD Level** through the existing transaction
  service. Apply, undo, redo, source capture, cooking, and source-free loading all
  preserve the value.
- GPU-scene ABI 2 packs the four-bit maximum ordinal into instance state-flag bits
  8–11 without increasing the 80-byte instance record. The flag survives both the
  backend-neutral reference packer and persistent publisher.
- Changing only this value revises only the instance record; transform, primitive,
  and shared-geometry records remain unchanged.
- The Vulkan indirect preparation stage clamps the compatible resident LOD prefix
  by the authored ceiling before constructing the device candidate. No shader ABI,
  indirect-command size, or `DrawPacket` size changes.

Historical M4/M5 fixture hashes remain intact. New `m7_5Supersession` entries record
the intentional runtime-manifest/cook/artifact changes.

## Remaining work and risk

- M7.5 still needs worthwhile production-path performance and richer visual
  admission; the existing experimental route remains slower in its accepted static
  comparison.
- Missing-fine physical residency and streaming fallback remain M7.9 work. The
  current host prefix is resident and buffer-compatible, not an asynchronous
  residency system.
- Directional/spot/point shadow and reflection-capture LOD decisions remain
  independent M7.7 consumers. The per-content ceiling is published on the shared
  instance record so those consumers can honor it without a second authoring model.
- ABI 2 currently supports sixteen ordinals. Expanding that limit requires a new
  explicit ABI decision rather than silently consuming adjacent state bits.
- M7.7 conventional-shadow reconstruction, directional coverage/cascade density,
  and receiver-bias hardening are recorded in ADR-0010 and the milestone/fidelity
  contracts before M7.8 VirSM evaluation. Temporal shadow accumulation remains M9.

ADR-0014 is refined for GPU-scene ABI 2; no ADR is superseded. M7.5 remains the sole
active milestone slice.
