## Protocol

- Release, MSVC 19.51.36252.0, 32 logical processors.
- Each scale ran in an independent process with one warmup and five measured
  samples.
- Deterministic fixtures contain one backend-neutral fixed-width component per
  entity. The current-schema source document and staging world are constructed
  outside timed compile work so the compile result measures deterministic scene
  compilation and artifact serialization rather than M4.3 JSON parsing.
- `cold_source_compile` compiles a staged authoring world into the exact cooked
  sections and serializes the M3 artifact envelope. `warm_ddc_read` reads the
  published artifact through `LocalDerivedDataCache`. `artifact_read_validate`
  validates the artifact envelope, hashes, type/schema, target, CookKey, section
  directory, registry manifest, and structural ranges without constructing ECS
  state. `cpu_ready_stage` additionally constructs and validates a complete staged
  runtime world. `active_scene_commit` measures only the active/staged world swap;
  setup and old-world retirement are excluded.
- Allocation bytes are aggregate global C++ `new`/`new[]` requested traffic.
  Working/private deltas are process samples while each result is alive. Peak
  working set is process-wide and monotonic, not an object-size measurement.

## Comparison and interpretation

M4.3's 100k strict JSON parse was 18,627.488 ms median and its staged source world
was 367.181 ms median. M4.4 does not time JSON parsing in the compiler benchmark,
because source parsing is an editor/cook-host concern, but the production runtime
path reads, validates, and builds the same scale from a 5.34 MiB cooked artifact in
approximately 204.7 ms median when the independently measured DDC read and CPU-ready
stage are summed. Direct already-resident artifact validation plus staging is about
204.7 ms as well because both measurements intentionally include independent
artifact decoding. These components are not a single end-to-end trace and their
sum is illustrative rather than a new percentile distribution.

The important scale risk is the 100k CPU-ready p95 of 254.994 ms despite a stable
148.105 ms median. Construction also performs roughly eight allocations per entity.
This work is outside the frame loop and active-world commit remains sub-microsecond,
but later runtime streaming/job work should reduce the allocation count and prevent
large staging work from monopolizing one thread. M4.4 acceptance does not claim a
frame-time budget for pathological 100k one-shot scene loads.

The benchmark's warm DDC row includes reading and copying the full artifact, not
only the M3 key lookup. It should therefore not be compared directly with M3's
0.043 ms DDC lookup p95. No GPU resource, render graph, shader, image, steady frame,
or VRAM contract changed, so no visual, GPU-timing, or persistent-VRAM delta is
claimed.
