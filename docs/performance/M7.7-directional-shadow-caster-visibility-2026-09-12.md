# M7.7 directional-shadow caster visibility — 2026-09-12

## Result

The third accepted M7.7 conventional-shadow slice gives every refreshed
directional cascade its own conservative caster set. Camera visibility no longer
determines shadow eligibility, while casters that cannot intersect a cascade are
removed before Vulkan resource lookup, pipeline selection, and draw recording.

This is not M7.7 completion. GPU-scene/indirect shadow submission, shadow-specific
LOD, position-only streams, independent local/probe visibility, and the remaining
quality matrix are still open.

## Changed behavior and architecture

- The application continues to build the shadow source queue before main-view
  frustum/Hi-Z compaction. A camera-invisible caster can therefore remain eligible
  for a light view.
- `directionalShadowCasterCascadeMask` intersects each packet's world-space bounds
  sphere with only the cascades scheduled for refresh. The test uses the shared
  Vulkan `x/y = [-w,+w]`, `z = [0,w]` clip-volume contract already used by spot
  tiles and point faces.
- Unknown, zero-populated, non-finite, or degenerate bounds remain fail-visible.
  The optimization cannot discard an unbounded legacy/runtime-authored caster.
- A reusable byte-per-packet scratch mask avoids repeating four plane suites in
  the cascade draw loops. It is retained by the backend rather than allocated per
  draw.
- Exact counters report `shadow.directional.casters.tested` and
  `shadow.directional.casters.culled` in caster-cascade pairs. Recorded directional
  draws expose the surviving work independently.
- A same-day follow-up replaces the global caster cache identity with four
  backend-owned revisions derived from the same conservative membership. Caster
  content and membership changes now invalidate only affected cascades.

The implementation follows ADR-0010's independent light-view visibility and
conventional-shadow optimization direction. It does not change that decision, so
no superseding ADR is required.

## Qualification evidence

`m7_directional_shadow_caster_culling_v1` is a source-free moving 16-instance
fixture. Its 48 source primitives are spaced across 180 m while directional
coverage remains 35 m, deliberately presenting each cascade with relevant and
irrelevant casters every frame. The existing schema-7 cooked contact artifact is
used without loading the source model at runtime.

The validation-enabled Release run used 8 warmup and 16 measured frames at
1280x720. Every measured frame reported exactly:

| Metric | Value |
|---|---:|
| Caster-cascade pairs tested | 192 |
| Pairs conservatively culled | 162 |
| Pairs retained / draws recorded | 30 |
| Pair rejection | 84.375% |
| Directional-shadow GPU median | 0.032448 ms |
| Directional-shadow CPU record median | 0.204650 ms |
| Dropped profile frames | 0 |

This run establishes bounded surviving work and real Vulkan draw removal; it is
not presented as a matched before/after timing admission. The established grazing
contact fixture is the correctness control. Its post-change final-SDR SHA-256 is
`fb4d56d6e58ab6907369fb90f55031582d20367fe9fb57bd89437f187ba70f4f`,
byte-identical to the accepted receiver-bias image. All 12 valid caster-cascade
pairs remain present there.

## Affected-bounds cache follow-up

`m7_directional_shadow_affected_bounds_v1` holds a 16-instance scene static,
populates all cascades on frame 1, then moves instance 0 from x=-90 m to x=0 m on
frame 11. Frames 2-10 report four cache hits and no shadow work. The membership
transition invalidates and refreshes exactly two cascades, leaving two cached and
sampleable; frame 12 returns to four cache hits. A global caster revision would
have refreshed all four cascades. Exact telemetry is recorded in
`out/benchmarks/m7.7/profiles/directional-affected-bounds-v1.jsonl`.
