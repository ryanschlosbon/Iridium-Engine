- Release, MSVC 19.51.36252.0, Core i9-14900K, RTX 4090, driver 610.74.
- Native 3840x2160, reference GBuffer, cooked-only model loading, validation off,
  500 warmups and 10,000 measured frames in five independent processes per fixture.

  50 warmups, 300 frames, capture at measured frame 299.

## Frozen contracts and known defects

`LightingReferenceTests` freezes high-precision photometric conversion, range,
inverse-square, radius guard, spot-cone, Lambertian, split-sum IBL, BSDF finiteness,
and invalid-input vectors. `M5FixtureContractTests` freezes the current v1
directional/point/spot source, canonical and cooked hashes, byte-identical repeated
cooks, source-free runtime loading, fixture counts, capture domains, and the M5
stress/overflow recipes.

The renderer still ignores persisted Light components, uses fixed direct-light
values independently in deferred and forward shaders, samples a raw equirectangular
environment, and parses a source HDR image at production startup. These are explicit
M5 defects, not physical references.

One baseline discrepancy remains visible: the last 512 retained frames from each
sample-car process report one 8-byte C++ allocation at median and p99, with a maximum
of three calls/88 bytes. M4 reported zero. M5.0 changed no production source, and
the current profile summary does not aggregate counter distributions over all
10,000 frames, so this is an investigation and profiler-coverage gate before M5 can
claim zero steady allocation; it is not silently attributed to lighting.

## Roadmap and architecture status

M5.0 adds evidence and test/reference contracts only. No ADR is accepted or
superseded, no ROADMAP status changes, and M5.1 has not started.
