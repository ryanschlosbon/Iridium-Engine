# M7.8 page raster regions and conservative caster volumes

Date: 2026-10-01
Status: raster-projection prerequisite; not page-rendering admission

## Changed contract

RHI `VirtualShadowMap.h/.cpp` now owns the checked physical atlas layout and the
directional pending-page crop. `buildVirtualShadowAtlasLayout` derives row-major
physical tile locations from page interior, border, capacity and device dimension
limit. `VulkanVirtualShadowResources` uses this same layout instead of a private
duplicate square-root/dimension calculation. Its existing allocation is unchanged:
1024 pages, 128 interior texels, 4 border texels -> 136-texel tiles in a 4352-square
atlas. The checked layout is published in the backend resource info.

`buildDirectionalVirtualShadowPageRasterRegion` accepts only current pending-raster
work. It rejects wrong owner/projection/revision/level/mip, stale requested caster
layers, invalid physical slots, invalid layer masks, out-of-window signed world
pages, incoherent layouts and nonfinite cropped matrices. An unrequested dynamic
revision does not invalidate static-only work. Cached-sampleable or missing mappings
are not raster jobs. There is no implicit completion or page-cache publication.

The crop covers the page interior plus the full border. Its homogeneous matrix
rescales XY about the page center while preserving Z/W; clipmap origin scrolling
does not change the resulting world-space page volume. The returned viewport/
scissor is the complete physical tile. Interior page UV maps to atlas UV starting
at tile origin plus border, rather than sampling across neighboring tiles. Filtering
must remain within the rasterized border; this helper does not admit an unbounded
filter or itself implement filtering.

`virtualShadowPageMayContainCaster` is a conservative forward-zero-to-one sphere/
page-volume oracle. Border-only casters and spheres intersecting a plane stay
eligible. Negative/nonfinite radius, nonfinite center, singular/unsafe planes and
arithmetic overflow fail visible. Every plane is validated before rejecting any
caster. Alpha cutoff, double-sided semantics, geometry residency, indirect command
generation and independent static/dynamic physical storage remain renderer duties.

These are backend-neutral raster geometry contracts, not a change to packed GPU
marking ABI v2 or source/cooked asset serialization. No new GPU resource, shader,
runtime page draw or sampling path is introduced. The existing raw GPU projection
test now derives its coarsest level from the supplied stack instead of assuming
two levels; that qualification-harness correction does not alter production code.

## Verification

- Debug/Release builds succeed. The RHI suite expands from 18 to 20 tests and
  passes in both configurations. Cases cover atlas limits, signed origins,
  physical rows, exact interior/border projection, UV boundaries, scroll identity,
  stale owner/layer revisions, pending/cached/missing states, crop overflow,
  border-touching/intersecting spheres, near-plane rejection and unknown/singular
  fail-visible behavior.
- All 78 CTest tests pass in both configurations, including the refreshed latest
  fixture fingerprint gate. Standalone Vulkan marking tests also pass in Debug
  and Release with synchronization validation, including their existing full-4K,
  populated/empty reuse and capacity-overflow checks.
- The Vulkan marking qualification independently projects five points using the
  cropped matrix, including interior, border-only, outside-border and near/far
  exclusions. GPU membership matches the sphere oracle for zero-radius points
  and remains unchanged after one snapped page scroll. This tests GPU homogeneous
  projection, not triangle raster coverage or nonzero-radius GPU culling.
- A twelve-frame Debug native-4K contact-fixture launch with validation and live
  demand exits zero with no validation errors. Its measured-frame-6 capture has
  SHA256 `b03cc977ab54e11cde78d820a3de6b34192dbbcf13b0c5d8b11fcd0c0c383701`, identical
  to both preceding baseline/candidate captures. Artifacts:
  `out/m7_8_page_regions_20261001.{log,err,jsonl}` and
  `out/m7_8_page_regions_capture_20261001/`.
- Persistent pool/table/working-set requested bytes and qualification readbacks
  remain unchanged. The crop is not recorded in normal frames yet, so there is no
  new frame-time improvement claim or page-raster performance measurement. Previous
  receiver-demand overhead/p99 evidence remains authoritative.

## Remaining work and status

Next define/implement generation-safe GPU residency metadata, stable page-table
lookup/publication and caster-to-page device commands; then raster dirty page/layer
jobs with bounded updates and qualify real triangle/border coverage before sharing
sampling across deferred and complex-forward consumers. Do not feed production
allocation from delayed CPU readbacks, treat pending pages as sampleable, or reuse
one physical depth layer as independently cached static and dynamic products.
Local-light pages, transparent receiver coverage, invalidation/thrash, whole-frame
VSM admission and the other M7.9-M7.12 gates remain open. M7.8 remains active;
no accepted ADR is superseded and M7 is not complete.
