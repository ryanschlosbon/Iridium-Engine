# M4.10 Production Cutover - 2026-08-03

Status: Accepted M4 production-cutover characterization.

Machine-readable scene/ECS/editor/comparison results are retained under
`docs/performance/data/M4.10-*-2026-08-03.json`; full renderer JSONL and captures
are under `out/validation/m4.10/`. The frozen source and cooked contract is
`tests/scene/fixtures/m4_acceptance_contract.json`.

## Protocol

- Release, MSVC 19.51.36252.0, Core i9-14900K, RTX 4090, 32 logical processors.
- Source, cooked, ECS, transaction, and structural cases retain their slice-defined
  fixed workloads and sample counts. The ECS and editor cases use 30 samples; the
  source/cooked process cases use one warmup and five measured samples.
- The renderer repeats the accepted self-contained sample-car artifact in five
  independent 3840x2160 launches, each with 500 warmups and 10,000 measured frames.
- A separate 300-frame 4K run enables Vulkan validation and captures final SDR.

## ECS and editor results

The full post-cutover ECS matrix completed all 30-sample cases through one million
entities. Representative 100k results are 13.551 ns/op random hit, 2.353 ns/op
dense Transform iteration, and 177.685 ns/op persistent-UUID resolution. The
100k-operation property tests in CTest remain the correctness authority. The
benchmark no longer compiles or measures the removed v0 reader/writer; source
schema-1 is measured by the dedicated source benchmark and v0 exists only as pure
migration fixtures.

The repeat transaction run measures 10,000-target apply at 0.1001 ms median /
0.1167 ms p95 / 0.1223 ms p99, undo at 0.0472 ms, redo at 0.0443 ms, and 2.356 MiB
estimated history. At 10,000 entities, structural delete is 10.172 ms median and
subtree duplication is 33.258 ms median. These stay outside the normal frame and
preserve atomic undo/redo.

## Interpretation

M4 closes without a normal-frame wait, runtime source parse, path identity, or
editor/UI dependency. The material, selection, debug, wireframe, transport, and
viewport evidence accepted by M3/M4.7 remains valid; final output is exactly
preserved. Large authored JSON and one-shot 100k CPU staging remain visible future
load-tooling risks. M5 does not inherit a requirement to optimize source JSON, and
runtime streaming must continue to consume validated cooked data.
