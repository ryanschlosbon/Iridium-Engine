# M7.8 virtual-shadow residency contract

Date: 2026-09-29  
Status: accepted residency, persistent Vulkan storage, and GPU directional mark/compaction reference checkpoint; virtual sampling remains disabled

## Outcome

M7.8 now has a backend-neutral ABI and deterministic CPU reference planner for
sparse Virtual Shadow Map residency. The contract defines:

- stable light-owner, projection-revision, projection-kind, clip-level/cube-face,
  mip, and virtual-page coordinates;
- separate static and dynamic caster revisions and validity layers, allowing a
  moving caster to invalidate dynamic depth without discarding cached static depth;
- receiver-sample and authored-light priority ordering;
- a bounded physical page pool and per-frame update budget;
- deterministic free-page allocation and age/priority/physical-index eviction that
  never evicts another page requested in the same frame;
- explicit cached, pending-raster, and missing states;
- publication only after an exact physical-page completion is committed; and
- safe missing-page behavior through deterministic conventional-shadow fallback or
  fully lit fail-visible output. Stale virtual depth is never sampled.

Duplicate receiver marks merge only when their caster revisions agree. Conflicting
same-frame revisions are rejected as an incoherent producer state instead of
selecting an arbitrary revision. Static caching can be disabled explicitly without
changing dynamic-layer reuse.

The second checkpoint adds an explicit, default-off Vulkan allocation path behind
`--experimental-virtual-shadow-resources`. It reserves a 1,024-page D32 physical
atlas using 128-texel pages with a four-texel border and a 65,536-entry flat R32
page-table buffer. The RHI owns the resource dimensions; Vulkan owns atlas/device-
limit validation and allocation. The flat table is intentionally not a final GPU
address ABI and is not exposed to shaders until receiver-driven marking freezes
that layout. Conventional directional, spot, and point shadows remain live.

The resources have distinct persistent memory categories:

- `image.shadow.virtual.physical_pool`
- `buffer.shadow.virtual.page_table`
- `buffer.shadow.virtual.working_set`

The third checkpoint defines the backend-neutral directional receiver-marking
oracle. World-space receiver samples are projected into the finest containing clip
level, with a configurable page-sized guard band that moves edge samples to the
next coarser level without leaving an unmapped gap. Marks deduplicate by stable page
identity, accumulate receiver coverage with saturation, sort by authored priority
then coverage, and report invalid receivers, unmapped samples, bounded request
overflow, and dropped coverage explicitly.

Virtual-shadow ABI v2 changes directional page coordinates to signed world-page
coordinates. Each clip level publishes a snapped world-page origin, so scrolling a
camera-relative clip window changes local page coordinates while preserving the
same cached world-page identity. Projection revisions describe an incompatible
mapping change, not routine camera motion. A dedicated test proves identical page
addresses before and after a one-page snapped clip scroll.

The fourth checkpoint implements the raw directional receiver projection as a
Vulkan compute shader. The frozen std430 ABI uses 96-byte clip-level records,
32-byte receiver records, and 32-byte raw mark records. Each invocation emits one
of `Mapped`, `Unmapped`, `InvalidReceiver`, or `AddressOverflow`, plus the selected
clip-level record and signed world-page coordinates. The GPU representation uses
signed 32-bit page coordinates and fails explicitly on addition overflow; the CPU
identity remains signed 64-bit.

The fifth checkpoint adds that separate GPU request-compaction pass. It consumes
only valid mapped ABI-v2 marks, deduplicates stable page addresses, saturates
receiver coverage, preserves authored priority and required-layer unions, and emits
a capacity-bounded list in the same deterministic priority/coverage/address order
as the CPU oracle. Telemetry reports unique pages before capacity, output count,
overflow pages, dropped receiver coverage, ABI mismatches, and invalid clip-level
references. The shader intentionally uses one invocation as a correctness reference;
it is not the scalable production hash/radix implementation and is not enabled by
runtime frames.

The first parallel candidate is retained only as rejected qualification evidence.
It projects raw marks in parallel, globally bitonic-sorts by address, performs
segmented duplicate reduction, then globally bitonic-sorts by the frozen request
rank. Unlike a spin-lock hash design, no invocation waits for another workgroup, so
the result does not rely on Vulkan cross-workgroup forward-progress guarantees.
Correctness matches the CPU oracle across a 4,096-receiver multi-workgroup fixture
and a 65,536-unique-mark capacity fixture. Performance is not viable: after one
warm-up, five timestamped full-capacity runs produced a 841.992 ms Debug median and
837.758-844.757 ms across repeated Release medians on the RTX 4090. The two
65,536-entry global bitonic networks
require 272 compare/exchange dispatches and are rejected for runtime integration.
Their scratch record remains test-local rather than becoming public RHI ABI.

The replacement hierarchical candidate passes the same correctness gates and the
standalone compute admission measurement. Each 256-request block sorts in shared
memory, then eight global merge passes complete each full-capacity address/rank
ordering. Dropped coverage uses one shared reduction per block and one final
256-value reduction, eliminating the rejected candidate's globally contended
atomic counter. With device-local working buffers and a 4,096-request output cap,
five timestamped runs after warm-up measure 0.145792 ms Debug and 0.145984 ms
Release median for 65,536 unique mapped marks on the RTX 4090. Release stage
medians are 0.010016 ms projection/clear, 0.055296 ms address ordering, 0.006144 ms
deduplication/preparation, 0.069632 ms rank ordering, and 0.005120 ms bounded output
plus telemetry. Timestamps exclude qualification-only upload/readback and host
allocation; runtime integration must use persistent device-local storage and pass a
whole-frame gate.

The sixth checkpoint gives that candidate persistent runtime ownership without yet
dispatching it. The RHI derives one alignment-safe monolithic working-set layout
from the frozen std430 records and the configured 65,536-mark/4,096-request bounds.
At the validated 256-byte storage-buffer alignment, each frame owns 8,521,248 bytes:
clip levels, receiver inputs, raw marks, alternate sort requests, dense requests,
bounded output requests, and telemetry occupy non-overlapping aligned ranges. The
two Vulkan frames in flight therefore own two independent device-local buffers
(17,042,496 bytes total), preventing one frame from overwriting another frame's
mark/compaction state. Allocation is still default-off with the rest of the virtual-
shadow resources. The 2026-09-30 continuation binds these ranges with immutable
per-frame descriptor sets and qualifies the shared compute chain; normal scene
frames still await the live receiver producer.

## Verification

`VirtualShadowMapTests` covers policy and resource bounds, receiver-mark deduplication,
pending-raster publication, stable cache hits, independent dynamic invalidation,
conflicting-mark rejection, disabled static caching, priority update overflow,
requested-page protection, deterministic eviction, physical-pool overflow, and
safe missing-page fallback. It also covers finest-level selection, edge guard-band
fallback, signed world-page stability across clip scrolling, invalid/outside
receivers, request-capacity overflow, and incoherent clip-stack rejection. Debug
and Release focused builds pass 13/13 cases, and the engine links against the new
RHI and Vulkan implementations.

The final repository-wide verification after persistent working-set integration
passes 78/78 tests in both Debug and Release, including the frozen M5/M6 contract
suites. Both engine configurations link successfully.

The explicit `VulkanVirtualShadowMarkingTests` hardware qualification passes in
Debug and Release on the NVIDIA GeForce RTX 4090. Center and guarded-edge samples
match the CPU oracle exactly, outside-depth and nonfinite receivers report the
expected fail-visible states, ABI v2 is preserved in output, and a one-page snapped
clip scroll produces the same signed world-page address. Compaction qualification
also matches duplicate merging, deterministic ranking (including mip-before-level
address ties), bounded overflow and dropped coverage, saturated sample counts, and
ABI/level rejection telemetry. Vulkan validation reports zero engine errors.
The post-integration Debug/Release hardware recheck remains exact and reports
0.138112/0.138240 ms medians for the same 65,536-mark workload; the earlier
0.145792/0.145984 ms admission pair remains the recorded conservative baseline.

An eight-frame validation-enabled Debug launch passed with the allocation switch on.
The physical atlas requested and committed 75,759,616 bytes, the table 262,144
bytes, and the two frame-owned working sets 17,042,496 bytes, for an exact engine-
owned total of 93,064,256 bytes (88.753 MiB). A separate eight-frame disabled run
reports zero live bytes and zero allocations in all three categories. The enabled
run averaged 7.503475 ms at 1280x720, but this single short Debug lifecycle run is
not a performance admission result. Its redirected error log is empty and contains
no Vulkan validation error or VUID.

The runtime owner creates the descriptor sets and pipelines, and the hardware
qualification records the direct chain. Normal scene frames still await depth-
driven receiver/clip publication; page raster and virtual sampling remain gated.
Next schedule the live producer and direct chain with render-graph dependencies
and measure the integrated frame path before freezing page-table sampling and
page-raster interfaces.

The 2026-09-30 continuation completes immutable descriptor/pipeline ownership and
qualifies the shared direct marker-to-compactor operation. See
`docs/performance/M7.8-persistent-mark-compact-chain-2026-09-30.md` for current
evidence and the next live depth-receiver integration gate.

No ADR is superseded; this implements the first contract required by ADR-0010.
