# M5.12 Reflection-resolution stabilization — 2026-08-13

Status: implemented and verified as post-acceptance M5 hardening.

## User-facing behavior

- New HDRI imports use the high-end Ultra recipe: 1024 sky radiance, 32 diffuse
  irradiance, 1024 GGX specular, a 256 BRDF LUT, and 1024 deterministic samples.
- The Asset Browser exposes Iteration, High, Ultra, Cinematic, and Custom recipes.
  Custom controls separately expose sky resolution, reflection resolution, GGX
  samples, and BRDF samples. The panel reports estimated resident memory before
  reimport and warns for hero-size products.
- Existing 256-face reflection products are not silently expanded. Their settings
  remain stable until the user selects **Upgrade to Ultra**, or changes the custom
  settings, then chooses **Apply and reimport**.
- Material roughness remains the runtime scalability mechanism. Smooth and
  near-mirror materials sample the highest available GGX mips; progressively rougher
  materials select progressively smaller filtered mips. This avoids per-material
  duplicate cubemaps and keeps physically rough materials from becoming artificially
  sharp.

The presets are:

| Recipe | Sky face | Reflection face | GGX/BRDF samples |
|---|---:|---:|---:|
| Iteration | 512 | 256 | 128 |
| High | 1024 | 512 | 512 |
| Ultra | 1024 | 1024 | 1024 |
| Cinematic | 2048 | 2048 | 4096 |

## Cook and runtime architecture

Environment importer version 3 removes the editor-only 128-sample clamp. The CPU
reference cooker now builds a true downsampled radiance mip pyramid and uses the
GGX sample PDF to choose a source mip during specular convolution. Bright windows,
sun texels, and lamps therefore integrate over the footprint they represent instead
of appearing as isolated soft circles. This was the source of the reported
"bokeh" appearance; no depth-of-field or bloom pass was involved.

Radiance, irradiance, specular, and BRDF texels cook in parallel. Every texel keeps
a fixed Hammersley sequence and fixed accumulation order, so scheduling does not
change the result. Cancellation is checked during source projection and each major
parallel stage. Cooker/importer provenance and the environment preparation feature
version changed, invalidating old derived-data keys without changing the stable
environment product schema.

The general editor asset-upload budget remains 128 MiB. HDRI preparation may
explicitly schedule one oversized atomic publication as the first publication of a
tick, with a separate 640 MiB per-environment hard limit. Models and ordinary
textures cannot opt into this exception. Last-known-good residency and fence-delayed
retirement remain unchanged.

- Debug build and CTest: 69/69 pass.
- Release build and CTest: 69/69 pass.
- New tests cover smooth-mip sample-count invariance, cancellation, importer-v3
  defaults, and the explicit one-publication oversized upload contract.
- A repeated Belfast Ultra cook produced the same cook key and artifact SHA-256:
  `8806c552455a5e39c9cc8c7d687665effb82869328e76ee6b656187518cbba83`
  and
  `6ded02ac77c463defbf4e76cfa2e04f5011ec43cf9bad81a1c2c88490a272fcd`.
  The parallel cook took 18.531 seconds, versus 297.155 seconds for the same
  deterministic v3 algorithm before parallelization. The repeat took 13.664 seconds.

- The production asset-cook CLI also consumed the Ladybrand importer-v3 sidecar in
  the editor profile, built a DDC artifact in 6.7 seconds, and emitted no diagnostic.
  This exercises the real importer/metadata path rather than only the reference
  baker.
- A hidden 1280x720 Debug run loaded the Ultra Belfast product, rendered the
  118-primitive car for 8 warmups plus 16 measured frames, captured final SDR, and
  exited cleanly with Khronos Vulkan validation enabled. Persistent environment
  residency was 129.3 MiB in that run.

One matched native-4K Release checkpoint used the dressed sample car, 100 warmups,
300 measured frames, and identical settings apart from the cooked environment:

| Metric | Accepted 256 product | Ultra 1024 product |
|---|---:|---:|
| Environment creation | 0.483 s | 2.855 s |
| Total startup | 5.368 s | 6.790 s |
| Persistent environment residency | 29.276 MiB | 137.276 MiB |
| Total requested live memory | 1,524.623 MiB | 1,632.623 MiB |
| CPU frame median | 6.461 ms | 6.441 ms |
| GPU frame median | 6.010 ms | 5.879 ms |
| GPU p95 | 8.450 ms | 8.747 ms |

The exact 108 MiB residency increase is the expected quality cost. The matched
medians show no measurable steady shader cost from the larger cube; mip selection
and texture-cache behavior remain material/scene dependent. This single-process
checkpoint is not a replacement for the five-process M5 acceptance gate. The Ultra
CPU p95 contained a scheduling spike, so only the medians and memory delta are used
for the architectural decision.

The cloudy Belfast car captures differ by less than one final-SDR code value on
average. This is expected: the source is low-frequency and the car materials are
not perfect mirrors. The higher setting preserves capacity for detailed HDRIs and
near-mirror surfaces; it does not force rough surfaces to display nonphysical detail.

## Remaining work and ownership

- The current products are fully resident. M7 owns general streaming/residency work;
  sparse or streamed environment mip residency should be justified by measured
  multi-environment pressure before replacing this deterministic fallback.
- Cinematic 2048/2048 has a bounded publication contract but has not received a
  five-process runtime qualification. It remains a hero/offline option.
- A dedicated chrome-sphere, high-frequency HDRI fixture would make reflection
  sharpness regressions easier to score than the dressed-car fixture and should be
  added with the next reflection-quality acceptance pass.
- Local probes already use the same roughness-aware prefiltered environment path.
  Scene-captured probes retain their separately configurable 128-4096 capture
  resolution and update policy.

No ADR changed. The stable RHI environment handles, product schema, shared BSDF,
and deferred/complex-forward consumers remain intact.
