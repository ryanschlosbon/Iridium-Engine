# M7.7 reflection-probe device-command checkpoint

Date: 2026-09-14  
Status: accepted architecture/correctness checkpoint; probe LOD implementation
superseded by the radial checkpoint; warmed heterogeneous admission remains open

## Outcome

Reflection-probe capture now owns bounded per-frame candidate, indexed-command,
and count storage. A compute shader reads the persistent GPU-scene tables and the
scheduled cube-face matrix, performs the conservative sphere/clip test, excludes
the capture owner by its stable GPU-scene instance index, and emits commands whose
`firstInstance` is the dense primitive index. Compatible vertex/index/index-type,
alpha-mask, and sidedness work is submitted with `vkCmdDrawIndexedIndirectCount`.

The direct packet path remains the mixed-submission and capability/tiny-workload
fallback. Validation or the shadow qualification switch repeats face visibility
on the CPU and compares every device-written bin count after the frame fence.
Production omits those GPU-owned per-face CPU tests; delayed device counts and
overflow checks remain active.

Initial double-buffered probe command storage is approximately 0.58 MiB requested
for 512 primitives across the bounded 24 scheduled faces. It grows with prepared
GPU-scene primitive capacity and is capped by the existing one-million-command
local-work ceiling.

## Qualification

The existing 1280x720 Debug validation fixture schedules six faces over nine
independent probe-consumer primitives. It creates three compatible bins.

| Counter | Result |
|---|---:|
| Compact submission | 9 primitives / 36 bytes |
| Owner primitive-face exclusions | 18 |
| CPU oracle tests / culls / visible | 36 / 3 / 33 |
| Device / oracle commands | 33 / 33 |
| Mismatched bins / overflow | 0 / 0 |
| Direct fallback draws | 0 |

The no-validation deployable run records zero GPU-owned CPU face tests and still
reports 33 fence-delayed device commands with zero overflow. Its scene-linear
capture hash is `8f3f8d1d29dd276336927da69ae93ce283065d35e1e2359ff1a26ccf831fed33`,
identical to the prior GPU-scene direct-draw checkpoint. The isolated direct probe
reference remains
`3dd0f02a656888b88e8235bc00733367b4d7d0aaf6c94c9eef3debc8250f1832`.
Therefore this command transition does not enlarge the already accepted one-R16-
step numerical envelope between GPU-scene and direct capture shaders.

Retained first-capture timings are diagnostics only: the validation indirect run
records 3.5781 ms CPU capture recording and 0.782336 ms GPU capture; the deployable
run records 2.4425 ms and 0.772096 ms. Startup, first-use capture/filtering, Debug,
and validation state make these unsuitable for admission.

## Remaining gate

Probe-specific LOD is implemented by the subsequent face-invariant radial
checkpoint. M7.7 still needs a reflection-sensitive visual gate and warmed
heterogeneous directional, spot, point, and probe update workloads before these
policies are admitted beyond correctness fixtures. See
`docs/performance/M7.7-probe-radial-lod-2026-09-14.md`.
