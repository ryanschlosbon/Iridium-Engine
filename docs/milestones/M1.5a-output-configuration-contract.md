# M1.5a Evidence: Output Configuration Contract

- Status: Accepted implementation slice
- Date: 2026-07-19
- Parent slice: M1.5 final SDR transform, exposure, gamut map, and UI

## Result

The backend-neutral `OutputTransformConfig` now freezes schema version 1, output
operator, transport, profile, transfer, target and encoding chromaticities, requested
and effective luminance, manual EV, UI paper white, mastering/CLL/FALL metadata,
scRGB scale, and exact ACES package/transform identity.

The default is the approved production configuration: ACES 2, Windows SDR
Rec.709/sRGB, 0 EV, requested 203-nit paper white and 1,000-nit HDR peak, with the
effective SDR target fixed at 100 nits. scRGB uses a P3-D65 limiting target in a
linear Rec.709 encoding basis at 80 nits per 1.0; HDR10 uses a P3-D65 limiting target
in a Rec.2020/PQ container. Display-P3 and cinema DCI-P3 remain deliberately distinct
future profiles.

User-input validation rejects unsupported schema/ACES identities, non-finite values,
EV outside [-16,+16], paper white below 80 nits, and peak below paper white or above
10,000 nits. Persisted invalid data returns the complete default configuration plus
an explicit diagnostic and fallback flag.

## Verification and impact

Debug and Release `OutputTransformConfigTests` pass. They cover exact defaults,
SDR/scRGB/HDR10 effective profile derivation, chromaticity/transfer selection, EV
boundaries, NaN rejection, thrown user-input errors, and diagnostic persisted-data
fallback.

The configuration is not wired to runtime settings or shaders in this slice. Visual,
CPU-frame, GPU-frame, and memory impact is zero.
