# M1.5c Acceptance: Direct Final-SDR Capture

- Status: Accepted
- Accepted: 2026-07-19
- Baseline: accepted M1.5b graph path on commit
  `30252593f8fdd2de5dffbb8da31bb570ff49a7c0` plus preserved dirty work
- Reference system: RTX 4090, Core i9-14900K, 64 GB DDR5, 3840x2160

## Accepted architecture and behavior

The backend-neutral frame contract now separates the final output pass from UI. A
scene capture remains post-transparency/pre-output; `--capture-point final-sdr`
records the GPU-produced display color after exposure, gamut conversion, and the
selected output operator but before UI. This ordering gives M1 both an unclipped PFM
oracle and a direct final-output TGA oracle without reading the swapchain.

Windows SDR output is a BGRA8 sRGB image. The output shader writes display-linear
Rec.709 values; Vulkan performs IEC sRGB attachment encoding, and sampling that
image for UI performs the matching decode before the sRGB swapchain encodes once.
This removes the previous FP16 display intermediate and captures the exact stored
sRGB codes. The graph adds a disabled `final-capture-hook` between output and UI;
normal frames skip it without work, while capture frames use its declared transfer-
source state. The graph is now 12 passes, nine logical resources, seven physical
slots, and two frame contexts.

Final sidecars identify the capture point and source scene domain plus exact EV,
operator, gamut policy, display profile, transfer, effective paper white/peak, ACES
package, and transform ID. The legacy TGA metadata contract remains readable and
scene PFM naming/metadata is unchanged.

## Verification and visual evidence

Focused Debug and Release builds and tests pass. Coverage includes CLI capture-point
selection/rejection, modern final metadata, legacy metadata compatibility, graph
format/usage/topology, optional-pass ordering, scene/output/UI source ordering, and
PFM/TGA round trips.

Debug graph execution at 4K with +2 EV and direct output capture is Vulkan-
validation clean. The opaque emissive TGA hash is
`c0eb4d79a6cc5929a775cb264d51c68a27fb73849564094260367175ed447c6d`;
visual inspection shows an ordered six-step ramp with highlights clipping only at
the SDR output boundary. The Release color-volume final TGA hash is
`52187f1dfabe6295a9f449e74c5cbf8dbc1ac0e24a356889f1654a0fc0bda2c9`;
visual inspection confirms the transparent highlight and blue boundary are intact.
Evidence is under `out/captures/m1.5c-*` and `out/profiles/m1.5c-*`.

These are compatibility-operator evidence, not the final ACES 2 M1 references.

## Performance and memory

Three Release runs used 4K `transparency_v1`, 200 warmup frames, and 3,000 measured
frames:

| Run | CPU frame median | GPU frame median | Output GPU median / p99 | Output CPU median |
|---:|---:|---:|---:|---:|
| 1 | 0.5650 ms | 0.453408 ms | 0.028672 / 0.030720 ms | 0.0019 ms |
| 2 | 0.5695 ms | 0.453984 ms | 0.028672 / 0.031744 ms | 0.0019 ms |
| 3 | 0.5640 ms | 0.455072 ms | 0.028672 / 0.030720 ms | 0.0019 ms |

The BGRA8 target reduces the output-pass median by about 0.0113 ms from M1.5b's
FP16 display intermediate. Output remains well below the 0.25 ms median / 0.35 ms
p99 gate and CPU recording remains below 0.02 ms. Normal-frame allocation median is
zero.

Because BGRA8 is not alias-compatible with the expired FP16 resources, the graph
adds one target per frame context: steady memory is 729,909,068 B requested /
735,317,696 B committed, an increase of 66,846,720 B committed (63.75 MiB). This is
the complete categorized cost, remains about 220.9 MiB below the M0 committed
ceiling, and halves output-target bytes per pixel. Requested capture readback is an
additional temporary 33,177,600 B and is excluded from steady timing evidence.

## Acceptance and next work

M1.5c is accepted. The next slice adds selectable ACES 2, legacy-fitted, and identity
diagnostic operators. The production default will use a deterministic shaper/3D-LUT
representation baked from the pinned Academy
`Output.Academy.Rec709-D65_100nit_in_Rec709-D65_sRGB-Piecewise.a2.v1`
analytical transform, with Academy/OCIO vectors, transform provenance, approximation
error bounds, and measured GPU cost. The legacy operator remains the rollback path.
