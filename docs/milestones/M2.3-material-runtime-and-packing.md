# M2.3 Acceptance: Material Runtime, GPU Packing, and Diagnostics

- Status: Complete on 2026-07-22
- Milestone: M2 - Material Compiler and Canonical Shading Closures
- Source baseline: `30252593f8fdd2de5dffbb8da31bb570ff49a7c0`
- Worktree: intentionally dirty accepted M0/M1 and active M2 work
- Reference hardware: RTX 4090, Core i9-14900K, 64 GB system memory

## Decision

M2.3 is complete. The four material concepts are now mechanically distinct:

1. `SourceMaterial` is the immutable import/provenance description.
2. `CompiledMaterial` is created only by the compiler and shared as
   `shared_ptr<const CompiledMaterial>`.
3. `MaterialInstance` owns only sanctioned mutable values and resolved texture and
   sampler bindings while retaining immutable compiled ownership.
4. `PackedGpuMaterial` schema 1 is a backend-neutral, index-addressable GPU record.

The renderer does not consume these records yet. `AssetManager`, the legacy
`MaterialAsset`, draw packets, production graph, Vulkan descriptors, and shaders are
unchanged. M2.4 remains the opt-in activation and A/B slice.

## Instance contract

An instance starts from the compiled standard recipe and has a monotonic revision
and explicit override mask. Legal edits change uniform factors or replace an
already-required texture/sampler pair. The API returns `RequiresRecompile` instead
of mutating the closure contract when an edit would change workflow, closure class,
alpha class, culling class, required UV/texture features, or emissive activation.
Invalid finite/range or null-handle values are rejected separately.

Metallic/roughness and archived specular/glossiness expose different legal override
sets. Normal scale and AO strength require their compiled texture features. Emissive
may vary without recompilation only while its compiled feature remains active.
Instance edits do not alter the compiled semantic hash.

`MaterialInstanceStore` uses the existing 20-bit-index/12-bit-generation handle
model. Destroyed instance handles cannot access a replacement in the reused slot.
Texture and sampler bindings are independently generation-validated before packing.
A sampler is an RHI-level handle rather than a glTF source index or Vulkan object;
M2.4 may resolve glTF sampler state without encoding backend image/layout details in
the material contract.

## Packed schema 1

`PackedGpuMaterial` is 832 bytes, 16-byte aligned, standard-layout, and trivially
copyable. Static offset tests freeze its ABI. It contains:

- schema, closure, workflow, feature, alpha, sidedness, and texture masks;
- FP32 standard factors, preserving canonical values without introducing a material
  precision decision before GPU image evidence;
- fixed semantic texture and sampler indices;
- FP16 UV offset/scale/rotation and per-use scalar values;
- up to eight typed complex-lobe payloads for the later M2.6 interface;
- explicit zeroed reserved bytes so repeat packing and record hashes are bit-exact.

Only values with a known bounded-error use are FP16. Schema 1 does not use UNORM or
SNORM, so their boundary tests are intentionally not applicable. FP16 tests cover
positive and negative zero, 0.5, 1.0, maximum finite, minimum normal, minimum
subnormal, infinity/NaN conversion, and pack-time rejection of non-finite or
out-of-range finite values. Texture-coordinate and sampler-index overflows are
diagnostic errors rather than truncation.

The record deliberately favors a complete fixed semantic contract in this
correctness slice. Ten thousand records occupy 8,320,000 bytes; ten thousand CPU
instances occupy 3,200,000 inline bytes. This is acceptable as an initial high-end
material table, but not evidence that 832 bytes is the final cache-optimal production
stride. M2.4 must measure shader access and upload behavior. If the stride causes a
measurable regression, the rollback is to keep the renderer on `MaterialAsset` and
split standard texture/complex payload tables under a new schema rather than silently
discard semantics.

## Diagnostic snapshot

The backend-neutral deterministic JSON snapshot includes:

- source values and authored/default origins;
- source image identity, channel and transfer interpretation, UV, transform, scalar,
  and sampler state;
- compiled workflow, closure, factors, semantic hash, texture program, and complex
  lobe classifications;
- instance revision, override fields, and texture/sampler handle indices and
  generations;
- packed factor values, texture indices, raw FP16 texture-use bits, byte size, and
  record SHA-256;
- ordered compile and pack diagnostics.

Repeated snapshots of identical inputs are byte-identical and hash-identical. The
model has no editor, Vulkan, descriptor-layout, or draw-packet dependency; the M2.9
editor panel can consume it without moving UI dependencies into runtime material
types.

## Automated verification

Complete Debug and Release builds succeed. Each configuration passes all 18 CTests.
`MaterialRuntimeTests` covers:

- const compiled ownership and content-hash identity across instance edits;
- legal, unchanged, invalid, and recompilation-required overrides for both workflows;
- exact record sizes, alignments, offsets, flags, texture indices, sampler indices,
  and deterministic repeated bytes;
- FP32 closure and FP16 transform/scalar round trips;
- typed complex-lobe packing;
- stale texture, stale sampler, capacity/range, invalid binding, and schema rejection;
- generation-safe material instance reuse;
- initial, unchanged, single-change, and changed-only upload accounting;
- complete parseable diagnostic JSON and deterministic snapshot hashes.

## CPU and memory performance

`MaterialRuntimeBenchmark` runs two warm-up and ten measured x64 Release iterations.
It uses 10,000 standard instances and pre-reserved outputs. Allocation figures cover
global C++ `new`/`new[]` calls and requested bytes.

| Operation | Median | p95 | Mean allocations | Mean requested bytes | Upload bytes |
|---|---:|---:|---:|---:|---:|
| Pack 10,000 | 0.6372 ms | 0.6596 ms | 0 | 0 B | 8,320,000 B |
| Update 100 of 10,000 | 0.0161 ms | 0.0228 ms | 0 | 0 B | 83,200 B |
| Scan 10,000 unchanged | 0.0094 ms | observation only | 0 | 0 B | 0 B |

Packing is proportional to changed records after a linear revision scan, performs no
steady-state allocation with reserved output, and emits no bytes for unchanged
instances. Full-table packing is an initialization or mass-change cost, not a frame
budget precedent.

## Visual, GPU, and renderer-memory evidence

M2.3 is linked but inactive in renderer execution, so its attributable visual,
GPU-time, production VRAM, and steady-frame CPU deltas are zero. A final 3840x2160
Debug render-graph run used the Khronos validation layer and captured final SDR. The
TGA SHA-256 is
`87d130f6c107126d18b2f345a3aaf74c6368ea9ee0f9b8f45174ef67f7107404`, bit-exact
with accepted M1 and M2.0-M2.2. The run emitted no validation warning, error, or VUID.

The capture frame is perturbed and is not percentile evidence. It observed a
2.277856 ms GPU frame, 0.009216 ms opaque GBuffer range, 0.066560 ms deferred-lighting
range, 796,640,716 requested live bytes, and 802,049,360 committed live bytes. These
match the established inactive-path observation and include the 33,177,600-byte
capture readback; no M2.3 GPU material buffer exists yet.

## Rollback and next slice

Removing `MaterialRuntime`, its test/benchmark targets, and the unused RHI sampler
handle restores M2.2 without changing a rendered frame. No ADR changed: this slice
implements the ownership and packing boundary already accepted by ADR-0001 and the
future indexability required by ADR-0006.

The next slice is M2.4: resolve runtime textures and samplers, upload schema-1 standard
records behind an opt-in switch, index them from reduced draw data, and compare the
canonical standard closure against the unchanged legacy path. M2.4 must measure the
832-byte table's actual upload/cache cost and retain the old path as rollback.
