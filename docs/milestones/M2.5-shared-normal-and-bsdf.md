# M2.5 Shared Normal and BSDF Library

> Historical slice note: M2.10 removed the flag-based rollback and manual renderer.

Status: Complete on 2026-07-22.

This report is the durable acceptance record for M2.5 in
`M2-material-compiler-and-closures.md`. It does not accept M2.6 complex closure
evaluation or change the fixed M0 lighting/environment model.

## Delivered behavior

- `material_normal.glsl` is the descriptor-free raster/RT-compatible convention for
  tangent-frame construction, two-sided orientation, handedness, tangent-normal
  application, and octahedral normal encoding/decoding. Canonical GBuffer output,
  deferred decode, and forward shading use it.
- `material_bsdf.glsl` is the descriptor-free standard reflection library for
  F0/F90 Schlick Fresnel, perceptual-roughness-to-GGX-alpha policy, GGX distribution,
  Smith masking, diffuse energy weighting, and complete standard BRDF evaluation.
  Deferred and non-transmissive standard-forward evaluation call the same function.
- `StandardMaterialShading.h` mirrors the GLSL numerical and coordinate policy for
  compiler/reference vectors. Authored roughness remains in `[0,1]`; only BSDF alpha
  applies the `0.04` perceptual-roughness floor. Denominators use `1e-7` guards.
- Imported authored tangents retain glTF `w`. Missing tangents now accumulate both
  U and V derivatives, Gram-Schmidt orthogonalize against the normal, derive the
  MikkTSpace handedness convention `B = cross(N,T) * w`, and use a deterministic
  orthogonal fallback for degenerate UVs. Mirrored baked transforms flip `w`.
- Alpha-blended materials with zero transmission provide the M2.5 forced-forward
  standard parity route. Transmissive materials retain the bounded M1 transport for
  M2.6; no M5 lighting or M6 ordering/refraction work was pulled into this slice.
- The absence of `--canonical-materials` remains the material rollback. The legacy
  `shader.frag` normal implementation is intentionally retained only by that rollback
  and is removed with the manual/legacy renderer in M2.10.

## Automated and shader verification

Debug and a preset-verified Release configuration build every shader with `glslc`.
Both configurations pass 20/20 CTest tests. `StandardMaterialShadingTests` covers:

- F0 and F90 endpoints, grazing Fresnel, roughness zero/one, finite GGX/Smith
  boundaries, and dielectric/conductor diffuse weights;
- front/back two-sided orientation, mirrored handedness, normal-map Y response, and
  degenerate tangent fallback;
- positive and mirrored generated UV frames plus degenerate-UV statistics;
- compile-time source contracts proving deferred and forward include and call the
  shared normal/BRDF libraries and no longer define private Fresnel/GGX functions.

The opaque and alpha-BLEND fixtures record one deferred draw and one forced-forward
draw respectively under Vulkan validation. Both use identical material, geometry,
camera, and environment inputs. Their 4K final-SDR comparison has maximum code delta
1, p95 maximum RGB delta 0, mean luma SSIM 0.99999795, and no alpha difference.
The 1.5089% changed-pixel count is entirely one-code quantization at covered pixels;
the heatmap has no structured material difference. Hemisphere/edge numerical vectors
in the CPU test supply the sphere-normal sweep without making a tessellated sphere a
runtime fixture dependency.

The tracked M2.4 material GPU lab also completed 4K Debug validation captures for
final, normal, and roughness views. Visual inspection confirms the expected separated
factor/texture regions, stable flat/geometric normal convention, and three authored
roughness levels. No validation message was reported.

## Performance and memory evidence

The accepted M2.0 material-lab graph baseline is 0.0102 ms opaque GBuffer plus
0.0922 ms deferred lighting, approximately 0.1024 ms combined median. Five matched
Release runs used the same visible borderless 4K fixture, 500 warm-up frames, 10,000
measured frames, validation off, and GPU timestamps. Results are milliseconds:

| Run | GBuffer median | Lighting median | Combined median | Lighting p99 |
|---:|---:|---:|---:|---:|
| 1 | 0.009216 | 0.097280 | 0.106496 | 0.366592 |
| 2 | 0.009216 | 0.096256 | 0.105472 | 0.117760 |
| 3 | 0.009216 | 0.096256 | 0.105472 | 0.116736 |
| 4 | 0.009216 | 0.096256 | 0.105472 | 0.115712 |
| 5 | 0.009216 | 0.096256 | 0.105472 | 0.115712 |

The combined median-of-five is 0.105472 ms, a +0.003072 ms delta from the accepted
baseline and safely inside the +0.05 ms gate. Run-one p99 is an isolated scheduling
outlier; four repetitions cluster from 0.115712 to 0.117760 ms. The matched run keeps
requested live memory at 763,463,296 bytes and committed live memory at 768,871,936
bytes, so shared source/instructions add no GPU allocation. The canonical M2.4 proxy
remains at 770,278,664 requested and 775,691,328 committed bytes.

The initially named Release cache was discovered to contain `CMAKE_BUILD_TYPE=Debug`.
That diagnostic profile was discarded. CMake was reconfigured with the
`x64-release` preset, and every accepted timing profile records
`build_configuration: Release` in its run header.
