## Outcome

M1.1 adds an isolated backend-neutral render-graph module. It is compiled and tested
but is not yet connected to the RHI, Vulkan frame lifecycle, shaders, or renderer.
M1.2 can therefore integrate a Vulkan shadow executor without changing the frozen
declaration/compiler contracts opportunistically.

The graph provides:

- generation-checked resource and pass handles with deterministic stale-handle
  rejection;
- fixed declared capacities and pre-reserved builder storage;
- transient, persistent, history, and imported/external resource lifetimes plus
  explicit exports;
- versioned logical resources: every write creates one single-writer version;
  attachment `Load` operations explicitly preserve and order the prior version;
- stable topological order, explicit dependencies, producer/consumer edges, and
  cycle/read-before-write/discarded-content/stale-export diagnostics;
- backend-neutral access, queue, load/store, initial/final state, and transition
  records;
- first/last-use lifetime analysis and conservative exact-descriptor transient
  physical-slot reuse with unioned usage requirements;
- a topology hash that excludes handle generations and dynamic history validity;
- dynamic history validity tracking that can be invalidated without recompiling;
- an eight-entry fixed-capacity compiled-plan cache with allocation-free lookup.

## Verification

Focused unit coverage passes 11/11 in Debug and Release:

- stable DAG ordering and compiled usage spans;
- cycle diagnostics;
- read-before-write diagnostics;
- imported initial and exported final states;
- dynamic history invalidation;
- discarded-content, stale-export, and invalid load-operation rejection;
- nonoverlapping transient reuse;
- overlapping/incompatible non-reuse;
- versioned attachment-load ordering;
- stale handles and capacity exhaustion;
- repeatable topology hash and fixed compiled-plan cache behavior.

The final integrated gate passes all 10 CTests in Debug and all 10 in Release. The
Release cache independently reports `CMAKE_BUILD_TYPE=Release`.

## Performance and memory evidence

The Release synthetic benchmark constructs and compiles a chain of 1,000 versioned
passes, stores the plan, and performs five sets of 1,000,000 alternating hit/miss
cache lookups:

| Metric | Result | Gate |
|---|---:|---:|
| 1,000-pass topology compile | 1.8513 ms | topology-change path; reported, not a per-frame gate |
| Compile C++ allocation requests | 2,016 calls / 137,550 bytes | topology-change path only |
| Cached lookup median | 1.8324 ns | less than 0.01 ms |
| Cached lookup allocations | 0 calls / 0 bytes | zero |

The compiler intentionally uses bounded host allocations while building a changed
topology. Normal-frame code will use only the cached immutable plan, external
bindings, dynamic constants, and history-validity state. M1.2 must verify that the
shadow integration does not rebuild or allocate during steady frames.

## Visual, CPU/GPU, and renderer-memory impact

- Visual impact: none; no renderer path consumes the graph.
- GPU impact: none; no Vulkan work or resource allocation is emitted.
- Steady-state renderer CPU impact: none in this slice; cache lookup evidence is the
  future execution-path bound.
- Renderer VRAM impact: zero.
- Persistent engine runtime memory impact: zero because the module is not yet linked
  into the engine. Test/benchmark process memory is outside the renderer baseline.

## Remaining risks and next slice

- Physical reuse is deliberately conservative: descriptors must match exactly.
  Broader compatible/superset allocation needs measured M1.2 evidence.
- The compiler emits abstract state and queue intent only. Vulkan stage/access/layout
  mapping, frame-fence retirement, and resize failure cleanup belong to M1.2.
- The graph does not expose Vulkan recording callbacks. M1.2 owns the backend-only
  registration boundary without adding Vulkan types to this module.
- Compiled-plan cache capacity is eight deterministic entries. Eviction policy can be
  revisited only if real output/resolution/quality topology churn demonstrates need.

No accepted ADR was contradicted or superseded. M1.2, the Vulkan executor in shadow
mode, is the next slice.
