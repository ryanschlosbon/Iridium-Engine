# M2.4 Standard Material GPU Path

> Historical slice note: M2.10 made this path unconditional and removed
> `--canonical-materials` and `--render-graph`.

Status: Complete on 2026-07-22.

This report is the durable acceptance record for the opt-in standard-material GPU
slice in `M2-material-compiler-and-closures.md`. It does not accept M2.5 or select a
production GBuffer layout.

## Delivered behavior

- `--canonical-materials` selects the path and requires the production
  `--render-graph` executor. Without the flag, the legacy material shader, packing,
  push constants, and visual path remain available for matched A/B runs.
- A backend-neutral `CanonicalMaterialAsset` carries the schema-2, 832-byte
  `PackedGpuMaterial`, semantic texture handles, and pipeline state through the RHI.
  Vulkan owns the descriptor sets, two safe-frame material-table buffers, upload
  retirement, and canonical pipeline creation.
- Standard deferred metallic/roughness materials compile once during source import,
  instantiate and pack once, upload by stable material-handle index, and draw with an
  80-byte transform-plus-index push block. Active complex, transparent, unlit, or
  unsupported-UV closures retain explicit legacy routing for M2.6 rather than being
  flattened.
- The canonical vertex contract preserves VEC4 vertex-color alpha and independent
  `TEXCOORD_0`/`TEXCOORD_1`. The fragment path evaluates base color/alpha,
  metallic/roughness channels, tangent normal, AO strength, scene-linear emissive,
  per-use UV transforms, alpha mask, and double-sided normals. Its current output is
  a correct projection into the retained legacy three-target MR GBuffer; M2.8 still
  owns the complete RGB-F0/F90 canonical reference GBuffer.
- glTF sampler filters and wrap modes are mapped explicitly. CPU compatibility
  upload creates every mip requested by the minification filter, filters sRGB in
  linear light, renormalizes tangent normals, and keeps linear data linear. Vulkan
  image allocation, upload regions, views, transitions, and sampler LOD cover the
  full chain.
- AO occupies the existing albedo target alpha and is applied only to deferred
  ambient lighting. Legacy materials write AO 1.0, preserving rollback behavior.
- Runtime/profile metadata names the canonical render mode and reports persistent
  material buffers as `buffer.material_gpu`.

The material table currently reserves 4,096 records per safe frame. Two coherent
buffers cost 6,815,744 bytes requested and committed. This deliberately simple
fixed-capacity compatibility table is not the M3 cooked/bindless design.

## Verification

Both configured builds succeeded, including `canonical_material.vert` and
`canonical_material.frag`. Debug and Release each passed 19/19 CTest tests. Added or
extended coverage verifies:

- schema/offset/stride and reduced-push contracts;
- indexed resource-pool traversal and generation-safe records;
- independent per-frame revision retirement with unchanged revisions skipped;
- VEC4 vertex and dual-UV ABI;
- sampler/filter/wrap mapping, complete mip layout, sRGB filtering, normal
  renormalization, and invalid-source rejection;
- configuration rejection when canonical materials are requested without the graph;
- the tracked M2.4 material-GPU fixture and its content hash.

The Release runtime benchmark also records zero allocations for an unchanged scan
of 10,000 material instances. In integrated 10,000-frame runs, both legacy and
canonical paths had one median C++ allocation per frame; canonical never exceeded
one, while the legacy comparator ranged from one to ten.

Vulkan validation runs completed without reported validation messages for the 4K
material lab and the 1280x720 full sample car. The final 4K validation scene capture
hash is `325aeeaf625faf53aaf0ae47104ada6b92dafb1beb5fce51163e9988e17e0a5e`.

## Image evidence

The tracked `material_gpu_lab_v1` fixture contains factor-only, textured, and masked
emissive standard materials. It exercises sRGB base/emissive input, linear normal,
MR and AO input, both UV attributes, texture transform, mirrored/clamped sampler
state, and a required mip chain. The visually inspected 4K final-SDR capture shows
the expected factor triangle and transformed four-quadrant texture samples; its hash
is `8c8c24274aaf3fabdaf4da1af700728c3949979b486ec3bed7c52c371789f50d`.

The 4K material-lab canonical final-SDR hash is
`f36a3d8eb1cef5e5386cc8e06389b98066d4cc0397029c36cb8d4c96b5c23bad`.
Compared with the accepted legacy hash `87d130f6c107126d18b2f345a3aaf74c6368ea9ee0f9b8f45174ef67f7107404`,
0.4250% of pixels change and mean luma SSIM is 0.999142. The localized difference is
expected: canonical materials without a normal texture use the geometric normal;
legacy always samples the `(128,128,255)` fallback, which introduces a small false
tangent-space tilt.

The supplemental sample-car 4K capture was inspected directly. Canonical texture,
normal, roughness and AO evaluation produces a material-wide difference from the
legacy approximation (17.596% changed pixels, SSIM 0.879553). This is recorded as
behavioral evidence, not accepted as a lighting-quality oracle: active coat and
transmission remain on the bounded legacy routes until M2.6, and M5 owns production
lighting. The canonical car capture hash is
`ebe4c6b9cac405bbac1bf730f14303be389a9705030bcbf2b52470b2c7186395`.

## Matched 4K performance and memory

Reference system, Release, hidden 3840x2160 window, graph executor, validation off,
500 warm-up frames, 10,000 measured frames, `material_lab_v1`:

| Metric | Legacy median / p99 | Canonical median / p99 | Delta |
|---|---:|---:|---:|
| CPU extraction | 0.0063 / 0.0094 ms | 0.0050 / 0.0077 ms | -0.0013 / -0.0017 ms |
| CPU GBuffer recording | 0.0358 / 0.0542 ms | 0.0292 / 0.0439 ms | -0.0066 / -0.0103 ms |
| GPU opaque GBuffer | 0.010240 / 0.012288 ms | 0.010240 / 0.012288 ms | 0 / 0 ms |
| Requested live memory | 763,463,296 bytes | 770,279,040 bytes | +6,815,744 bytes |

The CPU delta is below the +0.02 ms median/+0.05 ms p99 gate and GPU delta is below
the +0.05 ms gate. The material lab has no authored textures, so texture memory is
bit-identical at 33,554,444 requested bytes. In the supplemental car run, compatible
mip chains increase texture storage from 95,700,364 to 115,977,328 requested bytes;
the count changes from 80 to 81 because semantic/sampler compatibility sometimes
requires a distinct image object. One-frame car GBuffer timing changed from 0.198656
to 0.208896 ms (+0.010240 ms), but that single sample is diagnostic, not the gate.

## Rollback and remaining ownership

Rollback is the absence of `--canonical-materials`; the old standard shader and
material allocation remain intact. M2.5 next owns shared normal/BSDF functions and
validated tangent generation. M2.6 owns complex-forward closures. M2.8/M2.9 own the
complete reference and measured packed GBuffer choices. M3 owns asynchronous cooking,
deduplication, streaming, and the long-term descriptor strategy.
