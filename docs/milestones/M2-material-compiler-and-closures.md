The audit and early-slice sections below preserve the reviewed state at their dated

## Objective and user-visible outcome

Iridium will import authored material intent without silently replacing defaults,
textures, channels, color spaces, UVs, samplers, or extensions. It will compile
ordinary single-lobe surfaces into one explainable standard closure and route
materials that need distinct lobes or transport into explicit complex-forward or
unlit closures. Deferred and forward shading will use the same closure and BSDF
conventions.

At acceptance, the sample car and tracked material fixtures must show the complete
path from source values through defaults, compilation, material instances, GPU
packing, closure selection, and shader-visible values. Paint coatings, windows,
headlight lenses, normal/roughness detail, and the absence of authored car emissive
data must be explainable without lighting or glass special cases. A high-precision
canonical GBuffer remains available as the image oracle; any production layout is
selected only after 4K image, bandwidth, GPU-time, and memory evidence. The selected
layout is the near-term canonical surface cache, not a permanent requirement that
geometry emit a full GBuffer; ADR-0006 defines its later visibility-resolve use.

## Current context and audited implementation

Repository source was reinspected on 2026-07-22 after reading the complete M0/M1
handoff and every accepted ADR. The current path is:

```text
glTF JSON + fastgltf 0.9.0
  -> AssetManager::loadModelFromFile
  -> MaterialAsset (source and runtime concepts combined)
  -> IRenderBackend::allocateMaterial
  -> VulkanMaterialPayload + two descriptor sets
  -> MaterialBinding in ModelAsset
  -> per-submesh DrawPacket
  -> 120-byte MeshPushConstants + five sampled textures
  -> shader.frag GBuffer or forward.frag
  -> lighting.frag deferred evaluation
```

There is no `SourceMaterial`, compiler, immutable compiled material, or material
instance. `MaterialProvenance` is a CPU-only M0 sidecar for textual `.gltf`; it
records selected source facts but then snapshots the same `MaterialAsset` and push
inputs rather than a compiled closure or GPU record. The Vulkan payload copies the
factors again. Material factors are pushed for every draw even though the push block
is already 120 bytes, close to Vulkan's guaranteed 128-byte minimum.

### Current ingestion behavior

- The fastgltf parser enables only `KHR_materials_emissive_strength` and
  `KHR_materials_transmission`. Clearcoat, specular, IOR, sheen, anisotropy,
  iridescence, volume, unlit, diffuse transmission, texture transforms, and archived
  specular/glossiness are not runtime inputs.
- Core base-color and emissive images use sRGB Vulkan formats; normal,
  metallic/roughness, and transmission images use UNORM. The shader therefore sees
  decoded linear base/emissive samples and raw linear data samples. Factors are
  treated as linear, which matches glTF.
- Metallic/roughness channels are correctly sampled as G=roughness and B=metallic;
  transmission uses R. Occlusion R and `occlusionTexture.strength` are recorded but
  never consumed.
- Each primitive retains only one UV stream. It chooses `TEXCOORD_0`, or falls back
  to `TEXCOORD_1` when set 0 is absent, regardless of each texture's `texCoord`.
  `KHR_texture_transform` is diagnostic-only.
- `Vertex` stores RGB color only. A glTF `COLOR_0` VEC4 is read, but its alpha is
  discarded, so vertex alpha cannot currently participate in material coverage.
- The car has 118 primitives with UV0, 101 with UV1, and 100 authored tangent
  streams. The remaining tangent frames are generated by a local approximation that
  always writes positive handedness; it is not a validated MikkTSpace-equivalent
  path and may disagree with normal-map baking.
- Source samplers are diagnostic-only. Runtime creates one sampler per uploaded
  image with linear min/mag, repeat addressing, no generated mip chain, default
  nearest mip selection, and `maxLod=0`. glTF minification/mipmap filters and wrap
  modes are ignored.
- `MASK` uses source cutoff; `BLEND` or nonzero transmission selects the same forward
  alpha-blended path. All other materials use the deferred path. Double-sided state
  changes culling, but deferred backfaces do not mirror the geometric normal as the
  forward shader does.
- All primitives sharing a material are merged into one baked submesh. This is
  visually usable for current opaque draws but destroys disconnected spatial
  boundaries needed by M6. M2 will not invent a new transparency algorithm; M3/M6
  retain ownership of general cook boundaries and sorting.

### Current shader and representation mismatches

- The current GBuffer is three `RGBA16F` color targets, 24 bytes/pixel before depth:
  octahedral normal XY + perceptual roughness + metallic; base color RGB + unused A;
  and emissive RGB + unused A. Comments describing 32- or 96-bit storage are stale;
  the actual color footprint is 192 bits/pixel.
- Deferred lighting reconstructs RGB F0 as `mix(0.04, baseColor, metallic)`. The
  GBuffer therefore stores the authoring parameter metallic rather than the accepted
  canonical F0. It has no AO, material ID, model ID, or feature flags.
- Both raster shaders clamp perceptual roughness to 0.04 before storage/evaluation.
  Source roughness is therefore not preserved at zero. M2 will retain authored
  perceptual roughness and apply only a documented numerical alpha floor inside the
  BSDF.
- Tangent-frame construction and two-sided handling are duplicated and differ
  between deferred and forward shaders. GGX distribution, geometry, and Fresnel
  helpers live in `lighting.frag`; forward has a separate Fresnel implementation and
  ad hoc glass evaluation. There is no shared BSDF include suitable for RT reuse.
- Deferred lighting still contains the M0 demonstration directional light and
  incomplete environment approximation. Those are useful fixed test illumination,
  not M2 work. M5 owns production direct lighting and IBL.
- Forward transmission hardcodes IOR 1.52, absorption scale, distortion scale, and
  two-bucket scene copies. M2 may replace material-derived Fresnel/closure inputs,
  but M6 owns ordering, depth peeling/OIT, layered glass, and production refraction.

### Accepted M1 invariant mismatch

M1 documentation names graph execution as the production path, and all accepted M1
evidence was collected with `--render-graph`. Current `ApplicationConfig` still
defaults `enableRenderGraphExecution` to false, so a normal launch uses manual target
ownership/transitions unless the flag is supplied. This is stale implementation
relative to the accepted invariant. M2 owns the already-planned legacy disposition:
make graph execution unconditional for production, retain the manual path only long
enough to compare the material migration, and remove it only after the complete M1
image/validation/timing/memory gate passes.

### Existing test and fixture coverage

- `MaterialProvenanceTests` passes in current Debug and Release builds. It checks
  selected glTF defaults, texture semantics, warnings, runtime copies, and optional
  Alfa indices. It does not compile closures or inspect shader-evaluated pixels.
- `material_provenance_fixture.gltf` declares UV1, a sampler, clearcoat, specular,
  transmission, texture transform, occlusion, and an unknown extension, but its
  referenced images are not runtime fixtures.
- `material_lab.gltf` covers factors and extension diagnostics but uses untextured
  triangles, not the full standard/complex closure matrix. There is no tracked
  specular/glossiness fixture.
- M1 provides authoritative scene-linear and final-output capture domains plus the
  accepted 4K output/transport baseline. M2 must preserve those hashes where material
  semantics are intentionally unchanged and create new references where corrected
  semantics intentionally change images.

## Invariants

- Lighting, emissive, and transparency remain scene-linear ACEScg/AP1 until the one
  accepted M1 output transform. No material compiler or BSDF code performs tone or
  display mapping.
- The render graph remains the production frame path. Vulkan handles, descriptor
  layouts, image formats, and synchronization remain behind the RHI/backend boundary.
- Source data is immutable and distinguishable from format defaults, engine
  fallbacks, compiler approximations, instance overrides, and packed GPU values.
- A required unsupported or conflicting extension fails deterministically. An
  optional fallback is explicit and diagnostic; no extension is silently ignored.
- The compiler never repairs suspicious authored data merely because it looks wrong.
- Standard deferred and standard/complex forward paths use the same closure fields,
  coordinate conventions, numerical guards, and BSDF functions.
- Texture color interpretation belongs to a texture use, not only an image. The same
  source image may require separate sRGB and linear views/resources until M3 supplies
  a richer texture asset system.
- Material instances cannot change closure class or required shader features without
  recompilation. Stable GUIDs and cooked asset identity remain M3 work.
- The high-precision canonical GBuffer is retained as the oracle even if a packed
  production layout is selected.
- Material, instance, geometry, and packed closure interfaces must not prevent the
  ADR-0006 visibility path from resolving the same canonical surface fields later.
  M2 does not implement that path.
- No slice adds production lights, IBL, shadows, probes, general transparent
  ordering, OIT, peeling, automatic exposure, or temporal reconstruction.

## Scope

- `SourceMaterial`, `CompiledMaterial`, `MaterialInstance`, and `PackedGpuMaterial`
  contracts with explicit ownership and versioning.
- Core glTF 2.0 material factors, defaults, textures, channels, samplers, UV sets,
  normal/occlusion strength, alpha modes, double-sided state, and texture transforms.
- Metallic/roughness and archived specular/glossiness source workflows.
- Exact standard-closure compilation where the source is one representable lobe.
- Explicit complex-forward and unlit classification plus the material/BSDF data
  interfaces needed by M5/M6.
- Shared GLSL closure, normal-mapping, Fresnel, GGX, Smith, and energy-weighting
  functions, structured for later equivalent RT implementation.
- Canonical reference and measured near-term production GBuffer/surface-cache candidates.
- Diagnostics and deterministic CPU/GPU reference tests.
- Production-graph-only renderer after accepted M1 behavior is reverified.

## Non-goals

- Production light extraction, the shared clustered-light assignment, direct-light
  scheduling, IBL, shadows, or probes (M5).
- General transparent sorting, depth peeling, weighted OIT, layered glass, rough
  refraction pyramids, absorption/thickness reconstruction, or advanced refraction
  (M6).
- Stable asset GUIDs, derived-data cache, texture compression/cooking, BasisU/KTX2,
  WebP/DDS policy, or bindless descriptors (M3 and later).
- Persistent GPU scene, indexed indirect draws, visibility-buffer raster/material
  resolve, or mesh shaders (M7/M8).
- Variant-selection UI or scene serialization. M2 may compile referenced variant
  materials and preserve mappings; M3/M4 own durable selection/serialization.
- Improving the M0 demonstration light to hide a material defect.

## Design and data flow

### Ownership model

```text
glTF importer
  -> SourceMaterial[]                 immutable authored/default provenance
  -> MaterialCompiler
       -> CompiledMaterial            immutable closure recipe + diagnostics
  -> MaterialInstance                mutable allowed overrides, references compiled
  -> packMaterial(instance)
       -> PackedGpuMaterial           backend-neutral fixed layout + texture uses
  -> RHI MaterialHandle
       -> Vulkan buffer/descriptors   backend-owned resources and synchronization
  -> near-term deferred standard OR forward standard/complex/unlit
```

`SourceMaterial` records workflow, every value with origin, texture use (image,
channels, transfer, UV set, transform, sampler), alpha/culling state, extensions,
and unknown/conflicting data. The glTF importer must support both `.gltf` and `.glb`;
M0's textual JSON provenance scanner is replaced by this one source of truth.

`CompiledMaterial` contains a closure class, evaluable factors/texture operations,
feature flags, alpha/queue policy, and structured diagnostics. Texture products stay
symbolic until fragment evaluation. The compiler is pure CPU code with no RHI or
editor dependency.

`MaterialInstance` references one compiled material and stores only sanctioned
factor/texture overrides. An override that activates/deactivates a lobe, changes
alpha class, changes UV requirements, or changes feature flags returns
`RequiresRecompile`; it never mutates the immutable compiled object in place.

`PackedGpuMaterial` is an explicitly versioned, standard-layout backend-neutral
record. It stores evaluated uniform factors, texture-use indices/handles, UV
selection/transforms, closure/feature flags, and diagnostic packing metadata. Vulkan
owns the actual buffer, descriptor sets, alignment, and update retirement. Draw push
constants shrink to transform plus material index/instance index; material factors
are not copied per draw. M7 can later replace the draw transform without changing
material semantics.

### Canonical standard closure

All RGB reflectance and radiance fields presented to shading are linear ACEScg/AP1.
The standard closure is:

```text
diffuseAlbedo : float3   // c_diff, nonnegative reflected diffuse input
f0            : float3   // RGB normal-incidence specular reflectance
f90           : float    // grazing/specular weight; 1 for core MR/spec-gloss
roughness     : float    // authored perceptual roughness [0,1]
shadingNormal : float3   // normalized world-space shading normal
ao            : float    // [0,1], applies to indirect terms only in M5
emissive      : float3   // scene-linear AP1 relative radiance, may exceed 1
flags         : uint     // closure/model and evaluated feature flags
```

The scalar `f90` is the one proposed refinement to ADR-0001. RGB F0 alone cannot
exactly represent `KHR_materials_specular.specularFactor < 1`, because that extension
also changes grazing reflectance. Retaining `f90` keeps the material single-lobe and
avoids incorrectly sending it to the complex path. On plan approval, ADR-0001 should
receive this additive clarification.

Let `sampleSrgb` decode an sRGB texture, `sampleLinear` return raw UNORM data,
`toAP1` transform linear Rec.709/sRGB primaries to ACEScg/AP1, and `sat` clamp a
defined [0,1] parameter. Core metallic/roughness compilation evaluates per fragment:

```text
base      = baseColorFactor.rgb * sampleSrgb(baseColorTexture).rgb * COLOR_0.rgb
alpha     = baseColorFactor.a   * sampleLinearAlpha(baseColorTexture) * COLOR_0.a
m         = sat(metallicFactor * sampleLinear(metallicRoughnessTexture).b)
r         = sat(roughnessFactor * sampleLinear(metallicRoughnessTexture).g)
ao        = mix(1, sampleLinear(occlusionTexture).r, occlusionStrength)
iorF0     = ((ior - 1) / (ior + 1))^2                 // ior default 1.5
specColor = specularColorFactor * sampleSrgb(specularColorTexture).rgb
specW     = sat(specularFactor * sampleLinear(specularTexture).a)
dielF0    = min(iorF0 * specColor, 1) * specW
diffuse   = base * (1 - m)
f0        = mix(dielF0, base, m)
f90       = mix(specW, 1, m)
emissive  = emissiveFactor * emissiveStrength * sampleSrgb(emissiveTexture).rgb

closure.diffuseAlbedo = toAP1(diffuse)
closure.f0            = toAP1(f0)
closure.f90           = f90
closure.roughness     = r
closure.ao            = sat(ao)
closure.emissive      = toAP1(emissive)
```

Missing textures contribute their exact semantic identity values. The compiler does
not bake the old 0.04 roughness clamp. Shared BSDF code derives microfacet alpha as
`max(roughness * roughness, alphaFloor)` only at evaluation and records the frozen
floor in tests.

For archived `KHR_materials_pbrSpecularGlossiness`, the extension is the selected
workflow when present and supported; core metallic/roughness remains fallback source
data, not an additional lobe:

```text
diffuse = diffuseFactor.rgb * sampleSrgb(diffuseTexture).rgb * COLOR_0.rgb
spec    = specularFactor * sampleSrgb(specularGlossinessTexture).rgb
gloss   = sat(glossinessFactor * sampleLinearAlpha(specularGlossinessTexture))

closure.diffuseAlbedo = toAP1(diffuse * (1 - max(spec.r, spec.g, spec.b)))
closure.f0            = toAP1(spec)
closure.f90           = 1
closure.roughness     = 1 - gloss
```

These are the Khronos-defined single-lobe inputs. Values outside finite/range rules,
missing required UV sets, contradictory required extensions, and non-finite compiled
results are errors, not silent clamps. Legal texture/factor multiplication is
performed before closure conversion.

The shared standard reflection function uses one convention in deferred and forward:

```text
F = f0 + (f90 - f0) * (1 - abs(VdotH))^5
fDiffuse  = (1 - max(F.r,F.g,F.b)) * diffuseAlbedo / pi
fSpecular = F * D_GGX(alpha) * G_Smith(alpha)
            / max(4 * abs(NdotV) * abs(NdotL), epsilon)
f = fDiffuse + fSpecular
```

The implementation freezes normal orientation, tangent handedness, N/V/L direction,
roughness-to-alpha, denominator epsilon, and invalid-input handling in CPU vectors
and GLSL tests. AO is carried but is not applied to M2's direct light. Emissive is
added once in scene-linear AP1.

### Classification and extension policy

| Input | M2 disposition |
|---|---|
| Core metallic/roughness, normal, occlusion, emissive, alpha, double-sided | Exact standard deferred/forward or unlit as applicable |
| `KHR_materials_emissive_strength` | Exact standard/complex emissive input |
| `KHR_materials_ior` | Exact F0 for opaque standard; retained IOR for transmissive complex |
| `KHR_materials_specular` | Exact standard via RGB F0 + scalar F90/specular weight |
| `KHR_texture_transform` | Exact per-texture UV transform and optional UV-set override |
| Archived `KHR_materials_pbrSpecularGlossiness` | Supported source workflow and exact standard conversion; explicitly enable/test deprecated fastgltf support or equivalent parser |
| `KHR_materials_clearcoat` | Complex opaque forward when effective coat is nonzero; distinct coat normal/roughness retained |
| `KHR_materials_sheen` | Complex forward when effective sheen is nonzero |
| `KHR_materials_anisotropy` | Complex forward when effective anisotropy is nonzero |
| `KHR_materials_iridescence` | Complex forward when effective iridescence is nonzero |
| `KHR_materials_transmission` | Complex transmissive forward interface; M2 fixes closure/Fresnel inputs but retains bounded M1 transport until M6 |
| `KHR_materials_volume` | Complex volume data retained with transmission; production absorption/thickness transport is M6 |
| `KHR_materials_dispersion` | Complex transmissive data; production dispersion is M6 |

Extension defaults that make a lobe identically zero compile to the standard closure
with a dormant-extension diagnostic. A texture whose possible nonzero values activate
a lobe selects the complex class unless a zero factor proves it unreachable.
Invalid combinations forbidden by Khronos are compiler errors. Optional supported
specular/glossiness takes precedence over core MR as its specification requires.

### Complex closure boundary

`ComplexClosure` is a tagged, versioned union of standard base plus only the active
lobe/transport records. It is not a universal all-features structure. Initial tags:
`Coated`, `Sheen`, `Anisotropic`, `Iridescent`, `ThinTransmission`,
`VolumeTransmission`, `DiffuseTransmission`, and legal combinations approved by the
compiler. Unsupported combinations fail or receive an explicit approximation record;
they never lose a lobe silently.

M2 implements shared surface-BSDF evaluation for reflection lobes under the existing
fixed test illumination. Transmission records expose IOR, specular weight/color,
transmission, thickness/attenuation, and dispersion to the current forward path.
M2 does not claim that the M1 two-bucket refraction algorithm correctly transports
those records; the diagnostic names that M6 limitation.

### GBuffer/surface-cache candidates to measure

No production layout is selected by this plan. All byte counts exclude D32 depth and
assume two frame contexts at 3840x2160 (8,294,400 pixels).

| Candidate | Proposed fields/formats | Color bytes/pixel | Two-frame logical storage | Purpose/risk |
|---|---|---:|---:|---|
| Legacy MR baseline | 3x `RGBA16F` | 24 | 379.69 MiB | Current timing/memory comparator; lacks canonical F0/AO/flags |
| Canonical reference R | diffuse+AO `RGBA16F`; F0+roughness `RGBA16F`; normal XYZ+F90 `RGBA16F`; emissive `RGBA16F`; material/flags `R32_UINT` | 36 | 569.53 MiB | Oracle; approximately +189.84 MiB over legacy before graph reuse |
| Quality production Q | diffuse+AO `RGBA16F`; F0+roughness `RGBA16F`; oct normal `RG16_SNORM`; emissive `B10G11R11_UFLOAT`; material/flags `R16_UINT` | 26 | 411.33 MiB | Preserves FP16 reflectance; approximately +31.64 MiB, mixed-format/MRT cost |
| Compact production C | diffuse+AO `RGBA8_UNORM`; F0+roughness `RGBA8_UNORM`; oct normal `RG16_SNORM`; emissive `B10G11R11_UFLOAT`; material/flags `R16_UINT` | 18 | 284.77 MiB | Approximately -94.92 MiB; AP1 gamut, 8-bit gradients, and flags/ID range are material risks |

Actual Vulkan attachment support, writes/reads, compression, cache behavior, render
pass count, transient reuse, and Nsight bandwidth counters decide the result. Candidate
C is rejected if AP1 values require clipping or if smooth dielectric/normal/highlight
tests show structured error. Candidate Q is not accepted merely because it is high
precision; it must justify extra targets over the legacy footprint. A hybrid material
ID lookup candidate may be added only if it does not resample material textures in
deferred lighting or introduce divergent per-pixel descriptor access without evidence.

At 100 FPS, a simple one-write/one-read lower bound is approximately 39.8 GB/s for
the legacy color data, 59.7 GB/s for R, 43.1 GB/s for Q, and 29.9 GB/s for C. These
are comparison aids, not measured DRAM traffic.

### Contract with the future hybrid renderer

M2 selects a conventional deferred layout for the current production renderer and
retains R as an oracle. It does not select Iridium's permanent opaque visibility
architecture. Under ADR-0006, the selected packed layout is also the canonical
surface-cache candidate produced by a later visibility-buffer material resolve.

The staged destination is:

```text
M7/M8 GPU visibility
  -> standard opaque depth + visibility identity
  -> attribute/material resolve using M2 compiled materials
  -> M2 canonical packed surface cache
  -> M5 clustered deferred lighting

complex opaque / classified transparency
  -> M2 compiled complex closure
  -> M5 shared cluster/light records
  -> clustered forward shading
```

M5 owns the single shared clustered-light representation. M7 owns the first indexed
visibility-buffer experiment after stable GPU-scene and geometry identities exist;
M8 makes mesh shaders an alternate emitter of the same representation. A fused
material-plus-lighting resolve is only a later measured alternative. Except during
validation, production does not write both a full conventional GBuffer and a
visibility buffer without evidence that downstream reuse repays the duplication.

M2 packing therefore uses stable, versioned material indices and backend-neutral
closure semantics, but it does not invent M3 asset GUIDs, M7 geometry identities,
bindless policy, barycentric payloads, or derivative reconstruction.

## Risks, fallback, and rollback

- **Source/compiler split grows into M3:** use import-local identities and current
  synchronous loading only. Do not introduce GUIDs, cooker containers, or DDC.
- **F0-only closure loses `KHR_materials_specular`:** add scalar F90/specular weight,
  test grazing vectors, and clarify ADR-0001 after approval.
- **Texture-use semantics conflict with image caching:** key current uploads/views by
  image plus transfer/format and sampler; M3 may later deduplicate storage/views.
- **Correct samplers increase texture memory/upload work:** generate only the mip
  chains required by source sampling, categorize the delta, and leave compression and
  offline mip cooking to M3.
- **Generated tangent disagreement:** use a validated MikkTSpace-compatible path and
  compare authored/generated normal-detail fixtures; never silently substitute the
  current positive-handed approximation.
- **Specular/glossiness importer is compile-disabled:** explicitly enable and test
  fastgltf's deprecated extension path or implement an equivalent source adapter;
  never infer it from core MR fallback.
- **Complex shader permutation explosion:** use tagged active records and measured
  feature variants; do not put every lobe in every shader/GBuffer.
- **Correct car data still looks wrong:** retain source diagnostics and fixed M0 light;
  do not change lighting or invent emissive/glass intent.
- **GBuffer reference cost:** keep it selectable as an oracle, measure Q/C, and allow
  the production decision to remain R if packed candidates fail fidelity gates.
- **Manual-path deletion masks regression:** removal is last, after matched M1
  transport/capture/timing/memory evidence and graph-default tests.
- **Licensed car cannot gate release:** duplicate every required behavior in tracked
  procedural or Khronos-licensed fixtures; car remains supplemental evidence.
