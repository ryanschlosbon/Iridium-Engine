# M2.6a Editor Output and Transform UX Maintenance

Status: Complete on 2026-07-22.

This owner-requested maintenance slice sits between M2.6 and M2.7. It fixes editor
usability without changing material closure semantics, the M1 output architecture,
or the M2.7 diagnostics scope.

## Delivered behavior

- **Window > Project Settings** now contains a real **Display and HDR** section
  instead of placeholder project/physics controls.
- Scene exposure is live-editable from -16 to +16 EV for every transport.
- **UI / paper white** is live-editable from 80 to 1000 nits and **display peak**
  from paper white to 10,000 nits. Reset restores the accepted 0 EV, 203-nit,
  1000-nit defaults. The controls remain visible in SDR so their values and inactive
  state are explainable rather than disappearing.
- Output changes update output-pass constants immediately. Paper-white changes also
  update the ImGui display-linear scale, so editor white tracks the selected Windows
  HDR reference white without applying scene exposure or tone mapping to UI.
  Peak changes update `VK_EXT_hdr_metadata` when HDR10 metadata is available.
- Transport remains a visible read-only runtime fact because changing swapchain
  format/color space requires the existing startup selection and renderer rebuild.
  Live values are session settings; CLI values remain the durable startup mechanism
  until project settings persistence is owned by the asset/project milestone.
- The settings panel now states prominently when Iridium is outputting SDR despite
  Windows HDR being enabled. Exclusive fullscreen is not required; an scRGB or HDR10
  startup transport and renderer restart are required by the current architecture.
- The transform inspector now owns its editor drawer for position, rotation, and
  scale. **Uniform scale** collapses XYZ to the current X value when enabled and a
  single scalar thereafter updates all three axes and marks the transform dirty.
  This UI-only toggle is not added to runtime component or scene data.
- Scalar, integer, and vector numeric controls retain drag adjustment while allowing
  exact text entry by double-click or Ctrl-click. Bounded values clamp typed input to
  their valid range and advertise the interaction in a hover hint.

## Verification

- Debug and Release configurations build successfully and pass 20/20 CTest tests.
- Color reference tests cover 203-nit (`2.5375` scRGB) and user-dimmed 120-nit
  (`1.5` scRGB) UI white, plus source contracts for the live backend update path and
  editor control.
- 3840x2160 Debug Vulkan validation runs are clean for SDR, scRGB at 120/1000 nits,
  and HDR10 at 120/1000 nits. Each run exercises the runtime output-settings setter
  after ImGui initialization.
- The change adds no render pass, image, descriptor, or persistent allocation.
  With the settings window closed and no edit pending, the GPU path is unchanged;
  the CPU adds one predictable dirty-flag check per editor frame.

## Boundaries and rollback

The RHI exposes only output-domain values; Vulkan metadata and ImGui backend details
remain in the Vulkan backend. UI is still composed display-linearly after the scene's
single final output transform. Reverting this slice restores startup-only controls
without affecting material or graph data. M2.8 is the next material slice.
