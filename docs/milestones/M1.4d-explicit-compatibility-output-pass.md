# M1.4d Evidence: Explicit Compatibility Output Pass

- Status: Accepted implementation slice
- Date: 2026-07-19
- Parent slice: M1.4 scene-linear HDR and transparent composition

## Result

The renderer now has an explicit full-screen scene-to-output boundary between
transparent composition/capture and ImGui/present. M1.4d's output shader is identity;
M1.4e will move the legacy fitted curve into it when lighting becomes scene-linear.
The viewport descriptor reads the output resource rather than scene color, so future
output operators cannot feed display values back into lighting or transparency.

The compiled graph now has ten passes, nine logical resources, six physical slots,
and 27 transition intents. `output.compatibility` is FP16 and reuses the expired
`scene.opaque-copy`/GBuffer-compatible physical slot, so graph-mode memory does not
increase. Pass recording and telemetry expose `compatibility-output`,
`gpu.output.compatibility`, `cpu.render.record.compatibility_output`, and
`draw.recorded.output` explicitly.

The selectable legacy path owns a separate output image because its manual allocator
does not alias lifetimes. That fallback remains below M0's memory ceiling but is not
the intended steady-state resource policy.

## Verification and impact

- Debug and Release full suites pass 12/12 tests.
- 4K graph-mode nested transparency and legacy-mode material lab are Vulkan
  validation-clean.
- The pass is identity and capture remains deliberately before it, so the accepted
  M1.4c scene artifact is unchanged. There is no intentional presented-image change;
  a final-output capture oracle remains M1.5 work.
- Three Release 4K nested-transparency runs measured the output pass at 0.0399 ms GPU
  and 0.0021-0.0022 ms CPU recording. Total GPU median is 0.4752 ms versus the M1.3
  0.3984 ms baseline, a cumulative +0.0768 ms that remains inside M1.4's +0.10 ms
  allowance. Median normal-frame allocations remain zero.
- Graph steady memory remains 663,553,868 B requested / 668,470,976 B committed.
  Legacy fallback memory is 928,974,284 B requested / 935,857,488 B committed, still
  below the accepted M0 total.

Evidence is under `out/profiles/m1.4d-*.jsonl`.
