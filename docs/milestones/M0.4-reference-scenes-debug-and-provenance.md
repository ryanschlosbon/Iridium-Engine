## Outcome

Iridium now has a versioned M0-only benchmark manifest, five required redistributable
fixtures covering material, transparency, current lighting, CPU scaling, and temporal
inputs, plus an explicitly optional licensed sample-car diagnostic. Benchmark launches
verify source hashes before upload, use a fixed manifest camera and procedural linear
environment, ignore interactive camera input, derive projection aspect from the actual
render extent, clear selection overlays, use frame-indexed motion, and record the
fixture, camera, manifest hash, content hashes, debug view, and output domain.

The importer retains CPU-only material provenance in an `AssetManager` sidecar indexed
like the model's material bindings. It does not add source paths, warnings, or editor
data to the RHI material contract or Vulkan payload. A separate editor panel displays
source values and explicit/default origin, texture identity/channels/UV/sampler/color
interpretation, consumed and ignored extensions, actual fallback binding, runtime
pipeline state, and the current backend's declared push-constant inputs.

The deferred lighting pass exposes final, base-color, decoded-normal, roughness,
metallic, emissive, and depth views through a backend-neutral enum. Diagnostic G-buffer
views suppress selection and forward transparency so they cannot be mistaken for
complete material coverage. Emissive uses `x / (1 + x)` solely for display, and depth
is raw nonlinear Vulkan device depth. Material ID and motion vectors remain explicitly
unavailable because the current renderer has neither target.

## Durable benchmark contract

`assets/benchmarks/m0/manifest.v1.json` contains the effective camera, environment,
grid/motion factory, run length, expected behavior, unavailable axes, and content
hashes. `.gitattributes` forces LF for benchmark files so byte hashes remain stable
with Windows `core.autocrlf`.

Required fixtures:

| Fixture | Purpose | Stable current workload |
|---|---|---|
| `material_lab_v1` | explicit versus glTF-default factors, ignored coating extensions, emissive/transmission | 1 instance, 5 submeshes, 4 opaque, 1 transparent |
| `transparency_v1` | disconnected overlapping alpha/transmission layers | 1 instance, 4 submeshes, 1 opaque, 3 transparent |
| `lighting_legacy_v1` | low neutral environment plus current hardcoded shader light | 1 instance, 5 submeshes |
| `geometry_cpu_v1` | current extraction/sort/per-draw scaling | 128 moving instances, 640 submeshes, 128 changed transforms per frame |
| `temporal_proxy_v1` | frame-indexed object/camera motion and a frame-120 cut | 1 moving instance; motion vectors/reconstruction unavailable |

The material fixture intentionally does not claim normal-map detail, absorption, or a
specular/glossiness workflow. The transparency fixture does not claim nested closed
shells, particles, production rough refraction, or off-screen fallbacks. The CPU
fixture does not claim LOD transitions. These omissions are stored in the manifest,
not left implicit.

`sample_car_local_v1` is stored as an optional local diagnostic record with its
CC-BY-NC-SA-4.0 restriction and existing tree-manifest SHA-256
`9ff1c6e9a6c66a15e89b616a1e9d2cf0cde634745245083c88fae3621e5d6c1d`.
It is not a required/commercial acceptance asset. The local HDRI remains unsuitable
as a required fixture because repository license provenance is absent.

## Material findings made durable

Automated optional assertions retain the current sample-car diagnosis:

- red paint materials 0 and 36 explicitly author red base color and roughness but
  omit metallic, so glTF supplies `1.0`; clearcoat is present but not consumed, and
  material 0's specular extension is also not consumed;
- window material 6 is `BLEND`, omits metallic and therefore receives `1.0`, and has
  no transmission extension, so the forward path treats it as a nearly opaque metal;
- lens materials 3 and 4 are `BLEND`, omit metallic and receive `1.0`, explicitly use
  transmission `1.0`, while the forward shader still uses its hardcoded IOR.

The panel calls retained numeric values declared push-constant inputs rather than
claiming they are final G-buffer values. Texture multiplication, vertex color, normal
mapping, and shader clamps occur later and require capture evidence.

## Verification evidence

Debug and Release both build cleanly and pass six CTest targets. New tests cover:

- glTF explicit values versus exact format defaults;
- texture identity, channels, color interpretation, UV set, sampler, occlusion, and
  source-present/runtime-fallback reporting;
- applied, known-but-unconsumed, and unknown extension disposition;
- runtime binding and declared push-input copies;
- optional Alfa paint/window/lens provenance;
- SHA-256 known vector, manifest/content verification, duplicate load determinism,
  frame-120 camera cut, frame-indexed object motion, explicit-zero run options, and
  adversarial instance-grid overflow.

Validation-enabled bounded runs covered all five fixtures and all six new diagnostic
views without Vulkan validation output. Runtime counter cross-checks were:

| Fixture | instances | submeshes | opaque | transparent | changed transforms | recorded transparent depth/forward |
|---|---:|---:|---:|---:|---:|---:|
| material | 1 | 5 | 4 | 1 | 0 | 1 / 1 |
| transparency | 1 | 4 | 1 | 3 | 0 | 3 / 3 |
| lighting | 1 | 5 | 4 | 1 | 0 | 1 / 1 |
| CPU | 128 | 640 | 512 | 128 | 128 | 128 / 128 |
| temporal | 1 | 5 | 4 | 1 | 1 | 1 / 1 |

Two fresh `material_lab_v1` launches matched fixture/revision, camera, manifest hash,
content hash, frame count, and every counter value/status in all eight measured frames.
The second check used explicit `--warmup-frames 0`, which remained zero rather than
being replaced by the manifest default.

The final Release exact-4K attribution smoke used a visible borderless 3840x2160
surface, validation off, and CPU/GPU telemetry on:

Pixel probes through the four opaque material primitives agreed with the importer and

The emissive view is black for this fixture because its only emissive material is in
the forward transparent path and opaque diagnostic views deliberately suppress that
path. That is a recorded fixture-coverage limitation, not evidence of opaque emissive
support.

Representative Release captures of all five required fixtures retained their
manifest camera and expected composition. Their final image hashes are recorded in
`docs/milestones/M0.5-capture-comparison-and-baseline.md`. A Debug validation capture
also completed without Vulkan validation output. This closes M0.4's readback-dependent
acceptance gate. Nsight Graphics/RenderDoc descriptor inspection remains unavailable,
but observed target pixels now validate the current data path sufficiently for the
truthful M0.4 scope.
