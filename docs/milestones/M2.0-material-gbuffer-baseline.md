## Decision

M2.0 is accepted. It changes no renderer, material, shader, RHI, or Vulkan behavior.
It freezes the source/material coverage matrix, exact run contract, current graph-
default mismatch, accepted M1 images, current GBuffer/deferred timings, draw/material
counts, and memory state needed by later M2 comparisons.

The production graph remains opt-in through `--render-graph`; an argument-free launch
still selects the deprecated manual path. A passing characterization test records
that mismatch. M2.10 remains the gate that makes graph execution unconditional and
removes the second renderer after parity evidence.

## Material-lab Release baseline

Both required runs use a visible borderless 4K window, 500 warm-up frames, 10,000
measured frames, validation disabled, GPU timestamps enabled, and warm steady-state
cache labeling. Medians and p99 values are milliseconds.

| Metric | Graph median / p99 | Manual median / p99 |
|---|---:|---:|
| CPU frame | 1.9598 / 42.0403 | 0.7205 / 10.2292 |
| CPU extraction | 0.0015 / - | 0.0008 / - |
| CPU GBuffer recording | 0.0304 / - | 0.0215 / - |
| CPU submission | 0.0482 / - | 0.0424 / - |
| GPU frame | 0.7232 / 22.4647 | 0.4546 / 9.5625 |
| GPU opaque GBuffer | 0.0102 / 0.0174 | 0.0092 / 0.0123 |
| GPU deferred lighting | 0.0922 / 0.1034 | 0.0942 / 0.1024 |
| GPU UI | 0.3338 / 22.0887 | 0.1147 / 9.1914 |

Both paths request four opaque and one transparent draw, five unique materials/five
material binds, and report zero steady-frame C++ allocations in the sampled final
frame. Graph and manual GBuffer/lighting pass medians agree closely. Whole-frame p99
is dominated by UI/presentation variability and is not suitable as a sub-0.05 ms
material decision oracle. Later M2 performance gates use matched pass-local evidence,
five independent repetitions, and Nsight attribution where layout/resource ownership
changes.

A first automated run used a hidden window and showed compositor/presentation
throttling, especially on the graph UI pass. Those profiles are retained as
`*-hidden-diagnostic.jsonl` but are excluded from the accepted performance table.
This is why the final run contract follows M0's visible-borderless protocol.

## Optional sample-car baseline and risk

The local car remains supplemental because of its CC-BY-NC-SA-4.0 license. Source
`scene.gltf` hashes to
`be2981b07dc2bb440627a4bca78e71eec9792cff527ab8652cb230831e32b324`.
The M2 audit remains the canonical source interpretation: 87 materials, 118 source
primitives, 25 omitted metallic factors, 72 normal textures, two MR textures, one AO
texture, five BLEND materials, ignored coating/specular inputs, conflicting
metallic-plus-transmission lenses, and zero authored emissive materials.

The 10,000-frame graph run submits 87 runtime submeshes after current merge-by-
material behavior: 82 opaque and five transparent, 87 unique materials, 174 material
binds, and 612,836 triangles. Current measurements are:

| Metric | Graph Release median / p99 |
|---|---:|
| CPU frame | 37.4914 / 89.7817 ms |
| CPU extraction | 0.0029 ms median |
| CPU GBuffer recording | 0.0725 ms median |
| CPU submission | 0.0655 ms median |
| GPU frame | 21.5604 / 65.9506 ms |
| GPU opaque GBuffer | 0.1925 / 0.2120 ms |
| GPU deferred lighting | 15.5064 ms median |
| GPU forward shading, both buckets | 0.1034 ms median |
| Requested / committed live | 1319.059 / 1324.219 MiB |

A bounded manual-path comparator also shows the large current full-screen cost
(`gpu.lighting.deferred` 18.7658 ms and foreground copy 18.6870 ms median). It is
therefore not graph-specific and was not introduced by M2.0. M0 historically measured
the car near 0.383 ms deferred lighting and 0.041 ms foreground copy. GPU clocks/power
are unavailable in the current telemetry, so the cause may include current driver/
power state or intervening renderer behavior and is not assigned without external
evidence.

This finding is frozen rather than hidden. M2 must not add lighting/HDRI special cases
to repair it: M5 owns production lighting. Material/GBuffer changes still compare the
car's GBuffer, closure-class, forward, CPU, draw, and memory deltas, while performance
acceptance relies on controlled material fixtures until the full-screen anomaly is
independently attributed.

## Rollback and next slice

M2.0 adds data contracts, tests, and documentation only. Rollback is removal of those
files and test cases; no runtime path needs restoration.

M2.1 is next: introduce a pure CPU `SourceMaterial` model and deterministic `.gltf`
and `.glb` ingestion while leaving renderer, RHI, Vulkan, and shaders unchanged.
