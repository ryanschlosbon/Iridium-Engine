# M1.6b Acceptance: Live Output Capability Discovery

- Status: Accepted
- Date: 2026-07-22
- Reference GPU: NVIDIA GeForce RTX 4090, driver 610.74
- Runtime output: unchanged SDR

## Implemented behavior

The Vulkan instance enables `VK_EXT_swapchain_colorspace` when exposed, and the
logical device enables `VK_EXT_hdr_metadata` when exposed. Both are optional and
reported independently. Swapchain creation now enumerates the live surface through
the accepted M1.6a selector, publishes every exact supported transport, and still
requests the mandatory SDR transport only.

CPU profile headers now serialize the supported transports, requested and effective
transport, fallback diagnostic, and both extension-enable states. This makes output
capability evidence reproducible without inferring HDR from the selected format.

## Reference-system evidence

The validation-enabled 3840x2160 probe is
`out/evidence/m1/m1.6b-capabilities/live-sdr.jsonl`. Its header records:

- supported transports: `sdr_srgb`, `scrgb_linear`, `hdr10_pq`;
- requested/effective transport: `sdr_srgb` / `sdr_srgb`;

  `VK_COLOR_SPACE_SRGB_NONLINEAR_KHR`;
- `VK_EXT_swapchain_colorspace`: enabled;
- `VK_EXT_hdr_metadata`: enabled;
- fallback diagnostic: empty.

The 4K Debug graph/color-volume run completed with Vulkan validation and no warning
or error. Focused `CpuProfilerTests` and `VulkanOutputTransportTests` pass in Debug
and Release, and both engine configurations link.
No non-SDR swapchain is selected yet. Visual output, GPU/CPU frame cost, and memory
are unchanged by construction. The live evidence resolves the platform branch:
scRGB and HDR10 are both implementable on this machine; scRGB remains the first
approved runtime transport. M1.6c first pins the shared production HDR transform.
