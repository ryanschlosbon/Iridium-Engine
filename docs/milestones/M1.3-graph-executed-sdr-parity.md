# M1.3 Acceptance: Graph-Executed SDR Parity and Transient Ownership

- Status: Accepted
- Accepted: 2026-07-19
- Baseline commit: `30252593f8fdd2de5dffbb8da31bb570ff49a7c0`
- Worktree: dirty by design; all pre-existing M0 and RHI-refactor work preserved
- Reference system: RTX 4090, Core i9-14900K, 64 GB DDR5, 3840x2160

## Accepted architecture

The opt-in `--render-graph` mode now executes the existing SDR renderer through the
compiled graph. The graph owns the offscreen images for two fenced frame contexts;
`VulkanFrameTargets` owns only the compatible views, framebuffers, and sampler in
that mode. Swapchain UI framebuffers remain indexed by acquired swapchain image.
The legacy recorder remains selectable by omitting the flag, and
`--render-graph-shadow` remains a mutually exclusive diagnostic mode.

The executor checks compiled pass order, emits Vulkan image transitions immediately
before active passes, preserves physical-slot state across resource reuse, and lets
empty transparency buckets skip their passes without inventing state changes.
Capture transitions participate in the same state tracker. The imported swapchain
transition is intentionally realized by the UI render pass's Vulkan initial/final
layout contract; the graph remains the ordering owner while Vulkan-specific
presentation semantics remain in the backend.

The source audit corrected three integration assumptions before acceptance:

- Each transparency layer requires its own scene-color copy.
- `glassDepth` is sampled by the forward pass and therefore requires sampled usage.
- Sampled depth images require `DEPTH_STENCIL_READ_ONLY_OPTIMAL`, not the color
  shader-read layout. Descriptors, runtime transitions, and a regression assertion
  now agree on that rule.

Resize rebuilds the compiled topology and graph allocation set after device-idle
swapchain replacement. Allocation failure preserves the previous active set in the
resource-pool contract, and initial graph allocation failure falls back to legacy
frame targets. Fence completion retires old frame-context resources.

cover deterministic topology, access/format mapping including sampled-depth layout,
pass-order rejection, frame bounds, extent rebuild, fence-scoped retirement,
allocation-failure cleanup, cache statistics, and fallback configuration. Runtime
source inspection additionally verified that out-of-date acquisition rebuilds before
graph execution begins and suboptimal presentation rebuilds only after the completed
graph frame.

warmup frames, 3,000 measured frames, CPU profiling, and GPU timestamps. Durations
below are per-run medians in milliseconds.

The median-of-run-medians graph delta is -0.0077 ms CPU (-1.45%) and -0.0029 ms

are `out/profiles/m1.3-final-{legacy,graph}-{1,2,3}.jsonl`.

## Memory evidence

Graph execution reports 663,553,868 B requested (632.814 MiB) and 668,470,976 B
committed (637.504 MiB), including 663,552,000 B requested / 668,467,200 B committed
for fourteen graph-owned render-target allocations. Shadow-graph allocation is zero.

Against the same renderer's former three-swapchain-image ownership
(995,329,868 B requested / 1,002,704,576 B committed), frame-context ownership saves
331,776,000 B requested and 334,233,600 B committed, a 33.33% reduction. The present
topology has seven engine-owned physical slots for seven simultaneously required
physical resources, so it claims no aliasing reduction; the measured reuse benefit
is the reduction from three swapchain images to two fenced frame contexts.

## Acceptance decision and remaining risks

M1.3 is accepted. It is validation-clean across every M0 fixture, bit-exact to M0,
below the CPU/GPU regression limits, allocation-free in normal frames, and materially
below the memory ceiling. The legacy fallback remains available.

The remaining deliberate risks are bounded: swapchain layout realization is still
a Vulkan render-pass contract; conditional capture is integrated into resource state
but is not a first-class graph pass; and graph mode remains opt-in until the M1.7
legacy-disposition gate. M1.4 may now change image interpretation intentionally, but
must retain this executor, validation, timing, and memory evidence as its baseline.
