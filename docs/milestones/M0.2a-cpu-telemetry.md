## Outcome

M0.2a adds a bounded, hierarchical, thread-safe CPU event collector without a
global mutex per marker. The application owns the shared frame ID and passes the
collector through backend-neutral render configuration. Vulkan-specific frame
wait, acquire, upload, command-recording, submission, and presentation sites use
the stable names frozen in M0.1.

Collection defaults off in Release and on only when explicitly requested. Vulkan
validation is now an explicit run setting: Debug defaults on and Release defaults
off, with command-line overrides in both configurations. Bounded runs support a
warm-up interval, measured-frame count, requested window size, hidden or visible
borderless surfaces, and a clean JSON Lines export after renderer shutdown.

The exporter distinguishes requested window size from the actual Vulkan render
extent. This caught and rejected two invalid measurement setups during the gate:

- a decorated 3840x2160 window was clamped to a 3840x2130 render extent;
- an exact-size hidden surface switched between normal and compositor-throttled
  presentation states.

Final overhead evidence therefore uses a visible, borderless surface whose
backend-reported extent is exactly 3840x2160. Hidden-surface results and all runs
that did not report the exact target extent were discarded from the gate.

## Architecture and behavior

- `CpuProfiler` preallocates bounded per-frame storage when enabled, stores at
  most 512 events and 64 counters per frame, and retains the last 512 completed
  frames.
- Cross-thread event writes use atomic slot allocation. Frame close never waits
  for a worker marker; an unfinished frame is dropped and counted.
- Overflow drops new detail while preserving already recorded data and increments
  explicit event, counter, or nesting diagnostics.
- Event names are stable static-lifetime strings. Events retain thread, parent,
  frame, start, and duration identity.
- Percentiles use nearest rank. Repeated occurrences of one stable range within a
  frame are summed before per-frame aggregation, so two fence waits do not become
  two statistical frames.
- JSONL contains a run header, retained frame records, and a run summary. It
  reports retained and total completed counts separately and lists unavailable
  metadata rather than substituting zero.
- The backend reports its actual render extent through the RHI. Run metadata does
  not infer resolution from the requested GLFW dimensions.
- The current requested draw, instance, submesh, light, transparency, upload, and
  changed-data availability counters are exported. Actual recorded-work counters
  remain the next M0.2b slice.

## Verification evidence

### Automated tests and builds

Both `x64-debug` and `x64-release` were configured and built with the documented
MSVC/Ninja toolchain. CTest passed 3/3 executables in both configurations:

- the existing Stage 3 renderer architecture cases;
- CPU profiler disabled behavior, hierarchy, counters, multithread stress,
  overflow, active-scope frame dropping, ring wraparound, explicit frame IDs,
  nearest-rank aggregation, and JSONL structure;
- application configuration parsing and invalid-input rejection.

The multithread test records 256 events from eight threads in one frame without
drops or nesting errors. The ring test records 517 frames, retains 512 in order,
and reports all 517 as completed.

### Vulkan validation and runtime export

A final bounded Debug run used validation, 16 warm-up frames, and 64 measured
frames at 1280x720. It exited normally, emitted no validation messages, exported
shared frame IDs 17 through 80, and reported zero dropped frames, overflow, or
nesting errors.

A final Release export used validation off, a visible borderless exact
3840x2160 render extent, 500 warm-up frames, and 1,000 measured frames. It exited
normally and reported:

- 1,000 completed frames and 512 retained frames;
- retained shared frame IDs 989 through 1500;
- zero dropped frames, dropped events, dropped counters, or nesting errors;
- one per-frame aggregate sample for ranges that can occur multiple times, such
  as `cpu.renderer.frame_fence_wait`.

Generated JSONL evidence is kept under ignored `out/profiles/` build output and is
not a redistributable benchmark fixture or milestone baseline.

### Release overhead

The exact-4K application A/B interleaved collection-disabled and core-collection
runs for five repetitions. Every run used 500 warm-up and 1,000 measured frames,
Release, validation off, a visible borderless surface, and a backend-reported
3840x2160 extent.

| Repetition | Disabled average | Enabled average | Paired delta |
|---|---:|---:|---:|
| 1 | 1.209466 ms | 1.200453 ms | -0.009013 ms |
| 2 | 1.199592 ms | 1.208723 ms | +0.009131 ms |
| 3 | 1.200218 ms | 1.203986 ms | +0.003768 ms |
| 4 | 1.196545 ms | 1.200681 ms | +0.004136 ms |
| 5 | 1.201087 ms | 1.199985 ms | -0.001102 ms |

The disabled median was 1.200218 ms and enabled median was 1.200681 ms. The
difference between condition medians was +0.000463 ms (0.039%). The more
conservative median paired delta was +0.003768 ms (0.314%).

A separate 10,000-frame Release microbenchmark exercises the current 18 child
markers, root marker, 11 counters, frame begin/end, and ring commit:

| Mode | Median | p99 |
|---|---:|---:|
| Collection disabled | 0.0001 ms | 0.0002 ms |
| Core collection enabled | 0.0011 ms | 0.0017 ms |
| Enabled minus disabled | +0.0010 ms | +0.0015 ms |

The disabled absolute cost is below 0.05 ms. The enabled application impact is
below 0.10 ms and 2%, and the stricter observed paired median is also below 0.05
ms and 1%.

These are CPU instrumentation-overhead results, not renderer throughput evidence.
GPU timestamps and the deterministic benchmark fixtures required for a gameplay
baseline do not exist yet.

## Remaining limitations and next slice

- Only the last 512 full frames are retained. Long-run summary streaming or
  online aggregation remains required before the 10,000-frame M0 baseline.
- GPU identity, timestamps, memory, swapchain format/color space, present mode,
  fixture/camera identity, and capture outputs remain explicitly unavailable.
- Requested frontend counters are present, but actual draw, triangle, material
  bind, pipeline bind, transparency-bucket, and changed-transform counts are not
  complete. M0.2b owns them.
- Runtime collection and JSONL export are separate, but no editor profiler panel
  exists. Presentation remains M0.2c after counter semantics are stable.
- No visual output was accepted in this instrumentation slice. Deterministic
  fixtures, captures, and comparison evidence remain M0.4 and M0.5.

No ADR was superseded or added by M0.2a.
