# M2.10 - Production Cutover and Manual Renderer Removal

- Status: Complete
- Accepted: 2026-07-25
- Parent: `M2-material-compiler-and-closures.md`

## Production state

Render-graph execution and schema-2 canonical materials are unconditional. The
manual renderer, legacy material shaders, old material push fields, and the
`--render-graph`, `--render-graph-shadow`, and `--canonical-materials` switches are
removed. Those arguments are deliberately rejected. Source-control reversal is the
rollback; production does not carry a second renderer.

Opaque standard, opaque complex, and transparent complex surfaces use three explicit
queues. Opaque complex materials depth-test and depth-write in `forward-opaque`;
only coverage blend/transmission enters the transparent layer path. This corrected
the car geometry loss and material-order occlusion reported during acceptance.

A later M3-precondition audit found an independent standard-deferred coverage
regression: the canonical-routing override accidentally disabled depth writes for
the `Opaque` queue while retaining them for `ForwardOpaque`. Material 84 on the
sample-car tires therefore executed and wrote material attachments without
establishing depth, causing lighting to return the environment. The correction
derives depth writes from the final queue (`Opaque` and `ForwardOpaque` true,
`Transparent` false) and adds a material-ID/depth capture gate. Full evidence,
source primitive ranges, hashes, and verification are recorded in
`M2-acceptance-report-2026-07-25.md`.

Debug views include forward materials. “Diffuse / Base Color” distinguishes canonical
deferred diffuse albedo from complex-forward source base color, and metallic is
explicitly a forward/source diagnostic because deferred pixels store RGB F0.

Selection writes a mask only, disables culling for thin/two-sided pieces, and is
outlined after all scene passes in the final output transform. The selected mesh
retains its normal shading. A deterministic `--select-benchmark-entity` option exists
only to make this editor behavior captureable in benchmark fixtures.

## HDR/editor behavior

The editor uses the same swapchain/output pipeline as a game build. Exclusive
fullscreen is not required:

- default `sdr` uses a Windows sRGB swapchain;
- `--output-transport scrgb` is the recommended Windows HDR editor transport;
- `--output-transport hdr10` tests direct Rec.2100 PQ output and HDR metadata.

Transport selection currently occurs at startup because changing swapchain format,
render passes, and pipelines requires a renderer rebuild. Project Settings always
shows active transport, exposure, paper white, and peak. Exposure affects scene
mapping; paper white independently controls color-managed UI brightness. A separate
HDR popup viewport is not required and would add another swapchain/calibration
boundary.

## Deliberate milestone boundaries

The sample car contains coated conductors and transmissive materials with glTF
defaults that are now faithfully visible in diagnostics. M2's single environment
radiance sample no longer extinguishes rough-metal energy, but it is not production
IBL: M5 still owns irradiance, prefiltered specular IBL, BRDF integration, direct
lights, clusters, shadows, and probes. M6 still owns general transparent ordering,
layered glass, OIT/depth peeling, and advanced refraction. No car-specific material,
light, or glass exception was added.
