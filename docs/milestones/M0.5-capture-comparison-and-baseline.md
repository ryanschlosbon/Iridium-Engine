## Outcome

M0.5 implements deterministic readback of the current Vulkan scene target, stable
image and metadata artifacts, and a standalone comparison tool. It also records a
fresh 4K Release baseline for all five required M0 fixtures. The implementation,
automated tests, validation capture, deterministic image evidence, and internal
performance baseline pass their gates. Nsight Graphics 2026.2 GPU Trace also measured
the same Debug Utils ranges on two consecutive 4K frames. All 16 external/internal
duration pairs agreed exactly or within one observed 32 ns timing/export quantum,
closing the external attribution gate.

`docs/milestones/M0-acceptance-audit-2026-07-18.md` subsequently reopened M0.5 and

## Capture contract

`--capture-frame INDEX` and `--capture-directory PATH` are paired options and require
`--benchmark`; the captured measured-frame index is zero based. Capture occurs after
legacy transparency and before UI, from the actual current `litScene` target. The
source is honestly labelled `legacy_display_referred_srgb_target`; M0 does not invent
the scene-linear FP16 capture that becomes meaningful after M1.

The backend queues an image-to-host-buffer copy in the current command buffer. It
does not add a normal-frame wait. Each pending readback belongs to a frame slot and is
harvested only after that slot's existing fence wait. The frame fence remains signaled
until command recording has completed and submission is ready, so a capture exception
cannot leave cleanup waiting on a reset-but-never-submitted fence. Collection rejects
use during an open frame. End-of-run collection explicitly drains outstanding frames.
Capture buffers are accounted separately as
`buffer.capture_readback` allocations with `capture_request` lifetime.

Artifacts use a dependency-free, uncompressed, top-left-origin 32-bit TGA plus a
JSON sidecar. The stable stem is:

```text
<fixture>__r<revision>__<camera>__<debug-view>__<width>x<height>__mf<frame>
```

The writer refuses to overwrite either artifact. The sidecar records image SHA-256,
encoding/origin/source format, exact capture point, transfer/primaries/range, legacy
output operator and exposure note, source commit/branch/dirty state, build and
validation state, profiling state, requested and benchmark-state frame indices,
fixture/revision/camera, manifest and content hashes, debug-view semantics, and
explicitly unavailable fields. It marks the capture frame perturbed and unsuitable
for percentile timing.

## Comparison contract

`IridiumImageCompare` reads the strict TGA subset and reports:

- per-channel RGBA MAE, RMSE, and maximum code difference;
- p95/p99 maximum-RGB pixel difference;
- changed-RGB-pixel fraction at a configurable code threshold;
- fixed non-overlapping 8x8 luma SSIM after sRGB decoding to linear Rec.709;
- a deterministic grayscale difference heatmap.

Thresholds are inclusive. Defaults are intentionally strict: maximum absolute code
difference 0, changed-pixel fraction 0, and minimum mean luma SSIM 1.0. Exit codes are
0 for pass, 1 for threshold failure, and 2 for malformed input or contract error.

Threshold evaluation normally requires both JSON sidecars. Each actual image is
re-hashed against its own sidecar before comparing pixels. The tool then rejects
incompatible encoding/source pixel format/dimensions, capture point/color domain/
transfer/primaries/range/output operator, fixture/revision/camera/manifest/content
hashes, measured and benchmark-state frame, or debug-view name/semantics. Explicit
`--allow-missing-metadata` is permitted only when both sides lack metadata. Reports
and heatmaps also refuse overwrite or path aliasing. Capture pairs and comparison
output pairs are staged under temporary names and rolled back on ordinary
write/rename failure rather than deliberately leaving half an artifact pair.

## 4K Release performance baseline

Each long fixture run used its manifest warm-up (500 frames), 10,000 measured frames,
a visible borderless backend-reported 3840x2160 extent, validation disabled, and CPU,
GPU, counter, and memory collection enabled. The temporal proxy intentionally uses 0
warm-up and 240 measured frames.

```powershell
out/build/x64-release/bin/IridiumEngine.exe `
  --benchmark <fixture-id> --profile-gpu `
  --profile-cpu-output out/profiles/m05-final-<fixture>.jsonl `
  --window-size 3840x2160 --borderless-window --no-validation
```

| Fixture | measured frames | full-run wall average | CPU median / p95 / p99 | GPU median / p95 / p99 |
|---|---:|---:|---:|---:|
| material | 10,000 | 0.408068 ms | 0.3903 / 0.4526 / 0.5115 ms | 0.319264 / 0.322016 / 0.322816 ms |
| transparency | 10,000 | 0.475928 ms | 0.4495 / 0.5284 / 0.5748 ms | 0.372480 / 0.377088 / 0.377920 ms |
| lighting | 10,000 | 0.417505 ms | 0.4478 / 0.4851 / 0.5620 ms | 0.319360 / 0.321920 / 0.322944 ms |
| geometry CPU | 10,000 | 0.519260 ms | 0.5704 / 0.6281 / 0.6702 ms | 0.343936 / 0.346688 / 0.347456 ms |
| temporal proxy | 240 | 0.440856 ms | 0.4125 / 0.4741 / 0.5720 ms | 0.333728 / 0.338976 / 0.358368 ms |

The wall average covers all measured frames. The bounded profiler deliberately retains
only the last 512 completed frames, so long-run CPU/GPU percentiles describe that
retained window rather than all 10,000 samples; the temporal run retains all 240.
All runs reported zero dropped frames.

The required fixtures use 949.220 MiB logical requested live Vulkan memory and
956.253 MiB engine-committed live memory after warm-up, with effectively identical
peaks. This is dominated by the deliberately high-precision legacy per-image targets
already reconciled in M0.3. External swapchain logical payload and driver heap usage
remain separate scopes and are not added to engine commitment.

These small deterministic fixtures are attribution baselines, not evidence that a
fully dressed active-gameplay scene meets the 10 ms base-frame target. The current
renderer also lacks M1 HDR composition, production lighting, shadows, probes, motion
vectors/reconstruction, GPU-driven rendering, and the later fidelity workload.

## Import and cache-state scope

Source model import, initial GPU upload, shader/pipeline initialization, and window/
Vulkan startup occur before the measured interval. Every fresh process still performs
that initialization, but M0 does not have trustworthy phase timers for it and does not
flush OS, driver, or shader caches. `cache_state` remains explicitly unavailable in
run metadata. No uncontrolled process wall time is presented as a cold-import metric.
The 500-frame manifest warm-up is the reproducible warm steady-state contract; future
asset-cooker/upload work must add separately attributable cold/import measurements.

## Rejected measurement setups

An intermediate reconfiguration left `out/build/x64-release` with
`CMAKE_BUILD_TYPE=Debug`. The runtime header and capture sidecars exposed the mismatch.
All performance numbers and Release labels from that setup were rejected. The preset
was reapplied, the cache reported `Release`, the executable emitted
`"build_configuration":"Release"`, all tests were rerun, and the complete profile and
capture sets above were regenerated. Pixel hashes remained identical, but only the
new sidecars qualify as Release evidence.

The comparison tool also rejected an intentionally mixed old/new sidecar pair at
`/capture/color_domain` with exit code 2, proving metadata compatibility is enforced
rather than advisory. Post-audit checks also paired a final image with a base-color
sidecar and verified SHA-256 rejection with exit code 2, and verified that identical
report/heatmap paths are rejected with exit code 2. A valid post-audit strict
comparison still returned maximum delta 0, changed fraction 0, and SSIM 1.0.

## External-profiler cross-check

Nsight Systems 2026.1.1 was first evaluated. Its final batch-mode check used:

```powershell
nsys profile --trace=vulkan,vulkan-annotations `
  --vulkan-gpu-workload=batch --force-overwrite=true `
  --output=out/m05_final_nsys_batch_4k `
  out/build/x64-release/bin/IridiumEngine.exe `
  --benchmark material_lab_v1 --warmup-frames 20 --frame-limit 64 `
  --profile-gpu --profile-cpu-output out/profiles/m05-final-nsys-internal.jsonl `
  --window-size 3840x2160 --borderless-window --no-validation
```

The internal 64-frame `gpu.frame` median/p95 was 0.334848/0.339296 ms. Nsight's
steady outer `vkQueueSubmit` workload median/p95 was 0.716001/0.775184 ms, 2.14 times
the internal median. The external batch boundary includes queue/semaphore behavior
outside the two in-command-buffer timestamps and is materially perturbed. Individual
workload mode was already rejected in M0.3 for even greater projection overhead and a
collapsed nested outer marker. Nsight still validates marker discovery, nesting, and
ordering, but neither mode is an exact numerical oracle.

Nsight Graphics 2026.2 was then installed. GPU Trace required elevated performance-
counter access; the successful Release trace used the equivalent of:

```powershell
ngfx --activity "GPU Trace Profiler" --platform "Windows (x86_64)" `

  --limit-to-frames 2 --max-duration-ms 5000 --auto-export `
  --architecture Ada --metric-set-id 2 --set-gpu-clocks unaltered `
  --collect-screenshot 0 `
  --exe out/build/x64-release/bin/IridiumEngine.exe `
```

## Remaining risks and deferred work

- Capture is only the current 8-bit legacy display-referred target. M1 must add
  scene-linear HDR and final-output captures as distinct artifacts.
- The fixed strict default is a change detector, not a physical-correctness threshold.
  Per-scene tolerances require evidence across drivers and output paths.
- Material ID and motion-vector captures remain unavailable because no such targets
  exist yet.
- The final M0 report supersedes these now-closed limitations: opaque-emissive visual
  coverage, exact 10,000-frame aggregation, cache-state labels, and cold import/upload
  phase timing are implemented and verified.
- Scheduler fence/error recovery and the complete CLI are not yet covered by a mock
  Vulkan or subprocess integration test. Independent lead and read-only follow-up
  review found the lifecycle and provenance fixes correct, and runtime validation
  covered the normal path, but these rare error paths retain lower automated coverage.
- Two-file artifact staging rolls back ordinary failures but cannot be fully atomic
  across a process/power loss between the two final renames.
- External attribution is proven for the current single graphics queue and marker
  set. New queues, async work, or materially changed pass boundaries require a fresh
  external cross-check rather than inheriting this result.

No ADR was added or superseded by M0.5.
