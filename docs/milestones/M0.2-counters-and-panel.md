## Outcome

M0.2 now distinguishes frontend requested work from commands actually recorded by
the Vulkan backend. Counter increments are adjacent to the current
`vkCmdDraw*`, graphics-pipeline bind, and material descriptor-bind sites. Invalid
or stale handles therefore do not inflate recorded counts.

Per-frame unique material and pipeline identities use bounded, pre-reserved
storage. Overflow preserves the lower-bound value, increments a separate overflow
counter, and changes the unique counter status from `exact` to `estimated`.
Collection-disabled runs allocate no profiler frame or unique-counter storage and
skip detailed UI command mirroring.

The transform system now returns the number of transforms actually recalculated.
Parent-dirty propagation is counted, while clean transforms remain zero.

A separate `ProfilerPanel` consumes completed profiler frames through a read-only
main-thread view. It shows current/median/p95/p99 CPU ranges and latest counters,
refreshes aggregate scans every 30 frames, and owns no collection state. It is
available through the Window menu or `--show-profiler`; collection remains an
independent `--profile-cpu` setting.

## Counter semantics implemented

- requested opaque, transparent, selection, instance, submesh, light, and legacy
  transparent-primitive counts from application extraction;
- recorded opaque, selection, lighting, transparent-depth,
  transparent-forward, ImGui, transparent-total, and all-draw counts;
- current triangle-list submissions, including mirrored non-callback ImGui draw
  commands;
- material binds/unique identities and pipeline binds/unique identities;
- exact legacy background/foreground packet counts and nonempty bucket count;
- exact upload bytes/batches when a batch is submitted;
- exact changed transforms;
- zero dispatches because the current frame records no compute work;
- explicit `unavailable` status for changed materials, lights, and instances.

ImGui user callbacks can record unknown work. Their count is exported; when any is
present, UI draw, total draw, and triangle values are labelled `estimated` rather
than exact.

## Verification and overhead

Debug and Release builds pass 4/4 CTest executables: renderer architecture, CPU
profiler, application configuration, and transform-system tests. Transform tests
cover orphan changes, clean frames, and parent-to-child dirty propagation.

A bounded Debug run exercised the open profiler panel for 128 measured frames
with validation enabled. It exited normally and emitted no validation messages.
The separate counter export also completed with zero dropped frames, event/counter
overflow, nesting errors, unique overflows, or untracked UI callbacks.

The final exact-4K core-collection gate used Release, validation off, a visible
borderless backend-reported 3840x2160 extent, 500 warm-up frames, 1,000 measured
frames, and five interleaved repetitions:

| Repetition | Disabled average | Enabled average | Paired delta |
|---|---:|---:|---:|
| 1 | 1.194560 ms | 1.223977 ms | +0.029417 ms |
| 2 | 1.198694 ms | 1.998794 ms | +0.800100 ms |
| 3 | 1.196031 ms | 1.200795 ms | +0.004764 ms |
| 4 | 1.200230 ms | 1.202148 ms | +0.001918 ms |
| 5 | 1.200739 ms | 1.197264 ms | -0.003475 ms |

Repetition 2 is a scheduling/compositor outlier retained in the evidence. The
disabled median was 1.198694 ms and enabled median was 1.202148 ms, a +0.003454 ms
(0.288%) difference. Median paired delta was +0.004764 ms (0.397%). Both satisfy
the 0.05 ms/1% disabled-path and 0.10 ms/2% enabled-path gates.

The expanded 10,000-frame microbenchmark exercises the root plus 18 child ranges,
31 counters, frame commit, and ring reuse:

| Mode | Median | p99 |
|---|---:|---:|
| Collection disabled | 0.0001 ms | 0.0002 ms |
| Core collection enabled | 0.0015 ms | 0.0015 ms |
| Enabled minus disabled | +0.0014 ms | +0.0013 ms |

One exact-4K run with the optional profiler panel open averaged 1.230334 ms. This
is about +0.028186 ms versus the enabled core median and is reported separately
because it adds visible UI draws plus periodic aggregate scans.

## Deferred work

- Engine allocation, driver heap, and persistent/external memory scopes were
  completed subsequently in M0.3 under the same Vulkan lifecycle owner.
- Changed materials, lights, and instances remain unavailable until their owning
  systems have durable change tracking.
- GPU time, capture, deterministic fixtures, and visual comparisons are not part
  of M0.2.
- ImGui is still referenced by existing runtime component inspector methods. The
  profiler panel does not add editor state to runtime components, but the broader
  accepted editor-drawer separation remains future cleanup.

No ADR was added or superseded by M0.2.
