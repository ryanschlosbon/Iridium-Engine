## Accepted result

M4.0 changes no production behavior. It freezes the exact scene and ECS state that
M4 replaces and supplies repeatable evidence for every later performance comparison.

- The complete current M3 logical-v0 field shape and all known pre-M3 path shapes
  are tracked fixtures.
- Characterization tests expose, without endorsing, Transform-only serialization,
  duplicate saved IDs, broken relationship acceptance, unknown-data loss,
  late-failure scene clearing, direct non-atomic saves, and silent predecessor-path
  loss.
- The runtime/editor dependency inventory proves current ImGui/RTTI/central-switch
  coupling before M4.5 removes it.
- The Release benchmark covers the approved current-code matrix at 10k/100k/1M and
  uses one warmup plus 30 samples with median/p95/p99, allocations, process-memory
  deltas, and bytes/entity.
- Unsupported stale-handle, UUID-map, and cooked-scene workloads are explicit
  baseline defects assigned to M4.1/M4.4.

## Verification

- Debug configure/build and 40/40 CTests pass.
- Release configure/build and 40/40 CTests pass.
- `SceneSerializerCharacterizationTests`, `SceneAssetReferenceTests`,
  `TransformSystemTests`, and `ViewportLayoutTests` pass in both configurations.
- The version-2 benchmark JSON parses, contains 34 cases, and every case contains
  exactly 30 measured samples.
- A freshly cooked `material_lab_v1` self-contained artifact starts in hidden
  Release mode with Vulkan validation, completes two measured frames, and exits
  cleanly with expected five-submesh/five-material/five-texture state.

## Performance and visual comparison

Dense Transform iteration remains the preferred layout. Random sparse lookup and
editor hierarchy construction are measured future candidates, while source JSON
save/load is the largest allocation pressure. Exact values and the storage decision
are in the linked performance report.

M4.0 contains no renderer changes and replaces no reference image. The representative
runtime startup is validation-clean.

## Remaining risk and deferral

- Current handles cannot detect staleness and no persistent scene entity UUID exists;
  M4.1 is now active.
- Current source serialization defects are intentionally unchanged until M4.2/M4.3.
- Cooked scene comparisons begin only when M4.4 defines that format.
- Runtime/editor UI coupling remains until M4.5.

No ADR changed. `ROADMAP.md` remains M4 `In Progress`; only M4.0 is accepted.
