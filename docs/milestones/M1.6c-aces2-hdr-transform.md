# M1.6c Acceptance: ACES 2 HDR Transform Asset

- Status: Accepted
- Date: 2026-07-22
- Runtime behavior change: none

## Decision and asset

One pinned ACES 2 transform supplies the common display rendering for scRGB and
HDR10: a 1000-nit P3-D65-limited output encoded in the Rec.2100/Rec.2020 ST.2084
container. The exact Academy transform is
`urn:ampas:aces:transformId:v2.0:Output.Academy.P3-D65_1000nit_in_Rec2100-D65_ST2084.a2.v1`.

The 128-cubed deterministic LUT is
`assets/color/aces2_p3d65_1000nit_rec2100_pq_128.irlt`, 33,554,464 bytes, SHA-256
`742a0fff9f8048adf56513f4760180d9d07fa28757628a7a051df084a62bac52`.
Its JSON sidecar pins ACES `v2.0.0+2025.04.04`, core commit
`2d7af39344725aaa8ac3bf1746693c9a1d6c4792`, output commit
`aab74723f76728c37345ed01e51ebb24fb1f2f1f`, and OpenColorIO 2.4.2.
The transform ID was cross-checked against the CTL header at that official Academy
output commit.

HDR10 will sample the LUT's Rec.2100-PQ values directly. scRGB will use the same
display rendering, decode ST.2084 to absolute Rec.2020 nits, convert to linear
Rec.709 primaries, and divide by the Windows scRGB scale of 80 nits per 1.0. This
keeps one rendering intent while separating transport encoding and avoids the false
HDR that would result from scaling the accepted 100-nit SDR LUT.

## Verification and impact

The cooker now selects an explicit profile. Regenerating the SDR profile remains
bit-exact at SHA-256
`79f5c05609e853f843772d8f85902c074d05cef751fa092cfa6a416605c46558`.
The new HDR LUT passes pinned neutral and primary vectors in Debug and Release.
Against 20,000 deterministic random RGB samples, encoded absolute error is mean
0.0000400377 and p99 0.000523759. A rare maximum of 0.0937631 at a sharp gamut
boundary is retained as explicit evidence for the later resolution gate.

The asset is not uploaded in this slice, so runtime VRAM, CPU/GPU timings, and images
are unchanged. M1.6d adds independent ST.2084/Rec.2020/scRGB reference math; M1.6e
wires the first scRGB swapchain/output path.
