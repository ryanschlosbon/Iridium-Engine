# M2.7 Production Material Diagnostics

> Historical slice note: M2.10 made canonical snapshots/routing unconditional and
> completed material/flag pixel diagnostics in the R cache.

Status: Complete on 2026-07-22.

This record accepts the production material-inspection slice defined by
`M2-material-compiler-and-closures.md`. It changes editor diagnostics only; it does
not select the M2.8 GBuffer, add lighting, or expand transparency transport.

## Delivered behavior

- Every loaded canonical material retains one deterministic diagnostic snapshot
  spanning `SourceMaterial`, `CompiledMaterial`, `MaterialInstance`, and the exact
  `PackedGpuMaterial`. The editor displays the snapshot SHA-256 and packed-record
  SHA-256 so a reviewer can distinguish source/compiler changes from GPU packing.
- Material search covers name, source index, asset, workflow, closure, and warnings.
  The selected record reports its workflow, closure class, and an explicit reason
  for lossless standard-deferred, unlit-forward, or complex-forward routing.
- Source fields show authored versus format-default origins. Texture rows show a
  live thumbnail, semantic, source image identity, channels, transfer function, UV
  set, transform, glTF sampler state, engine fallback state, and evaluated UV for a
  user-entered coordinate. The transform evaluator is shared with a pure CPU test.
- Compiled closure values, feature flags, active complex lobes, texture-operation
  count, instance revision/override mask/bindings, and packed schema/bytes/IDs/
  vectors/half-bit records are separate sections rather than a mixed runtime dump.
- Structured compiler and packing diagnostics retain stage, severity, stable code,
  and message. Loader compatibility warnings remain visible alongside them.
- Texture previews are allocated lazily through the RHI/backend boundary and are
  retired with their texture. Opening diagnostics neither creates render passes nor
  changes scene material descriptors. The ImGui pool now has bounded capacity for
  project material previews.
- `--show-material-diagnostics` opens the panel at startup for reproducible QA.
  Without `--canonical-materials`, the panel names the unavailable compiled/packed
  contract instead of presenting legacy values as canonical evidence.
- Material/closure-ID pixel views are explicitly unavailable until M2.8 supplies
  reference integer fields. Complex forward surfaces are explicitly absent from
  deferred GBuffer views. No placeholder channel or universal GBuffer cost was added.

## Material inspection evidence

The tracked fixtures and optional local car were re-read by the Debug and Release
test suites:

- tracked `material_lab`, opaque/emissive range, M1 color/transparency, and complex
  closure lab fixtures cover standard deferred, standard forward, every frozen
  complex-lobe class, unlit, texture interpretation, defaults, and diagnostics;
- the car imports 87 materials: 25 default metallic values, 61 explicit metallic
  zeros, five blends, 72 normal uses, two metallic/roughness uses, one AO use, no
  emissive textures, and no nonzero emissive factors;
- paint 0 and 36 retain default metallic 1 plus active clearcoat and classify complex
  forward; lens/headlight materials 3 and 4 retain BLEND, explicit transmission 1,
  normal detail, and their metallic/transmission conflict diagnostic; window 6
  remains the authored standard-forward BLEND metal with zero transmission rather
  than being changed into glass;
- runtime validation opened the diagnostics panel on the car with all 87 material
  draws and lazy thumbnails active. Cleanup produced no Vulkan validation messages.

This is enough for a reviewer to trace an unexpected surface from authored/default
input through texture interpretation and closure selection to the packed GPU bytes.
Lighting correctness remains M5 and layered glass/ordering/refraction remains M6.

## Verification and measured cost

- MSVC Debug and Release builds completed after the final change.
- Debug and Release CTest: 20/20 passed. Deterministic snapshot JSON/hash, origins,
  diagnostic stability, handle generations, packed half records, car classification,
  all tracked fixture classes, and selected-UV rotation/scale/offset are covered.
- Debug Vulkan validation at 3840x2160, production render graph, canonical materials,
  diagnostics open, three frames: clean; 87 car materials and thumbnail descriptors
  were exercised.
- Closed-panel Release CPU telemetry at 4K measured median `cpu.editor.build`
  0.1137 ms, 7 C++ allocations, and 224 bytes per frame. Open-panel telemetry after
  caching the parsed snapshot measured 0.2506 ms, 210 allocations, and 33,612 bytes:
  an editor-only +0.1369 ms median and +33,388 bytes/frame. The remaining formatting
  allocations are accepted for an explicitly opened diagnostic tool, not gameplay.
- Persistent engine/GPU memory categories and graph allocation are unchanged by
  opening the panel. Preview descriptors consume descriptor-pool entries only for
  viewed textures; no image, buffer, attachment, upload, or GBuffer allocation is
  introduced. Rendering shaders, passes, and output transports are unchanged, so
  the accepted M2.6 images and GPU timing remain the rendering baseline.

The short present-paced wall runs varied with hidden-window compositor behavior and
are not used as GPU evidence. M2.7 changes no GPU render workload; M2.8 resumes the
required captured-image, timestamp, bandwidth, and memory comparisons.

## Rollback and remaining work

The panel is closed by default and can be omitted without changing rendering.
Disabling `--canonical-materials` also removes canonical snapshot/preview population.
M2.8 is the next slice: implement candidate R as the complete canonical reference
GBuffer, including the integer material/closure fields needed by pixel debug views.

## Post-acceptance selection correction

Selection previously wrote its temporary negative mask into albedo alpha. M2 uses
that channel as AO, so the deferred light clamped selected pixels to zero AO and made
the selected surface dark and apparently unshaded. The mask now writes only emissive
alpha, which is outside the current closure; albedo/AO, normal, roughness, metallic,
emissive RGB, depth, and the regular material draws remain untouched. The outline
pass samples the relocated mask and remains the only visible selection effect.

The corrected shaders build in Debug and Release, both configurations pass 20/20
tests, and 4K Vulkan validation is clean in SDR, scRGB, and HDR10. M2.8 replaces this
temporary alpha reservation with an authoritative integer material/closure field.
