# M2.8 - Canonical Reference GBuffer

- Status: Complete
- Accepted: 2026-07-25
- Parent: `M2-material-compiler-and-closures.md`

## Outcome

The production graph now owns a complete canonical surface cache. Candidate R uses
five color attachments plus depth:

| Field group | Vulkan format | Bytes/pixel |
|---|---|---:|
| world normal + scalar F90 | `RGBA16F` | 8 |
| diffuse albedo + AO | `RGBA16F` | 8 |
| scene-linear AP1 emissive + selection mask | `RGBA16F` | 8 |
| RGB F0 + perceptual roughness | `RGBA16F` | 8 |
| material identity + feature/closure flags | `R32_UINT` | 4 |
| Total color payload | | 36 |

The mask is encoded only in the otherwise unused emissive alpha channel and never
changes material shading. The final output pass reads it only when an entity is
selected. The material/flag field is exact integer data. The reference layout is an
oracle and near-term surface cache, not a promise that future geometry must emit a
full GBuffer; ADR-0006 remains the visibility-resolve migration contract.

## Implementation and regression fixes

- The render graph declares all formats, lifetimes, loads, stores, and transitions.
- Standard materials emit the canonical closure directly.
- Opaque complex closures use a distinct depth-writing forward-opaque pass after
  deferred lighting. They no longer enter the transparent queue.
- Transparent complex closures retain the bounded M1 two-layer transport interface.
- Forward closures provide the same debug views instead of disappearing outside the
  final view.
- The output pass composites a symmetric three-pixel cyan selection boundary after
  all scene rendering. The no-selection path performs no mask-neighborhood reads.

## 4K reference cost

Five Release runs used 500 warm-up and 10,000 measured frames on the RTX 4090.
Five-run medians for `material_lab_v1`:

- GPU frame: 0.455296 ms
- GBuffer: 0.012288 ms
- deferred lighting: 0.124928 ms
- matched GBuffer + lighting: 0.137216 ms
- output transform: 0.038912 ms
- UI: 0.106496 ms
- CPU frame: 0.631800 ms
- steady C++ allocation calls and bytes: median 0, p99 0
- graph requested/committed: 862,617,600 / 935,854,080 bytes
- engine requested live/peak: 861.158 / 893.159 MiB
- engine committed live/peak: 931.003 / 963.005 MiB

The requested peak is 6.497 MiB above M1's worst transport baseline, exactly
explained by the two persistent 4096-entry schema-2 GPU material buffers. No
normal-frame device wait was added.
