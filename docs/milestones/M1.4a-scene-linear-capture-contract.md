# M1.4a Evidence: Scene-Linear Capture Contract

- Status: Accepted implementation slice
- Date: 2026-07-19
- Parent slice: M1.4 scene-linear HDR and transparent composition

## Result

The capture boundary can now represent `RGBA32Float` data in the
`scene_linear_acescg_ap1` domain and write a canonical diagnostic RGB PFM artifact.
PFM files are little-endian float32, bottom-row-first on disk, restored to top-left
row order on read, and retain negative and above-one scene values exactly. Alpha is
intentionally omitted by the RGB PFM format.

The JSON sidecar distinguishes this artifact mechanically from final SDR capture:
the point is `post_transparency_pre_output_scene_color`, transfer is `linear`,
primaries are `acescg_ap1`, exposure is `unapplied`, and output operator is `none`.
Existing display-referred TGA behavior and metadata remain unchanged. Pixel-format
and color-domain mismatches are rejected rather than mislabeled.

## Verification and impact

- Debug and Release `CaptureArtifactTests` pass, including exact round trip of
  negative, fractional, 16.0, and 100.0 channel values and metadata assertions.
- The Debug engine target links with the new capture module.
- This slice changes no renderer resource, shader, presented pixel, frame work, or
  live GPU allocation. Visual, CPU, GPU, and VRAM impact is therefore zero until the
  renderer readback path begins producing this capture type.
