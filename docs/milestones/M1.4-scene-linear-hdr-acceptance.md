# M1.4 Acceptance: Scene-Linear HDR and Transparent Composition

- Status: Accepted
- Accepted: 2026-07-19
- Baseline: accepted M1.3 graph path on commit
  `30252593f8fdd2de5dffbb8da31bb570ff49a7c0` plus preserved dirty work
- Reference system: RTX 4090, Core i9-14900K, 64 GB DDR5, 3840x2160

## Accepted architecture and behavior

Scene color and its transparency copy are FP16 linear ACEScg/AP1. Vulkan sRGB base
color and emissive texture sampling performs the transfer decode; the GBuffer and
forward material boundaries then transform linear Rec.709/sRGB primaries to AP1.
Linear HDR environment inputs are transformed to AP1 before lighting/reflection.
Opaque lighting, environment, emissive, refraction, and both transparency buckets
remain in that common domain.

The fitted legacy curve no longer exists in lighting or forward shaders. A distinct
`compatibility-output` pass converts AP1 to linear Rec.709, applies the selectable-
architecture legacy fitted curve, and supplies the viewport/UI path. It is the only
display mapping in the current frame. A disabled `bloom-hook` pass exposes the
post-transparency scene input without allocating or dispatching work. Capture occurs
before bloom/output/UI and writes a canonical float PFM with linear/AP1/unexposed
metadata.

The final M1.4 graph has eleven passes, nine logical resources, six physical slots,
and 27 transition intents. FP16 scene copy and compatibility output reuse expired
FP16 GBuffer/transparent-copy storage. The legacy manual fallback remains selectable;
it uses separate images but the same shader/color semantics.

Durable incremental evidence is in M1.4a through M1.4d. The semantic-cut and fixture
evidence is captured here.

## Automated and validation evidence

Fresh Debug and Release full suites pass 12/12. Tests cover:

- IEC sRGB vectors, Rec.709/sRGB-D65 to AP1-D60 primary vectors, neutral adaptation,
  wide/negative round trips, and IEEE half decode;
- shader source boundaries: material/environment conversion exists, lighting and
  forward contain no fitted output curve, and the curve/AP1 inverse exist only in
  output;
- scene capture ordering before output/UI and PFM negative/above-one exact round trip;
- deterministic M1 color-volume fixture content/hash and transparent material axes;
- eleven-pass graph ordering, six-slot reuse, depth sampling layout, rebuild,
  retirement, and failure cleanup.

Debug Vulkan validation is clean at 4K for graph-mode material lab, lighting,
nested transparency, opaque-emissive, and the new transparent-highlight fixture.
The legacy fallback is validation-clean for material and transparency after the
semantic cut.

## Performance and memory

Three final Release runs used 4K `transparency_v1`, 200 warmup frames, and 3,000
measured frames:

| Run | CPU frame median | GPU frame median | Compatibility output GPU |
|---:|---:|---:|---:|
| 1 | 0.5386 ms | 0.4245 ms | 0.0399 ms |
| 2 | 0.5698 ms | 0.4244 ms | 0.0399 ms |
| 3 | 0.5516 ms | 0.4237 ms | 0.0399 ms |

Against M1.3 median-of-run-medians, the final M1.4 delta is +0.0294 ms CPU and
+0.0260 ms GPU. Deferred lighting is 0.0635 ms; the sum of six transparency scope
medians is 0.1321 ms, far below the 1.0 ms ordinary-scene transparency budget and
inside the frozen +0.10 ms M1.4 proxy allowance. Output CPU recording is
0.0020-0.0022 ms. Median normal-frame C++ allocations are zero.

Graph-mode steady memory remains 663,553,868 B requested / 668,470,976 B committed,
well below the M0 ceiling. A requested 4K PFM capture uses a temporary 66,355,200 B
FP16 readback plus CPU float storage and remains excluded from steady/timing evidence.
The non-aliasing legacy fallback uses 928,974,284 B requested / 935,857,488 B
committed, also below M0.

## Acceptance and next work

M1.4 is accepted. Scene capture is structurally exposure-independent because it is
recorded before the sole output pass and its sidecar records `unapplied`; M1.5 must
repeat this as a runtime differential test once user exposure controls exist.

M1.5 is next: implement versioned `OutputTransformConfig`, manual EV persistence,
the frozen ACES 2 production transform and legacy option, final SDR gamut/encoding,
display-linear paper-white UI composition, direct final-output TGA capture, reference
vectors, and new SDR image baselines.
