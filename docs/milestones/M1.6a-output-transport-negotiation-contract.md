# M1.6a Acceptance: Output-Transport Negotiation Contract

- Status: Accepted
- Date: 2026-07-22
- Runtime behavior change: none; SDR remains the only wired transport

## Contract

The Vulkan backend now owns a pure, deterministic selection contract for requested
SDR, scRGB, and HDR10/PQ transports. A transport is supported only by an exact
format/color-space pair; format alone never implies HDR.

Preferred pairs are:

- SDR: `B8G8R8A8_SRGB` or `R8G8B8A8_SRGB` with `SRGB_NONLINEAR_KHR`;
- scRGB: `R16G16B16A16_SFLOAT` with `EXTENDED_SRGB_LINEAR_EXT`;
- HDR10/PQ: `A2B10G10R10_UNORM_PACK32` or `A2R10G10B10_UNORM_PACK32` with
  `HDR10_ST2084_EXT`.

An unavailable HDR request selects a known exact SDR pair and records why. If the
surface does not expose a known SDR pair, selection fails instead of assigning SDR
semantics to an arbitrary format. `VK_EXT_hdr_metadata` is tracked independently:
HDR10 transport may remain available without static metadata, but the limitation is
reported and metadata calls remain disabled.

## Verification and impact

`VulkanOutputTransportTests` passes in Debug and Release and covers exact selections,
both SDR fallbacks, optional HDR metadata, alternate HDR10 packing, Vulkan's
undefined-format case, and fatal absence of a known SDR fallback. Both engine builds
also link the new module.

The selector is not called by swapchain creation in this slice. Visual output,
performance, and memory are therefore unchanged by construction. M1.6b will
enumerate the live surface, invoke this contract for capability discovery, and
publish the requested/effective transport and diagnostic while retaining SDR.
