# M1.4b Evidence: Scene-Color Reference Math

- Status: Accepted implementation slice
- Date: 2026-07-19
- Parent slice: M1.4 scene-linear HDR and transparent composition

## Frozen contract

`renderer/color/SceneColor` is the CPU numerical oracle for M1 source conversion.
It implements the IEC sRGB piecewise decode/encode and a frozen linear
Rec.709/sRGB-D65 to ACEScg/AP1-D60 matrix with Bradford white adaptation. The inverse
matrix exists for compatibility-output tests. It neither clamps nor tone maps, so
negative and high-dynamic-range linear values remain representable.

The AP1/D60 definition follows the official ACEScg specification:
`https://docs.acescentral.com/encodings/acescg/`. ACES release aggregation remains
frozen by M1.0 at `v2.0.0+2025.04.04`. The exact coefficients are source constants
and test vectors, avoiding runtime color-library or configuration drift.

## Verification and impact

Debug and Release `SceneColorTests` pass. They cover sRGB breakpoint and mid-gray
reference values, all three transformed primary vectors, adapted neutral white,
encoded transfer round trips, and wide/negative linear matrix round trips.

This slice adds CPU reference code and tests only. No frame path calls it yet; visual,
CPU-frame, GPU-frame, and VRAM impact are zero.

## Next slice

Mirror these frozen constants in a shared shader include, convert sRGB-authored base
color/emissive inputs into AP1 at the GBuffer/forward boundary, and move graph-owned
scene color/copy to `RGBA16F`. Keep the compatibility output explicit so the first
rendered HDR composition can be validated independently of the M1.5 production
output transform.
