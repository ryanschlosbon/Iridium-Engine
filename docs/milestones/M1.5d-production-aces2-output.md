## Accepted architecture and behavior

The default SDR operator is now the Academy ACES 2 output transform
`Output.Academy.Rec709-D65_100nit_in_Rec709-D65_sRGB-Piecewise.a2.v1` from the
pinned `v2.0.0+2025.04.04` package. The exact transform ID is
`urn:ampas:aces:transformId:v2.0:Output.Academy.Rec709-D65_100nit_in_Rec709-D65_sRGB-Piecewise.a2.v1`.
The retained CLI choices are `aces2` (default), `legacy`, and diagnostic `identity`.

The production runtime representation is a deterministic log2-offset shaper over
[-10,+16] stops followed by a 128-cubed RGBA32F LUT tiled into a guaranteed-valid
16384x128 2D image. The LUT stores encoded sRGB results from the official OpenColorIO
2.4.2 composition of ACEScg-to-ACES2065-1, the Academy SDR 100-nit Rec.709 output,
and the CIE-XYZ-D65-to-sRGB display transform. The shader uses tetrahedral
interpolation, decodes the interpolated sRGB value to display-linear, and writes it
to the existing sRGB attachment for the one final IEC encoding. Exposure remains
upstream of every selectable operator and downstream of scene capture.

The source package commits and bake inputs are recorded in
`assets/color/aces2_rec709_100nit_srgb_128.json`; the binary asset SHA-256 is
`79f5c05609e853f843772d8f85902c074d05cef751fa092cfa6a416605c46558`.
`tools/color/BakeAces2Lut.py` is the durable deterministic cooker. Runtime loading
rejects the wrong magic, schema, dimensions, shaper range, payload length, or
non-finite values. Captures and profiles serialize the selected operator, gamut
policy, output mode, Academy package, and exact transform ID.

The fitted ACES compatibility curve and AP1-to-Rec.709 identity/clamp diagnostic
remain explicit rollback and debugging branches. They do not alter scene-linear
composition or output-pass ordering.

## Color-science and visual evidence

The CPU sampler mirrors the shader shaper, tiled addressing, tetrahedral
interpolation, hostile-input sanitization, and output clamp. Tests cover black,
18% gray, 1.0 and 4.0 neutrals, AP1 primaries, a monotonic neutral range through
65536, and negative/NaN/infinite input. Representative official encoded-sRGB
references include 18% gray `0.349187`, 1.0 gray `0.706683`, and 4.0 gray
`0.899869`; all pinned-vector LUT results are within 0.0003 encoded units.

The deterministic 20,000-sample, full 26-stop-cube bake validation records encoded
absolute error max `0.0811969`, p99 `0.00115024`, and mean `0.000100242`. The maximum
is a rare interpolation sample at a sharp ACES gamut-compression boundary, not the
representative error; it remains an explicit M1.5 color-volume-fixture risk and is
not hidden by the good p99 result.

A validation-enabled 1280x720 opaque-emissive final capture is visually ordered from
black through the six highlight steps and hashes to
`69f5a7dfe2ff36f73375834c4b01032b4617183f23758e3513977c457cc25317`.
Legacy and identity captures produce distinct hashes and correct sidecars. No Vulkan
validation message was emitted during any of the three operator runs. Evidence is
under `out/evidence/m1/m1.5d-aces2/`.

This slice does not accept the complete M1.5 visual gate: a dedicated saturated
color-volume/UI fixture, hue-boundary review, and color-managed UI composition remain
the next slice.

## Verification, performance, and memory

Fresh Debug and Release build trees both compile the shaders and engine and pass all
14 CTests. The production shader therefore compiles in both configurations, while
the CPU reference and operator parser are exercised independently.

Three matched 4K Release runs per operator used `transparency_v1`, 200 warmup frames,
and 3,000 measured frames:

| Operator/run | CPU frame median | GPU frame median | Output GPU median / p99 | Output CPU median |
|---|---:|---:|---:|---:|
| ACES 2 / 1 | 2.0518 ms | 0.468576 ms | 0.043008 / 0.044032 ms | 0.0043 ms |
| ACES 2 / 2 | 2.0420 ms | 0.468800 ms | 0.043008 / 0.043008 ms | 0.0042 ms |
| ACES 2 / 3 | 2.0538 ms | 0.468704 ms | 0.043008 / 0.043008 ms | 0.0044 ms |
| Legacy / 1 | 2.0379 ms | 0.453920 ms | 0.028672 / 0.029696 ms | 0.0043 ms |
| Legacy / 2 | 2.0250 ms | 0.452672 ms | 0.028672 / 0.029696 ms | 0.0042 ms |
| Legacy / 3 | 2.0311 ms | 0.452352 ms | 0.028672 / 0.029696 ms | 0.0043 ms |

The ACES 2 operator adds about 0.0143 ms to the output pass and 0.0156 ms to the GPU
frame median versus the matched legacy branch. CPU output recording is unchanged;
the observed total CPU-frame difference is presentation-bound and is not attributed
to command recording. ACES 2 remains far below the 0.25 ms median / 0.35 ms p99
output gate. Steady frame allocation counters remain zero.

The LUT adds 33,554,432 requested bytes and 33,555,968 committed bytes in the
persistent texture category. Total engine live memory is 763,463,500 B requested /
768,872,128 B committed; graph transient memory remains 729,907,200 B requested /
735,313,920 B committed. Startup uploads 33,555,916 B in one batch. Total committed
memory remains about 187.0 MiB below the M0 956.253 MiB ceiling.

## Acceptance and next work

M1.5d is accepted as the production ACES 2 operator slice. M1.5 itself remains in
progress. The next bounded slice adds the dedicated output/UI color-volume fixture
and correct display-linear UI composition, then verifies UI exposure independence
and the rare LUT gamut-boundary behavior before accepting M1.5.
